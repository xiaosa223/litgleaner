# ADR 0004：段落翻译流式返回，单段即时执行

- 状态：已接受
- 修订：ARCHITECTURE.md 第 12.3、15.1、15.2 节

## 背景

第 12.1 节要求段落翻译流式返回、首字 2 秒内出现。第 15.2 节要求模型输出一律通过 JSON Schema 校验，现有 `LLM` 接口只支持一次性返回 JSON 对象，流到一半的内容无法按 JSON Schema 校验。第 15.1 节要求领读器的翻译走统一的任务队列，但流式结果必须在用户点击的那次请求里返回，等不了后台调度。

## 决定

1. **`LLM` 接口新增流式文本输出。** 除 `complete`（结构化 JSON）外，增加 `stream`：逐段返回文本增量，结束时给出模型名和 token 用量。四种协议（Anthropic Messages、OpenAI Chat、OpenAI Responses、Gemini）都实现。网关的 `stream` 与 `call` 一样先查预算，结束后记录费用；中途失败也记录已知的用量。
2. **`translate` 任务输出纯文本，结束后由代码校验，替代 JSON Schema 校验。**
   - 提示词约定每行一句译文，与原文分句一一对应。
   - 结束后校验：行数等于原文句数；原文出现的术语表英文术语，对应译句必须包含术语表译名。
   - 校验通过才写入 `translation` 缓存；不通过时界面照常显示本次译文，但标为“未通过核验”，不缓存，可以重试。
   - 译文同样视为不可信内容：按纯文本渲染，长度有上限，去掉其中的链接。
3. **单段翻译即时执行，整篇翻译走任务队列。**
   - 点一段翻一段：在本地接口的请求里直接调用网关，照常检查预算、记录费用、写缓存。用户主动发起的操作本来就优先于后台任务（第 15.2 节）。
   - 整篇双语对照：先估算费用，用户确认后为每个未翻译的段落排入队列，由后台逐段翻译；界面按段显示进度。
4. **费用按论文记录。** `llm_call` 增加可空的 `paper_id`，领读器顶栏显示本篇和本月花费（第 12.1 节“花费看得见”）。

## 后果

- 每个协议适配器多一套流式解析，契约测试覆盖四种协议的事件格式。录制真实响应需要各家的密钥，没有密钥时测试数据按官方文档的事件格式构造，并在测试里注明。
- 其他任务（初筛、提取、评估、讲解、问答）仍然使用结构化输出和 JSON Schema 校验。问答以后如需流式，另行决定。
