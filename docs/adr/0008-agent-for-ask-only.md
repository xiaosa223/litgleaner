# ADR 0008：本机 agent 只用于边读边问，先用 API 跑通

- 状态：已接受（2026-11-08，用户决定）
- 修订：ADR 0005 第 6、8 条，以及第 2 条的安全前提；ARCHITECTURE.md 第 1、12.1、12.3、12.4、15.2、15.3、15.5 节；REQUIREMENTS.md R19、R20、R24
- 依据：[API 端到端与本机 agent 实测](../experiments/2026-11-08-api-e2e-and-acp-probe.md)

## 背景

ADR 0005 第 2 条假设：初始化时不声明文件和终端能力、拒绝 agent 发来的每个权限请求，就能让 agent 只当模型用。实测推翻了这个假设：

- DeepSeek Harness（`dsh` 0.2.1-rc.2，`--profile acp`）在默认权限模式下，**没有发出任何权限请求**就写了会话目录里的文件，并执行了 `ls -la /Users`。
- 设为只读模式（`DSH_PERMISSION_MODE=read-only`）后，写文件被沙箱拦下，提权请求被我们拒绝；但读取任意路径仍然不询问。
- Codex 的只读模式、Claude Code 的计划模式按公开资料同样允许不询问地读文件。这两家的 ACP 适配器本机没有安装，未实测。

论文内容可能含有提示注入。只要 agent 有读文件的工具，它就可能在我们察觉之前读到用户本机的文件。客户端看到 `tool_call` 通知时，工具多半已经执行。

用户决定（2026-11-08）：先用 API 把全部功能跑通；本机 agent 只用于边读边问（连续问答）。

## 决定

1. **本机 agent 只能接 `ask` 任务。** 配置校验拒绝把 `ask` 以外的任何任务路由到 `acp` 提供方。翻译、释义、导读、评价回答（`translate`、`explain`、`guide`、`evaluate`）和全部后台任务都走 API 提供方。取代 ADR 0005 第 8 条。
2. **实施顺序：先用 API 跑通全部 LLM 功能，再接本机 agent。** `acp` 提供方推迟实现。
3. **首次向导先配置 API 提供方**（推荐低价模型，或 OpenAI 兼容的本地服务），再询问是否用本机 agent 做边读边问，可以跳过。取代 ADR 0005 第 6 条。这一条是由第 1 条推出的：其他功能都依赖 API。
4. **接入 `acp` 时，agent 的安全措施另行决定。** ADR 0005 第 2 条的措施不足以保证“没有工具权限”。可选的做法（每家开最严格的模式并尽量关掉工具；收到 `tool_call` 立即取消会话、丢弃输出、重启进程；启用前用探针自检；系统级沙箱）在接入前比较并定案，记入新的 ADR。
5. ADR 0005 的其余决定（协议、预设、进程与会话、额度取代美元、不替用户安装 agent、自写同步客户端）不变，接入时照做。

## 后果

- “不让用户为 API 付费”（R20）只在问答上兑现；翻译等功能需要 API。推荐免费或低价的模型，以及 OpenAI 兼容的本地网关。
- 第 12.3 节整篇翻译不再有“走本机 agent 时显示调用次数”的分支，统一先估算费用、确认后执行。
- 实测发现的 API 侧问题（部分兼容接口不强制执行 JSON Schema、推理模型的思考 token 挤占输出上限、推理模型首字慢）记在实测记录里，由配置项和后续的界面工作处理，不改本决定。
