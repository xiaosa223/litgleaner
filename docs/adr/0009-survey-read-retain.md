# ADR 0009：按“调研、读懂、沉淀”三件事组织产品，语言成为变化点，上手改为渐进式

- 状态：已接受（2026-11-11，用户决定六条全部采纳）。提议于 2026-11-10。
- 界面先行（2026-11-10，用户要求“先把前端做好，不要求后端适配”）：第 3 条的页面结构和阅读页布局、第 2 条的添加论文入口、第 5 条的第一屏两个入口已在 `web/` 实现；第 1 条的课题页用示例数据做了界面。后端没有改动，第 4 条（语言）没有动。进度见 ROADMAP。
- 修订：ADR 0006 第 3 条（界面只有中文、不做多语言）；ADR 0008 第 3 条（首次向导先配置 API 提供方）；REQUIREMENTS.md 第 1、6 节，R7、R13、R14、R19，新增 R27–R31；ARCHITECTURE.md 第 1、3、5、6.1、7.1、7.2、12、12.1、12.2、12.3、13.1、15.1、15.2、15.5、16、17 节，新增第 7.5、12.8、15.6 节
- 依据：2026-11-10 对架构文档和领读器界面的评审（界面在 1366×768 下用演示数据走查）

## 背景

用户明确了产品目的（2026-11-10）：让科研新手也能**全面调研一个课题、快速读懂一篇文献、沉淀自己的长期知识库**，适用于世界上所有的研究者。

按这个目的检查现有设计，工程骨架不用动：事实与判断分离、派生物带指纹、不静默产生费用、解析防腐层、引用核验、接口加机械检查、本地优先。问题在产品结构：现有设计的中心是“每天检索、打分、推送”的流水线，领读器是推送的落点；而目的里的三件事，都是用户主动发起的。具体有五处缺口：

| # | 缺口 | 证据 |
|---|---|---|
| 1 | **调研不是一等流程。** 流水线只处理新发现的论文；历史文献靠命令行 `topic backfill`；引文追踪排在路线图最后一步；数据模型没有引文关系表，切分器解析出的参考文献没有落库 | ARCHITECTURE 第 5、7.3 节；ROADMAP 第 13 步；`infra/db/schema.py` 没有引文表 |
| 2 | **读不了自己手里的论文。** 领读器只能打开流水线推荐的论文；手动投喂排在路线图第 13 步，界面上没有入口。而路线图第 6 步的用户测试要求“每人读一篇自己方向的论文” | `web/src/Inbox.tsx`；ROADMAP 第 6、13 步 |
| 3 | **知识库有概念，没有文库和总检索。** 读完的论文从首页消失；笔记只能在单篇论文里按关键字过滤；R7（P0）要求的“集中、可检索”没有对应的页面；个人数据怎么带走没有规定 | `web/src/panel/NotesTab.tsx`；ARCHITECTURE 第 12 节没有定义页面结构 |
| 4 | **语言写死为“英文论文、中文读者”。** ADR 0006 第 3 条规定界面只有中文；翻译提示词写死“英文译成简体中文”；术语表和概念的字段是“英文名、中文名”；默认推送渠道只有飞书 | ADR 0006；`prompts/translate.md` 第 1 行；ARCHITECTURE 第 5、7.1 节 |
| 5 | **上手第一步就要 API key。** 首次向导的顺序是模型和 key、研究描述、飞书、Zotero；而“配 API key”正是需求调研里强证据的劝退点（P6） | ARCHITECTURE 第 15.5 节；REQUIREMENTS P6、R19 |

“适用于世界上所有的研究者”是产品决定。需求调研的证据全部来自中文学生（REQUIREMENTS 第 1 节），其他人群的需求没有证据，按假设处理。

## 决定

1. **课题调研成为一等流程**（ARCHITECTURE 第 7.5 节）。
   - 新画像启用时，在领读器里发起一次有边界的调研：按检索式做历史检索，再从种子论文和高分论文出发做一到两轮引文扩展（参考文献和被引），过本地关键词过滤和初筛。执行前显示预计篇数和费用，用户确认后才执行。
   - 每一轮记录新增了多少篇、多少篇通过初筛。新增比例低于阈值时提示“已基本覆盖”。覆盖度是参考指标，界面上写明检索了哪些来源、没有覆盖什么（如没有接口的中文数据库）。
   - 结果在课题页呈现：调研进度、阅读路线（综述、奠基论文、代表作、最新进展）、课题地图（子方向分组）、对比表和综述骨架。原第 7.2 节的入门清单并入阅读路线。
   - 调研完成后转入日常跟踪，即现有流水线。`topic backfill` 保留为底层命令。
   - 新增：`ReferenceList` 查询类型；表 `citation`、`survey_round`、`topic_map`；LLM 任务 `map`。不做引文图谱可视化（第 1 节的“不做”不变）。
2. **任何论文都能直接读**（第 12.8 节）。贴 DOI、arXiv 编号、链接，或拖入 PDF，走已有的 `inbox` 和事实层流程，按用户主动操作排在后台任务之前。PDF 存好就能在原版视图打开，讲解和译文完成后陆续出现。不要求先建研究画像。
3. **领读器按三件事组织页面**（第 12.8 节）。
   - 常驻导航：今天（首页：继续读、今日复习、新推荐）、课题（调研与跟踪）、文库（在读、待读、已读）、知识库（概念、笔记、复习）、设置。导航上另有添加论文和全局检索。
   - 全局检索：一个搜索框查论文、笔记、回答卡片、问答和概念，每条结果跳到原文位置。
   - 个人数据随时能整体导出为开放格式（Markdown、BibTeX、CSL-JSON），单向导出，不反向写入。
   - 阅读页布局规则：正文宽度优先，目录和侧栏可以折叠；顶栏只留常用操作，其余开关收进“显示”面板；还没提供的功能不放禁用的占位控件；快捷键提示按操作系统显示；面向新手的文案不出现命令行。
4. **语言是变化点**（第 15.6 节，以及第 1、5、7.1、15.2、16、17 节的相应修改）。
   - 配置区分界面语言和阅读语言（译文、讲解、卡片、导读、评价的输出语言）。提示词不写死输出语言；输出语言计入派生物指纹，改语言不自动重做，由 `stale` 列出。
   - 术语表和概念按“原文术语 + 各语言译名”存储。
   - 前端文案集中到按语言分的消息表，由类型检查保证各语言的键一致；不引入多语言库。提供简体中文和英文两种界面，中文先做。
   - 飞书、GB/T 7714、期刊分区导入继续作为可选的适配器和数据，不进入核心流程。未配置渠道时，推荐只出现在领读器首页（R19 已有）。
5. **上手改为渐进式**（第 15.5 节）。
   - 第一屏只有两个入口：“读一篇论文”和“调研一个课题”。
   - 不需要模型的功能（打开 PDF、选字、高亮、笔记、检索）不配置任何东西就能用。第一次用到模型的操作时，在原地引导配置模型提供方，配好后继续刚才的操作。
   - 飞书、Zotero、本机 agent 移出向导，放进设置页，在相关场景里提示。
   - ADR 0008 第 3 条中“先 API、后本机 agent”的顺序不变，只是配置的时机从向导第一步改为第一次用到模型时。
6. **实施顺序调整**（ROADMAP）。当前的全文覆盖和双栏对照（第 5 步的 2c）完成后：
   - 先做添加论文、文库和页面骨架。这样领读器不依赖流水线就能用，第 6 步的用户测试才做得了。
   - 再做边读边问、导读和读后卡片，然后做用户测试。
   - 研究画像和课题调研合并为一步，引文追踪从第 13 步提前到这里。
   - 知识库先做事实部分（概念、出现位置、回答卡片、检索），掌握程度和复习等用户测试后再做（ADR 0007 的决定不变，只调顺序）。
   - 原理动画、公开渠道、只读 MCP、对象存储排在这些之后。

## 不采用的方案

| 方案 | 不采用的原因 |
|---|---|
| 保持“流水线为中心”，把调研做成 `backfill` 的参数 | 新手不用命令行（P6）；没有引文扩展和覆盖度，做不到“全面” |
| 引入向量库做课题聚类和语义检索 | 第 16 节的触发条件没有出现；子方向分组用一次显式的模型调用就够，检索继续用 FTS5 |
| 引入多语言库（如 i18next） | 现在约 2.3 千行前端，带类型检查的消息表足够；依赖越少越好（ADR 0006 的理由仍然成立） |
| 只留中文，等有非中文用户再改 | 与“适用于所有研究者”的目的冲突；文案和提示词写死得越多，以后改的成本越高，现在最便宜 |
| 内置一个免配置的托管模型 | 与“开源免费、数据在本机”（R21）冲突，有持续费用和滥用风险 |
| 知识库持续镜像到 Obsidian 文件夹并双向同步 | 双向同步会和“SQLite 是唯一真相”冲突；单向导出已经解决“带得走”的问题 |

## 后果

- 新增表：`citation`、`survey_round`、`topic_map`；`inbox` 表（第 5 节已有定义）提前实现。通过 Alembic 迁移加入。
- `Source` 的查询类型增加 `ReferenceList`，OpenAlex 和 Semantic Scholar 的适配器要实现并录制响应。
- 新增 LLM 任务 `map`、提示词 `prompts/map.md`；所有提示词要把输出语言改成参数，`translate.md` 现在写死了语言。
- `server/` 要补：添加论文、文库列表、全局检索、课题页、导出的接口；`web/` 要补页面骨架和消息表，现有文案迁入消息表。
- 输出语言计入指纹后，已有的提取、评估结果指纹不变（默认语言与现状一致），不触发重做。
- 引文扩展会明显增加候选论文数，初筛费用随之上升；每轮的篇数上限和费用预览是必须的。
- 范围变大（两种界面语言、三个新页面）。用第 6 条的顺序控制：先做让领读器独立可用的部分。
- ADR 0007 第 5 条写的“导读和评价可以走本机 agent”已被 ADR 0008 第 1 条取代，本 ADR 不涉及。
