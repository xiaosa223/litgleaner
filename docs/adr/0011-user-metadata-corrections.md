# ADR 0011：用户修正论文元数据另存一张表，只在用户看到的地方覆盖

- 状态：已接受（2026-11-14，用户在“另存用户修正表 / 直接改写论文记录 / 先不做”中选了前者）
- 修订：ARCHITECTURE.md 第 5、12.8 节（“用户可以手填”的落地方式）

## 背景

只上传 PDF、首页找不到 DOI 或 arXiv 编号时，论文以文件名作标题、标明“元数据待补”（第 12.8 节）。首页、文库、笔记、知识库里都显示 `upload-lime` 这样的文件名，用户认不出是哪篇。文档写了“用户可以手填”，没写修正存在哪里。

论文事实层的约定是“只补空字段，不覆盖”（`fill_missing`）：来源返回的元数据是事实，多来源合并靠这个约定保证结果稳定。标题、作者还参与去重、检索索引、嵌入输入和多个过期判断的指纹。

## 决定

1. 新增只追加的 `paper_correction` 表：`(id, paper_id, field, value, created_at)`。`field` 只能是 `title`、`authors`（顿号或逗号分隔）、`venue`、`published_at`（年份或日期）；同一字段以最新一条为准。用户清空某字段等于追加一条空值，表示撤销修正。
2. `paper` 表不改。来源之后查到的元数据照常按“只补空”写入事实层，与用户修正互不覆盖。
3. 修正只在**用户看到的地方**覆盖：阅读页标题和元信息、首页和文库的论文卡片、知识库的笔记与回答出处、个人导出。去重、检索索引、嵌入、提取和评估的输入、各类过期指纹仍用事实层，修正不会让任何派生物失效，也不产生模型费用。
4. 个人导出在论文文件里单列“用户修正的元数据”，与来源元数据分开标明（第 12.1 节“模型和作者分得清”同理）。
5. 界面：阅读页顶栏在“元数据待补”的论文上提示“补全信息”；表单预填代码从解析结果里认出的标题候选（首页第一个标题块，没有时取首页第一段长度合适的文字），用户确认或修改后保存。任何论文都可以修改，入口只在待补时醒目显示。

## 后果

- 全局检索按标题搜索时仍搜事实层标题；文件名作标题的论文要等来源补全或另行扩展检索（未做）。
- 修正是用户数据，进入个人导出；不进入推送（推送用来源元数据）。
- 新迁移 0023。
