# ADR 0001：自建领读器、飞书推送、桌面发布、原文为主的翻译

- 状态：已接受
- 依据：[REQUIREMENTS.md](../REQUIREMENTS.md) 第 6 节的四处冲突

## 背景

三轮用户调研显示，研究者最痛的是“读完留不下”“读得慢”“没人教”“不敢信 AI”和“工具配不起来”。原架构把阅读交给 Zotero 和第三方插件，翻译以 BabelDOC 双语 PDF 为主，只有命令行入口。这几点与调研结论冲突。

## 决定

1. **自建领读器。** 阅读在论文工厂自己的本地界面中完成，Zotero 改为可选同步。
   - 判断“好不好”以公开的人机交互研究为设计参照：Semantic Reader 项目的 ScholarPhi（就地释义）、Paper Plain（面向非专家的章节要点）、Scim（按目标、创新、方法、结果分面高亮）、CiteSee（结合读者文库标注引用）。
   - 用可测量的质量标准和真实用户测试来验收（ARCHITECTURE.md 第 12 节、ROADMAP.md）。
2. **推送仍用飞书卡片。** 卡片可以跳转到领读器。是否提供免建应用的简易接入方式，待验证。
3. **发布形态：桌面安装包，单进程本地服务。**
   - 双击启动后在后台运行一个进程，同时承担网页界面、定时任务、飞书监听和任务队列，并打开浏览器。
   - 首次使用有网页向导；密钥存进系统钥匙串。
   - 命令行（`uv tool install`）和服务器镜像作为进阶方式保留。
4. **原文为主，按需翻译，支持双语。**
   - 默认显示原文。
   - 翻译按段落进行，结果缓存，强制使用课题术语表。
   - 支持段落对照的双语视图；BabelDOC 双语 PDF 降为可选导出。

## 后果

- 新增本地网页后端和前端工程。原“故意不做：网页后端”的条款改为“不做公开的网页后端”。
- 数据库写入方收敛到一个服务进程（命令行操作同样走文件锁），不需要换数据库。
- 发布需要按操作系统打包，并处理代码签名。macOS 要做到无警告安装，需要 Apple Developer ID 签名和公证；嵌入 Python 的打包产物签名有已知坑。签名的费用和账号由维护者决定，见 ROADMAP.md。
- 推送依赖飞书，未配置飞书的用户只能在领读器首页看推荐。
