# ADR 0007：用户知识库与个性化引导

- 状态：提议。三项核心决定已由用户确认（2026-11-08）：掌握程度由系统评价、用户可以修改；每篇论文给 3 个引导问题，每个问题配一张回答卡片；知识库全局一份。其余细节待用户审阅。
- 被修订：第 5 条导读的输入、第 10 条“不引入向量库”由 [ADR 0010](0010-paper-memory.md) 修订（加入论文间记忆和本地向量，仍不引入向量数据库）
- 修订：REQUIREMENTS.md 新增 R26，修改 R9；ARCHITECTURE.md 第 1、3、5、9.4、12.1、13.2、15.2、15.3、17 节，新增第 12.7 节

## 背景

产品定位明确为一个闭环（2026-11-08）：

```
多源调研 → 按规则打分 → 推送 → 带读懂 → 用户说出自己的理解 → 沉淀进知识库
   ↑                                                                    │
   └──────────────── 下一篇按用户已经掌握的知识来引导 ←──────────────────┘
```

现有架构覆盖了前半段和“带读懂”的通用部分（背景卡、释义、读后卡片、先写后看），但没有“用户掌握了什么”这个概念：引导对所有人都一样，读后卡片只存在论文名下，不会影响下一篇的引导。

依据的教学原理（教育心理学中较成熟的结论）：
- 激活先备知识：新知识挂到已有知识上才记得住。
- 类比：要说清类比在哪里失效，否则会形成错误概念。
- 支架与渐隐：只在用户够不着的地方帮忙，越熟练帮得越少。
- 自我解释：用自己的话讲一遍最能暴露没懂的地方。
- 提取练习与间隔重复：回忆比重读记得牢，按遗忘时间安排复习。
- 对比案例。
- 迁移练习：用到自己的课题上才算会了。

## 决定

1. **知识库全局一份，以“概念”为单位。**
   - 概念跨课题共享，课题只是标签（由概念出现过的论文所属课题推出，用户也可以手动加）。
   - 课题术语表（第 7.1 节）继续负责翻译译名，条目按英文术语关联到概念。
2. **区分事实和判断。**
   - 事实（只追加）：概念及其别名；概念在哪篇论文、哪一页出现或被定义；用户的回答卡片及其修订；复习记录；用户对掌握程度的修改。
   - 判断（带指纹，可重算）：系统对回答的评价；每个概念的掌握程度；概念之间的关系（前置、相似、对比）。
3. **掌握程度由系统评价，用户可以改。**
   - 分四级：没见过、见过、能解释、能应用。
   - 由 `domain` 里的纯函数从事件算出，事件包括：回答评价、复习结果、用户修改。用户修改优先，并记录在案。
   - 打开讲解、读过论文本身只能把概念记为“见过”，不能算“能解释”。只有用户自己写出来、经过评价的内容才能提高等级。
4. **每篇论文 3 个引导问题，各配一张回答卡片。**
   - 三个问题分别考三层：理解（用自己的话说出核心机制）、对比（和用户已经掌握的概念或读过的论文比较）、迁移（能否用到自己课题的某个研究目标上）。知识库为空时，对比题改为和论文里的已有方法比较。
   - 问题在读前展示，作为阅读重点；也挂在对应章节开头。
   - 回答卡片“先写后看”：用户写一到三句话，提交后才显示评价和参考答案。评价指出哪里对、哪里漏、哪里理解偏了，每条附原文引用，引用必须通过 `verify_quote`；参考答案同样带引用。
   - 用户可以跳过任何一题，可以把评价标为“有误”（写入 `feedback`），可以随时修改自己的回答（保留修订历史）。
5. **个性化导读。** 打开论文时，按这篇论文的关键概念在知识库中的掌握程度分别处理：
   - 没见过：完整讲解，并用用户已掌握的最相近概念做类比，说明类比在哪里失效；
   - 见过：一句提醒加对比；
   - 能解释、能应用：一句带过，引用用户自己写过的话作为锚点，或者直接跳过。

   导读和引导问题由 LLM 任务 `guide` 生成，回答评价由 `evaluate` 生成，都走统一网关和 JSON Schema 校验，可以走本机 agent（ADR 0005）。
6. **不静默产生费用。**
   - 导读和问题在第一次打开时生成并缓存。指纹包含“相关概念的掌握状态”，只用到这篇论文涉及的概念，不是整个知识库。
   - 知识库变化后，旧导读不自动重新生成；再次打开时提示“你的知识库已更新，要不要重新生成”。规则同术语表（第 7.1 节）。
7. **复习。**
   - 到期的概念按间隔重复的规则排进复习：间隔由纯函数根据复习结果算出，比如 1、3、7、14、30 天。
   - 复习题从用户自己写过的回答出发。用户回答后自评“记得 / 模糊 / 忘了”，不调用模型，不产生费用。用户需要时才调用 `evaluate`。
   - 第 13.2 节周报里的“回顾”改为从到期概念中抽取。
8. **概念识别与合并。**
   - 提取阶段（第 9.4 节）增加 `key_concepts` 字段：概念名、论文中的定义原文、页码、在本文中的作用（核心、前置、提到）。
   - 按别名精确匹配到已有概念；匹配不上时新建概念。疑似同一概念的，由模型提议合并，用户在知识库页确认。做法同论文去重的 `merge_candidate`。
9. **知识库页**：按课题标签浏览和检索概念（FTS5），查看每个概念的掌握程度、出现过的论文、自己的回答卡片、相关概念；可以修改等级、合并概念、导出 Markdown。
10. **不引入向量库**（第 16 节）：概念匹配靠别名和模型提议，检索靠 FTS5。

## 后果

- 新增表：`concept`、`concept_alias`、`concept_occurrence`、`concept_link`、`concept_merge_candidate`、`answer_card`、`answer_evaluation`、`mastery_event`、`mastery_state`。通过 Alembic 迁移加入。
- `extraction` 增加 `key_concepts`，`extractor_version` 随之变化，旧提取结果由 `stale` 报告列出，不自动重做。
- 新增 LLM 任务 `guide`、`evaluate`，提示词 `prompts/guide.md`、`prompts/evaluate.md`。
- 数据去向（第 15.3 节）增加：用户的回答和知识库片段会发给 `guide`、`evaluate` 任务的模型提供方或本机 agent。
- 冷启动：新用户知识库为空，第一篇的导读接近通用导读。首次向导可以让用户勾选熟悉的概念，作为初始的“用户修改”事件。
- 写回答有负担：每篇最多 3 题、每题一到三句、允许跳过。上线后监测回答率和跳过率。
- 模型评价可能出错：每条评价必须带原文依据，用户能改等级、能标“有误”。这些都会写入反馈，用于校准评价提示词。
