# ADR 0010：论文间记忆——入库的论文以后读到相关论文时会被提起

- 状态：已接受（2026-11-11，用户决定）。用户确认方向，并要求加本地向量（第 10 条）；关系只在文库内建立。
- 修订：ARCHITECTURE.md 第 1、4、5、12.2、12.4、12.7、15.2、15.3、16、17 节，新增第 12.9 节；ADR 0007 第 5 条、第 10 条（导读的输入；不引入向量库改为“不引入向量数据库”）
- 依据：[开源实现调研](../experiments/2026-11-11-memory-open-source-survey.md)

## 背景

用户的问题（2026-11-11）：一篇论文入库后，以后读到一篇方法类似、或承上启下的新论文，带读的模型会不会提一句，还是入库了就不管了。

按现有设计基本是“不管了”：

| 已有 | 缺的 |
|---|---|
| 知识库以概念为单位：同一个概念在哪些论文里出现（ADR 0007） | 论文与论文之间的关系：谁扩展了谁、用了谁的方法、和谁比较、结论是否矛盾 |
| `citation` 表记录参考文献、对到库内论文（第 5 节，ADR 0009 提前） | 引用句和引用意图；“当前论文引用了你读过的论文”没有在阅读时用上 |
| 用户的笔记、高亮、回答卡片存在各自的表里 | 没有统一检索，下一篇的导读和问答拿不到“你在读 A 时写过……” |
| 导读输入写了“用户读过的相关论文”（第 12.7 节） | 怎么找出来、存在哪、什么时候提，没有规定 |

调研结论（见依据）：成熟系统都在往“事实只追加，冲突靠标记失效或检索排序消化”收敛；发现关系靠便宜的信号（引用、共现、文本检索），模型只做核实；对读论文的人最有效的提示是“这篇引用了你读过的那篇，引用句是……，你当时写过……”（CiteSee）。

## 决定

1. **记忆由三部分组成，都放在 SQLite 里，不引入向量数据库。**

   | 部分 | 内容 | 层 |
   |---|---|---|
   | 概念记忆 | ADR 0007 的概念、出现位置、掌握程度，不变 | 事实 + 判断 |
   | 论文关系 | 本 ADR 新增：两篇论文之间的事实关系和判断关系 | 事实 + 判断 |
   | 个人记忆 | 用户写过的东西：笔记、高亮、回答卡片、问答、读后卡片里的修改 | 事实，只追加 |

   只在**文库**范围内建关系：有阅读状态、笔记、或用户添加的论文（第 12.8 节）。流水线发现的几千篇候选不参与，费用和噪声都有上限。

2. **事实关系（零模型费用，入库时生成）。**
   - `citation` 增加引用句和意图：解析全文得到的参考文献带上正文里引用它的句子；Semantic Scholar 的 `ReferenceList` 带回 `contexts`、`intents`（背景、方法、结果比较）、`isInfluential`，原样写入，标明来源。
   - 由事实推出、不单独存的关系，用查询得到：
     - 直接引用：A 的参考文献对上了库内的 B；
     - 共同引用：A 和 B 引用了至少 k 篇相同文献（文献耦合）；被至少 ⌈n/3⌉ 篇库内论文共同引用的文献视为本课题的重要前作（借 PaperQA2）；
     - 共享概念：两篇都有同一个 `core` 概念（来自 `concept_occurrence`）；
     - 共享数据集或方法类别：来自 `extraction.datasets`、`extraction.method`，按归一化名称匹配；
   - 内容相近：本地向量的余弦相似度（第 10 条），找“方法相近但互不引用、用词不同”的论文。
   - `paper_mention`（新表，事实）：用户笔记或论文正文里，按 FTS5 匹配到库内某篇论文的短标题、方法名（如 “LIME”“Transformer”）的位置。做法同 Obsidian 的未链接提及，不调用模型。

3. **候选打分是纯函数。** 对上面的信号加权求和（直接引用 > 引用句带“方法/扩展”意图 > 共享核心概念 > 向量相似度 > 共享数据集 > 文本检索分），权重写在 `config/memory.yaml`，计入 `policy_hash`。改权重只重排，零费用重算，同 `rubric rescore`。

4. **判断关系由模型核实，不由模型发现。**
   - 新 LLM 任务 `relate`。一篇论文进入文库（添加、第一次打开、或推送后点“稍后读”）时，取打分最高的 N 对候选（默认 5），一次调用核实。
   - 输入：双方的提取结果片段（`problem`、`approach`、`method`、`claims`）和引用句；论文内容按不可信数据包裹。
   - 输出（JSON Schema）：每对给出一种关系或“无关”。关系类型：`extends`（扩展或改进）、`uses_method_of`（用了对方的方法）、`compares_with`（实验对比）、`contradicts`（结论冲突）、`similar_approach`（思路相近、无引用关系）、`same_problem`（解决同一问题的不同做法）。每条必须给出双方原文引用，经 `verify_quote` 逐字核对，对不上的整条丢弃。
   - 写入 `paper_relation`（新表，判断）：键 `(paper_a, paper_b, kind, input_hash, producer_version)`；带状态 `valid / superseded / rejected_by_user`。新证据推翻旧判断时，旧记录标 `superseded_by`，不删除（借 Graphiti）。用户可以确认、删除或改类型，写入 `feedback`。
   - 费用：受 `relate` 的任务预算限制，预算用完时推迟（`Deferred`）。只比较新进入文库的论文和已有的文库论文，不反向重算旧论文之间的关系；历史回填用显式命令 `litgleaner memory backfill`，先给出对数和预计费用。

5. **个人记忆统一检索。** 新建一个 FTS5 索引 `memory_fts`，收录笔记、高亮、回答卡片、问答、读后卡片中用户写的部分，以及每篇的提取结果摘要字段。每条记录保留出处（论文、页码、类型、作者是谁：作者原文、模型生成、用户写的）。全局检索（第 12.8 节）和下面的提起都用它。

6. **什么时候提起。**

   | 时机 | 提什么 | 来源 |
   |---|---|---|
   | 打开论文（导读顶部“和你读过的论文”） | 最多 3 条：已核实的关系卡（类型、对方论文、双方原文、你在对方论文上写过的一句）；本文引用了你库里的哪几篇、哪几篇引用了本文 | `paper_relation`、`citation`、`memory_fts` |
   | 读到某段 | 段落里的引用指向库内论文时行内标出（借 CiteSee）：悬停显示对方标题、你的阅读状态、你写过的笔记摘句；概念出现处链到其他论文中的同一概念 | `citation`、`concept_occurrence` |
   | 边读边问 | 检索结果加入本篇的已核实关系、相关论文的提取结果、你的笔记；回答里提到别的论文必须引用其原文或你的笔记 | 同上 |
   | 引导问题 | 对比题优先和已核实关系里的论文比较（ADR 0007 第 4 条） | `paper_relation` |
   | 回看旧论文 | 文库和论文页显示“后来读的 B 扩展了它” | `paper_relation` 反向 |

   - 提起的内容只来自上表的事实和已核实判断，模型不能凭空说“这和你读过的 X 类似”。
   - 导读缓存的指纹加入“相关关系和笔记的指纹”；记忆变化后不自动重写导读，同 ADR 0007 第 6 条。

7. **分层借自 Letta，但不让模型改写记忆。** 研究画像（背景、内容、目标）作为常驻块进入导读和问答的提示词；其余记忆按需检索，每次只放与本篇有关的条目。模型不写入任何记忆表；记忆的写入只有三条路：事实层流程、`relate` 的校验后结果、用户操作。

8. **不做**：向量数据库（Chroma、Qdrant 等独立服务或扩展）；社区摘要；引文图谱可视化；让 agent 自编辑记忆。

9. **先做成品，再用案例微调。** 用一组真实论文案例作为验收集：每组 3–6 篇，已知关系（例：Transformer → BERT 扩展；LIME 与 SHAP 同一问题；一篇复现论文与原文结论冲突）。指标：已知关系的召回、错误关系的数量、每篇的 `relate` 费用。权重、N、提示词按案例调整，调整记录写进 `docs/experiments/`。

10. **本地向量（用户 2026-11-11 要求）。**
    - 触发第 16 节“关键词检索明显不够用”的条件：用户要找的正是“方法相近但互不引用、用词不同”的论文，FTS5 按词匹配找不到。仍然不引入向量数据库。
    - 新端口 `Embedder`：`embed(texts) -> vectors`，带模型名和维度。默认适配器 `fastembed`（Qdrant，Apache-2.0，ONNX Runtime，不需要 PyTorch），默认模型 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`（Apache-2.0，384 维，约 220 MB，多语言，中英文可以互相检索）。在 `bootstrap` 注册，`config/memory.yaml` 可换模型或关闭。
    - 模型第一次用到时下载并校验，存在数据目录；没下载或关闭时，向量信号缺席，其余信号照常，界面不报错。
    - 向量存进 `paper_embedding`（判断层）：键 `(paper, input_hash, embedder_version)`，值是 float32 二进制列。输入是标题、摘要和提取结果的 `problem`、`approach`。文库几千篇以内在内存里逐个算余弦相似度，不建索引。
    - 换模型就是新的 `embedder_version`：旧向量保留，`stale` 列出，由 `litgleaner memory reembed` 显式重算（本地计算，零模型费用，但要时间）。
    - 向量只用来产生候选，不作为关系的依据：判断关系仍然要经过 `relate` 核实并带双方原文。
    - 同一套向量也用于全局检索的“相关论文”和边读边问的段落召回（与 FTS5 的 BM25 分合并排序，借 Mem0 的混合打分）。

## 不采用的方案

| 方案 | 不采用的原因 |
|---|---|
| 照搬 Mem0 / A-MEM：每篇论文让模型抽取记忆并和近邻比较 | 依赖向量数据库；每篇多次调模型；A-MEM 会改写已有记忆，违反事实只追加 |
| 引入向量数据库（Chroma、Qdrant、sqlite-vec 扩展） | 个人文库几千篇以内，内存里逐个算就够；原生扩展增加打包和签名的麻烦 |
| 用 SPECTER2 等科学论文专用模型 | 只支持英文，需要 PyTorch；适用于所有研究者的目的要求多语言 |
| 调用 API 提供方的嵌入接口 | 用户要求本地；本地模型零费用、数据不出本机 |
| Graphiti、LightRAG 的图数据库 | 第 16 节不引入；个人库几百篇，SQLite 的查询足够 |
| 只用引用关系，不用模型 | 方法相近但互不引用的论文（`similar_approach`、`same_problem`）找不到，这恰好是用户问的情形 |
| 让模型直接判断“和库里哪些论文有关” | 要把整个文库发给模型，费用随文库增长；没有原文依据时无法核实 |

## 后果

- 新增表：`paper_relation`（判断）、`paper_mention`（事实）、`paper_embedding`（判断）；`citation` 增加 `contexts`、`intents`、`influential`、`source` 列；FTS5 虚表 `memory_fts`。通过 Alembic 迁移加入。
- 新增 LLM 任务 `relate`、提示词 `prompts/relate.md`、配置 `config/memory.yaml`（权重、N、共同引用阈值、嵌入模型）。
- 新端口 `Embedder` 和适配器 `fastembed`，新增依赖 fastembed（带入 onnxruntime、tokenizers、huggingface-hub），安装包增大；模型文件约 220 MB，首次使用时下载。打包选型（ROADMAP F）要验证 onnxruntime 能被打进安装包。
- Semantic Scholar 适配器实现 `ReferenceList` 时取回引用句和意图（ADR 0009 已要求实现 `ReferenceList`）。
- 数据去向（第 15.3 节）增加：两篇论文的提取片段会发给 `relate` 任务的模型提供方；用户笔记只在导读和问答中按需发送。
- 每篇进入文库的论文多一次 `relate` 调用（约 5 对候选的片段），有预算上限；没有配置模型时只显示事实关系（引用、共享概念），不显示判断关系。
- 实施顺序：放在 C（导读、问答、读后卡片）里，与 ADR 0007 的知识库事实部分一起做；`citation` 的引用句随 E 的 `ReferenceList` 一起补全，在那之前只用解析全文得到的引用。
