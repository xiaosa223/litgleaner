# ADR 0012：上传任务书等文档，自动推断研究画像并起草检索式

- 状态：已接受（2026-11-14，用户在“自动填完一键启用 / 完全自动直接启用 / 只填背景内容目标”中选了第一项；文件解析选“PDF/DOCX/MD/TXT 本地抽取”）
- 修订：ARCHITECTURE.md 第 7.1、7.2、15.2 节

## 背景

研究画像的背景、内容、目标要求研究者自己写（第 7.1 节）。很多研究者手里已经有现成的文字：课题任务书、开题报告、比赛文档、基金申请书。让他们再改写一遍是新手试用的主要门槛。目标是“把文档甩进去就行”。

第 7.2 节规定检索式草稿不会自动生效，研究者确认后才使用；启用课题后每天会自动检索并产生初筛费用，推断错误的代价是持续花钱检索不相关的论文。

## 决定

1. 新建课题时可以上传一个文档（PDF、DOCX、Markdown、纯文本，单个文件，上限 20 MB）。上传本身就是用户显式发起的操作，允许产生模型费用；预算规则照常生效。
2. 文字抽取在本地完成，不走 `Parser` 端口、不消耗 MinerU 额度：PDF 用 pypdf 抽文字层，DOCX 用标准库读 zip 内的 `word/document.xml`，Markdown/TXT 按 UTF-8 读入（失败时试 GB18030）。抽取逻辑放 `adapters/documents/`，实现新端口 `DocumentText`。扫描件抽不出文字时明确提示“未识别到文字，请上传带文字层的文件或手动填写”，不静默降级。
3. 新增 LLM 任务 `profile`（提示词 `prompts/profile.md`）：输入抽取出的文字（超过约 12000 token 时截断并注明），输出 `name`、`background`、`content`、`goals`，经 JSON Schema 校验后由代码裁到课题字段的长度上限，目标最多 5 条。文档内容是不可信数据，与论文内容同样处理。接口 `POST /api/topics/profile-from-document` 同步返回推断结果，不写文件、不启用课题。
4. 结果预填到新建课题的表单里，用户可以修改；点“创建并起草检索词”写入课题（未启用），进入课题页后**自动开始**现有的 `topic draft`（第 7.2 节），不再要求用户点“让模型起草”。
5. 草稿生成后，用户在检索词页点**“保存并启用”**合并草稿并启用。保留第 7.2 节“研究者确认后生效”的原则：从上传到启用只需要创建、启用两次点击，不点启用就不会开始每天检索。
6. 原文件和抽取的文字都不保存，画像里不记录出处。

## 后果

- 多一个 LLM 任务路由；未配置模型时上传返回 `model_configuration_required`，前端弹出模型配置后自动继续（与翻译相同）。自动起草的费用沿用起草预览的估算，但不再等用户确认预览，上传文档即视为同意这两次调用。
- 新增端口 `ports/document_text.py` 与适配器子包 `adapters/documents/`，需要同步 import-linter 的适配器独立性列表。
- 不支持 .doc（旧版 Word 二进制）、PPT、图片；扫描件 PDF 需要用户自己转换或手填。后续若要支持，再评估走 `Parser` 端口。
