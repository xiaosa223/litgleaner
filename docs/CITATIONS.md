# 引文事实与参考文献查询

`citation` 保存论文引用了谁的原始证据：参考文献条目、来源、来源内的零基序号、精确标识符，以及来源提供的引用句、意图和重要性标记。解析条目另外保留原页和坐标。引用记录只追加，重复写入保留已有事实。参考文献条目的 `position` 包含来源、原序号和内容指纹；日常被引关系按来源、准确双端标识符和证据内容生成指纹，抓取日期、查询顺序及分页位置不参与，避免重叠窗口重复登记。

关联只采用 DOI 等精确标识符。多个标识符命中不同论文时保持未关联，原始条目照常保存。目标论文后来入库时，查询可以按全部命中唯一论文的标识符动态关联，原记录不改写。来源给出的 `intents` 和 `influential` 原样保留，后续论文关系核实使用这些证据。

## 日常被引关系

日常发现的 `CitationWatch` 除了保存引用者论文和发现记录，还保存来源明确返回的引用关系。来源同时返回两个种子的引用者时，只连接能核实的双端；一篇论文只引用其中一个种子，就只记录这一条关系。

- 按单个 DOI 请求被引列表的来源，以该请求的种子作为被引端，保留每个返回条目的引用端标识符和外层证据。
- 批量 OR 查询的来源，将返回论文明确列出的引用编号与本次查询的种子编号求交；无法核实具体双端时保留论文候选并跳过关系。
- 只有本次采纳的候选记录可以提供引用端。整组标识符命中冲突、缺少精确标识符或不在本次采纳范围时，不登记该引用关系。
- 候选和证据同步移除布尔值、列表、字典及空白等非法标识符，已知编号另校验格式；合法 DOI 等标识符继续使用。清理沿用原候选去重结果、条数和配额，原始响应完整保留，避免坏 ID 先合并两篇论文再误连关系。
- 被引端尚未入库时保存其标识符，后续入库即可动态查询反向关系；标题相似度不用于连边。
- 来源序号保存在 `source_position` 中供追溯，分页、种子顺序或抓取日期变化不会单独产生新版本。证据内容变化时追加，旧记录保留。

原始响应先压缩归档，然后在一个短事务中保存本批论文、发现记录、引用关系和游标。任一关系写入失败会回滚该批数据库修改；结果被截断时，已采纳范围正常登记，游标保持不变。该摄取复用既有日常请求和候选，不增加请求数、模型调用或初筛范围。

现有查询接口即可读取日常关系，无需新增配置、迁移或接口。已入库但本次重叠窗口未再次返回的历史论文不会自动补抓；历史参考文献可使用下面的显式刷新或课题调研。阅读路线按不同的引用者论文计数，同一关系的多来源证据不会重复抬高引用次数。

OpenAlex 的关系方向依据官方 [`referenced_works` 工作字段](https://github.com/ourresearch/openalex-docs/blob/main/api-entities/works/work-object/README.md) 和 [`cites` 筛选](https://github.com/ourresearch/openalex-docs/blob/main/api-entities/works/filter-works.md)，多值筛选遵循[同字段 OR 规则](https://github.com/ourresearch/openalex-docs/blob/main/how-to-use-the-api/get-lists-of-entities/filter-entity-lists.md)。Semantic Scholar 的引用元信息按 [Graph API citations 文档](https://api.semanticscholar.org/api-docs/graph)请求 `contexts,intents,isInfluential`，与引用端论文元数据一起返回。协议通过离线响应验证，尚未调用真实来源 API 验收本段变更。

## 查询和显式登记

| 接口 | 行为 |
|---|---|
| `GET /api/papers/{paper_id}/citations` | 读取 `outgoing` 与 `incoming`，保留原记录和当前关联的论文标题/ID；不联网、不产生任务 |
| `POST /api/papers/{paper_id}/citations/index` | 从已有解析归档登记引文；不重新解析 PDF，不请求来源或模型，可安全重复执行 |
| `POST /api/papers/{paper_id}/references/refresh` | 显式查询已启用的参考文献来源并登记引文；请求体 `{}` 使用全部支持来源，或传 `{"sources":["配置中的来源名"]}` |

刷新是同步请求，沿用来源的超时和频率限制。响应中的每个来源都有 `fetched`（原条目数）、`added`（本次新增记录）、`candidates`（来源返回的候选元数据数）、`truncated`、`warnings` 和 `error`。一个来源失败时返回错误类型，其余来源继续；截断会明确标出。接口沿用本地会话、Host/Origin 和 CSRF 保护。

刷新目前需要本篇论文的 DOI。`ReferenceList(dois=...)` 一次性查询它引用的文献，不套用日常新论文的出版日期窗口，也不推进日常抓取游标；`CitationWatch` 则查谁引用了它。每次按原始条目执行来源 `max_records` 上限，缺少目标详情或目标已删除时仍保留原条目及可用 ID。

来源返回的候选元数据不会在刷新时新增为论文，也不会排入初筛、取全文或评估。因此刷新和本地登记都不调用模型。课题调研在明确预览和确认之后复用这些候选。

新解析的参考文献与全文状态、检索索引在同一事务中落盘；引文写入失败会回滚本篇全文状态，其他论文可继续处理。迁移 0012 保留旧问答、批注、概念与 FTS 数据。旧归档通过显式本地登记接口补齐，普通读取保持只读。

原始网络响应压缩归档到 blob，单条引文保留来源原 JSON 或解析原文。共享 HTTP 客户端的响应日志按调用线程隔离，避免并发的网页刷新与后台抓取混入彼此的归档。

两家来源的字段和方向依据已读取的官方文档实现：[Semantic Scholar Graph API](https://api.semanticscholar.org/api-docs/graph)、[OpenAlex API recipes](https://help.openalex.org/how-to/api-recipes.md) 和 [OpenAlex single entities](https://help.openalex.org/api/get-single-entities.md)。新增的参考文献 JSON fixtures 按官方结构模拟构造，用于离线协议测试；尚未做真实来源 API 或浏览器验收。

课题调研和阅读路线已复用引文事实；文献耦合打分、向量候选、`relate` 语义关系核实及相应界面随后续模块接入。

参考文献基础模块验收：后端全量 1806 项通过，覆盖率 94.50%；Ruff、格式、Mypy 206 个源文件及三项依赖契约通过。独立审查 103 项定向验证及 92 项修复补验通过，无剩余问题。测试使用临时数据库、MockTransport 和假模型，未调用真实来源、模型或钥匙串。

日常被引关系验收：53 项专项和 135 项相邻来源回归通过，涵盖精确方向、缺失目标、非法 ID、配额、重试幂等、原始归档、事务回滚及阅读路线去重；全量 3424 项通过，覆盖率 95.29%。Ruff、442 文件格式、Mypy 278 个源文件、三项依赖契约及独立审查通过。使用临时数据库和模拟响应，未调用真实来源、模型或钥匙串；本段未改前端。
