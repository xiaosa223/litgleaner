# 课题地图后端

地图读取本课题当前画像下通过初筛的论文，用 `map` 模型任务按子方向分组。先预览、再明确确认；读取、修改配置和新增论文都不会自动调用模型。结果只追加保存，重复生成相同输入会复用已有结果。

## 接口

所有接口需要本机会话，POST 还需要 `X-CSRF-Token`。预览请求体可省略或为 `{}`；确认只接受 `plan_hash`，拒绝额外字段。

| 方法与路径 | 用途 |
|---|---|
| `POST /api/topics/{topic_id}/map/preview` | 只读预览论文范围、输入预算、费用和缓存命中 |
| `POST /api/topics/{topic_id}/map`，`{"plan_hash":"..."}` | 重新核对预览指纹并幂等排队 |
| `GET /api/topics/{topic_id}/map` | 当前地图、未分组、新增论文及过期原因 |
| `GET /api/topics/{topic_id}/map/jobs/{job_key}` | 任务状态、结果、费用及错误 |
| `GET /api/topics/{topic_id}/map/history?limit=20` | 历史结果，按生成时间倒序；上限 100 |
| `GET /api/topics/{topic_id}/map/results/{map_id}` | 按编号读取本课题的某次结果 |

预览不写数据库、不联网、不调用模型。`estimated_usd` 使用 `map` 任务单次历史费用均值；没有历史时为 `null`，无可发送论文或命中缓存时为零。实际费用以任务返回的 `cost_usd` 为准，包括同一 scope 内已报告用量的失败响应，所有模型任务共享每日预算。

确认后由常驻服务的按需队列执行，也可以用 `uv run litgleaner run --stage map` 推进已确认的任务。日常规划不生成地图。暂停的课题仍允许用户显式生成地图；没有配置 `map` 路由时可读历史，确认生成会要求先配置模型。

## 输入与结果校验

`config/app.yaml` 的 `map.token_budget` 默认 12000，必须是 512–64000 的整数。预算包括完整系统提示、数据隔离包装和论文 JSON，沿用保守字符估算。画像本身超过预算时拒绝预览；没有任何论文能纳入时拒绝确认。

论文按稳定编号顺序逐篇纳入。每篇发送标题前 1000 字、摘要前 2000 字，以及已有提取的 `summary`、`conclusion`、`innovation` 各前 1000 字。不会为了地图补取全文或重新提取。预算外的论文在预览的 `omitted_paper_ids` 和警告中明确列出，不允许模型为它们分组。

模型原始输出必须满足 5–8 个子方向的 JSON Schema，每组有名称、说明及论文编号。代码再丢弃不在实际发送范围内的编号；同一篇重复归组时保留第一组；空白名称、空白说明和清理后没有论文的组被移除。清理后可能少于 5 组，保留警告，不额外调用模型补组。所有未归组论文都保留在 `ungrouped`，包括预算外论文。

## 缓存、过期与新增论文

迁移 `0016` 新增 `topic_map`，不重建旧事实表或全文索引。数据库禁止修改和删除地图，并以课题、画像哈希、输入哈希和生产者版本保证并发首写幂等。

输入指纹包含实际发送文本、完整系统提示、预算、阅读语言及所发送论文的完整来源指纹。来源指纹包含完整标题、摘要、提取内容及提取版本；截断区外的内容变化也会使旧地图过期。生产者版本包含模型、提示词版本和提供方版本。确认和执行分别检查这些指纹；旧预览需重新预览，已排队但输入或配置改变的任务停止执行，不调用旧计划中的模型。

确认后新增论文不扩充该任务已授权的输入，也不使旧任务失效。读取接口通过 `new_paper_ids` 提示当前通过初筛、但尚未出现在该地图确认范围中的论文；这些论文同时进入当前视图的 `ungrouped`。新论文数量与 `stale` 分开：单纯增加论文只显示新增提示；画像、语言、预算、模型、提示词或已发送论文内容改变会给出过期原因。

主视图优先选择与当前配置匹配、且已发送论文来源仍有效的最近历史地图。切换语言、提示词或预算后再切回，可以复用旧结果；以后新增论文仍显示正确的历史地图和新增提示。没有有效候选时保留可读的历史结果并标明过期。历史结果接口返回生成时保存的原记录。

预算不足时任务保留待处理，次日可继续；普通临时错误沿用队列退避和重试。预览确认后的范围和费用 scope 不随重试扩张。
