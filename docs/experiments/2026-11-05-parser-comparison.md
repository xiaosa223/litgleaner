# 解析器对比：MinerU VLM 与 PDF 直接提取

- 日期：2026-11-05
- 复现：`source .env.example && uv run python scripts/probe_parsers.py data/probe`（结果有缓存，重跑不消耗额度）
- 原始数据：`data/probe/report.json`（不进 git）

## 结论

1. **英文论文两者基本持平。** IEEE 双栏、NeurIPS 单栏、ACM 双栏三篇，修正章节识别规则后，摘要覆盖率、章节识别和送入模型的内容都一致。
2. **中文期刊 MinerU 明显更好。** PDF 直接提取找不到摘要，也识别不出参考文献。
3. **最初的差距大多来自章节识别规则，不是解析器。** 第一轮 IEEE 版式的直接提取找不到摘要和引言；修了规则后与 MinerU 持平。这批规则问题对 MinerU 同样存在（中文论文的摘要和结论也没找到）。
4. **MinerU 的固有优势**：参考文献结构（引文追踪需要）、公式、表格和图片位置。**直接提取的优势**：每篇 0.3 秒、不耗额度，而 MinerU 需要 20～65 秒。

**建议**：深评论文默认用 MinerU。初筛后每天只有少量论文需要解析，额度足够（见下）。`pdf_text` 作为 MinerU 不可用时的降级方案。

## 这次修正的规则

都已写成测试（`tests/unit/test_chunker.py`、`test_mineru_mapping.py`、`test_pdf_text_parser.py`）：

- 小型大写标题会被拆成 `I NTRODUCTION`、`C ONCLUSION`，中文标题常写成 `5 总 结`、`参　考　文　献`：分类时同时检查去掉空格的写法。
- 中文期刊页首有英文标题：它不算正文开始，之后仍要检测摘要。
- `Abstract In recent years`（没有破折号）、`Key words`（有空格）、`结束语` 都要识别。
- MinerU 还会输出 `header`、`footer`、`image`。前两者丢弃，`image` 归为图。第一个样本里没有它们，是“未知类型标记为低质量”的保护机制发现的。
- 中文期刊在参考文献后附作者简介和照片，不能算作参考文献。
- 直接提取时，摘要常和标题、作者挤在同一段，需要拆开；`2003.`、`2262 计算机研究与发展` 是年份和页眉，不是章节号。

## 局限

- **没有测到“对打分的影响”。** 打分需要真实的大模型，目前还没有接入。这里测的是送进模型的内容质量，它决定了模型能看到什么，但不等于最终分数。接入大模型后，用同一批论文跑两种解析器并比较分数。
- **样本只有 4 篇**，每种版式各一篇，耗时各测一次。Elsevier、Springer、扫描件都还没测。
- **直接提取在中文期刊上为什么找不到摘要**还没深究：它是降级方案，暂不投入。

## 额度估算

按每天初筛通过 20 篇、每篇 15 页估算，每天约 300 页，低于 1000 页的优先额度。这是假设值，上线后用实际数据校正。
