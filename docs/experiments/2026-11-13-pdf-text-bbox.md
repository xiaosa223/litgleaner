# `pdf_text` 块坐标实测（2026-11-13）

没有配置解析服务时默认用 `pdf_text`。它原先不产生块坐标，原版视图（默认视图）上因此没有“译 / 问 / 记”按钮，覆盖和对照也没有“翻译本页”，新手打开论文后找不到任何操作入口。这次让 `pdf_text` 按 ARCHITECTURE 9.1 的约定填 `bbox`（0–1000 千分比、原点在左上）。

## 做法

- pypdf `extract_text(visitor_text=…)` 的回调片段拼起来与输出逐字相同，每个片段带文字矩阵、变换矩阵和字号。据此得出每个字符的起点；字宽查字体 `/Widths` 表，查不到用该字体的平均字宽，没有字宽表时西文按 0.5 个字号、全角字按 1 个字号。
- 按 `extract_text` 的原样分行，再按原切分规则合段，段的坐标是各行的并集；段落跨栏续写时只取行数多的一栏。
- 拼接与输出不一致（pypdf 行为变化）、页面旋转、文字斜排或竖排、矩阵或字号异常时不给坐标，文字照常输出。左、上、下边越出页面 5% 以上（页面外的隐藏文字、极端缩放）也不给坐标，不夹到页边上冒充合理位置；只有估计出来的右边越出时夹到页边。
- 解析器标识 `pdf_text@pypdf` 不变：块的文字、类型、页码和顺序与之前逐块相同，下游按块序号存的译文、批注不受影响；改标识会让所有论文重新解析、引用指纹失效。

## 结果

| PDF | 文字与切分不变 | 有坐标的正文与标题块 |
|---|---|---|
| arXiv 1907.10485（两栏，IEEE） | 是 | 97 / 97 |
| arXiv 1602.04938（LIME，两栏，ACM） | 是 | 104 / 104 |
| 领读器演示论文 | 是 | 136 / 141 |
| 上传样本 | 是 | 97 / 97 |

与同一篇（1907.10485）MinerU VLM 输出的块坐标对照，按文字匹配上的 22 个长段落 IoU 中位数 0.89。只按半个字号估宽时中位数 0.78，左栏段落的右边会越过栏缝；改查字宽表后左栏右边 476–495（MinerU 491–493），右栏 917–932（MinerU 921–924）。IoU 低于 0.5 的 3 个都是切分差异：`pdf_text` 把相邻段落合成一块，或跨栏段落取了另一栏。

浏览器走查（独立临时实例，1280 宽）：上传两栏论文后原版视图出现 25 个段落区域、18 个带“译 / 问 / 记”的正文段；对照和覆盖模式每页出现“翻译本页 N 段”；框与原文对齐，竖排的 arXiv 水印被排除。“添加并打开”后阅读页先显示“正在识别段落结构”，约 4 秒后自动出现按钮，不用刷新；控制台无错误。轮询单独请求论文状态，某次失败只跳过，不替换阅读页；约 5 分钟仍未识别完时改为“稍后刷新再看”。

## 未验证

- 中文期刊（多为复合字体，没有字宽表，右边靠估计）。
- 实际翻译后的覆盖效果：走查时本机免费网关对请求返回“账号受限”，翻译链路已在段落视图里另行验证（见 [模型原地配置实测](2026-11-13-model-setup-ui.md)）。
