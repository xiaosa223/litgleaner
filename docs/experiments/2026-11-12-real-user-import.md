## 问题与建议顺序

### P1：默认演示解析器无法处理用户上传的真实 PDF

服务日志在导入后记录 `fake_parser@1` 的 `UnicodeDecodeError`。`src/litgleaner/adapters/fakes/parser.py:25` 把 PDF 第一行之后的数据当作 JSON 解码，适用演示文件，不能处理此次真实文件。

只读数据库快照显示 PDF 状态为 `available`，`doc_key` 为空；解析任务 `pending`、已尝试 1 次，`last_error` 为 UTF-8 解码失败；首次入库任务等待解析。页面没有生成真实导读。

建议提供明确的真实阅读启动配置，使用现有 `pdf_text` 或配置完毕的 MinerU，并在真实文件导入前检查演示适配器。应同时处理演示文件与真实文件的兼容边界，再做代码修改。

### P1：阅读页缺少可见的处理状态和恢复入口

初次元数据提示会消失，重开页面后只看到“没有摘要”。用户无法从这里区分元数据缺失、解析排队和解析失败。截图见 `data/user-test-20261112/guide-missing-status.png`。

建议持久显示元数据、解析、提取的当前状态，失败时给出原因和对应修复或重试入口。

### P1：问答前端仍是预览

问答页已如实标注未接服务。此次真实用户无法完成“阅读后提问、获得带页码的回答”路径；没有把示例回答当作通过证据。

建议先接通现有后端问答契约，再以当前论文验证实际引用页码和错误反馈。此次没有测试付费模型、翻译、问答生成或引用核验。

### P2：默认元数据来源与用户上手流程不完整

前端已识别 arXiv 编号，但作者、年份和摘要未补齐；数据库 `authors=[]`、`abstract=null`。设置页没有解决这些配置问题的入口。

建议提供适用普通用户的来源与解析器配置流程，明确展示需要补充的元数据。此次只验证了默认来源失败，未验证启用真实来源后的补全。
