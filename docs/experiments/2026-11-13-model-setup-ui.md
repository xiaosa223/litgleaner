# 模型原地配置界面实测（2026-11-13）

把第 15.5 节“第一次用到模型时在原地引导配置”接到领读器上，并在真实浏览器里按新手路径走了一遍：没有任何模型配置 → 打开论文 → 翻译、翻译全文、提问 → 原地弹出配置 → 保存后自动继续。实测发现并修复了三个会让新手卡住的问题。

## 环境

- 独立实例：配置复制到会话临时目录，删除 `llm.yaml` 模拟新用户；数据库、blob 都在临时目录，未改仓库配置和默认演示库。
- 解析器：`pdf_text`；论文：arXiv `1602.04938v3`（LIME），经“添加论文”上传。
- 模型：本机 OpenAI 兼容网关 `workbuddy-ai/hy4free`（报价 0），表单选“其他 / 本地网关”，不填 key，因此没有写系统钥匙串。

## 走查结果

| 场景 | 结果 |
|---|---|
| 设置页“模型” | 未配置时只显示“配置模型”按钮；保存后列出各功能所用模型及单独限额 |
| 段落翻译 | 点“翻译这段”→ 弹出“先配置一个模型”，写明是“翻译”需要模型、PDF 和笔记不受影响 → 测试并保存 → 同一段自动重新请求，流式显示并通过逐句校验 |
| 翻译全文 | 估算接口返回 409 时弹窗说明需要先配置，“现在配置”保存后重新估算，确认后才开始 |
| 边读边问 | 提交返回 409 → 原地配置 → 保存后自动重新提交同一问题（202），进入轮询 |
| 连接测试失败 | 显示可读原因和“仍然保存”，不回显第三方错误 |

## 发现并修复的问题

1. **连接测试把推理模型误报为失败。** 测试请求输出上限原为 128 token，推理模型先输出思考内容，128 token 用完时正文为空（`finish_reason=length`, `content=null`），界面提示“请检查 API key”，实际 key 和模型都没问题。实测这个模型回答一句话约用 250 token。改为上限 1024（用户设置更小时取用户值），`estimated_usd` 改为按上限算的费用上限。
2. **兼容接口只认 `max_tokens`。** `openai_chat` 默认发送 `max_completion_tokens`，这个网关对它直接返回 403；改发 `max_tokens` 正常。YAML 早有 `max_tokens_field`，但配置接口不能设置。接口新增可选 `max_tokens_field`（只接受两个值），DeepSeek、智谱、本地网关预设默认 `max_tokens`。
3. **常驻服务里所有流式翻译崩溃（上一提交引入的回归）。** `HttpClient.post_lines` 用 `capture_inputs(None)` 包住整个流式生成器，跨 `yield` 持有 `ContextVar` 令牌；Starlette 在线程池里逐次 `next()` 同步生成器，每次在新的上下文副本里执行，结束时 `reset(token)` 抛 `ValueError`，界面显示“翻译时出现程序错误”。离线测试直接迭代生成器，没有覆盖这种执行方式。改为只在发送请求、收到响应头时停用留档（留档钩子只在这时触发），新增按“每次 `next()` 换一个上下文副本”复现的契约测试。
