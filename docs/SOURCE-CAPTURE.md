# 来源输入留档

生产来源调用在解析前保存原始输入。日常发现、添加论文、参考文献刷新和历史调研共用同一入口，使用本机 SQLite 和 BlobStore，不增加来源请求或模型费用。全文、PDF、模型、发布及独立的 `scripts/probe_sources.py` 网络探针不在此范围内。

本段提供可靠留档与内部只读查询接口。`litgleaner replay <来源> --since` 和离线解码、业务恢复尚未接通。旧 `FetchResult.raw` 缺少完整上下文，不能用作忠实重放依据。

## 保存内容与时序

每次调用先保存唯一采集凭据，包含来源实例名、完整有序查询、查询哈希、原游标和调用时间。游标的 `None`、空字符串、日期及版本号分别保留。正常组装的来源还保存适配器、生效选项、原显式选项集合、实际使用的联系邮箱和认证是否存在；认证值不会进入凭据。临时注入的未知来源不冒用同名旧来源配置，其配置标为空。

来源实际读取的日期逐次保存，保持来源使用的 UTC 日期与业务时钟之间的区别。HTTP 每跳响应（包括重定向、认证错误及限流错误）先读完、脱敏、写 blob 并登记索引，然后才检查状态或解析 JSON/XML。留档保存解压后的原字节和必要响应头，保留字符集，不再次应用压缩；认证和 Cookie 头不保存。已知密钥的原文、URL 编码及 JSON 转义形式会被清理。

文件来源在读完字节后、JSON 解析前留档。本地文库在原 SQLite 查询结果进入映射前记录 SQL、绑定参数和有序原始行，包括参与分页边界的额外一行。压缩流中断或字节编码无法安全脱敏时，只保留不完整响应元数据并停止该次调用，不能把省略的内容当作可重放输入。

每份输入使用独立压缩 blob，索引保存零基顺序、类型、字节数和 SHA-256。先写 blob 再登记索引，两步全部成功才继续。失败可能留下未被索引引用的 blob，该次来源结果不会继续进入业务采纳。索引只能连续追加，已结束凭据和已登记输入不能改写。

## 业务用途

每次操作有独立组标识，凭据保存操作开始前冻结的有序成员清单和当前成员编号。没有实际执行的成员不伪造空响应。

| 用途 | 冻结的关联与采纳规则 |
|---|---|
| 日常发现 | 原任务键（旧任务可能缺失）、原查询与游标；按本次来源实际返回范围采纳论文和准确被引关系 |
| 添加论文 | 真实收件箱 ID、类型、规范标识符、PDF 摘要和后备标题；来源按原顺序尝试，首个非空结果只采第一条 |
| 参考文献 | 主论文 ID、完整 DOI 和所选来源顺序；只登记引文，不创建响应中的候选论文 |
| 历史调研 | 预留计划 ID、完整 Topic 与限额、配置指纹、原种子、查询任务、本地日期与时区；内部续轮另存明确的 run_id/iteration，首次预览为空 |

调研来源返回后仍先按类别或扩展限额筛选、跨来源合并，再执行总候选上限。保存凭据不改变这些规则。一个组的成员清单可能含未执行调用或失败成员；本段没有业务提交凭据，也不证明整组业务已经完成。

## 状态与失败

`source_capture_attempt` 使用三个状态：

- `started`：凭据已创建，调用未正常结束；进程退出或结束状态写入失败时可能保持该状态。
- `returned`：来源方法已返回，保存条数、截断标记和返回游标，只说明来源调用结束。
- `raised`：来源调用或输入留档失败，只保存异常类名。

来源状态检查、JSON/XML 或条目映射失败，已经登记的输入仍可读取。后续业务事务回滚也保留凭据与输入。开始、输入或结束登记失败时，该次调用不会进入业务采纳，也不会推进在线游标。

内部只读入口是 `store.source_captures.get(id)`、`inputs(id)` 和 `list(source, since, limit=100, after=None)`。列表按凭据 ID 升序分页，`since` 按原开始时刻比较并处理时区；一次最多 1000 条。输入内容需经 BlobStore 读取、解压并核对索引摘要。尚无产品 HTTP 接口或 CLI。

离线重放后续须使用这些输入复用原来源解析器，严格核对请求顺序、参数和摘要，缺页时停止；按原用途恢复，并保持在线游标原值。它不会自动重绑已完成的收件箱、覆盖不可变调研预览或启动收费流程。
