# 拾穗架构设计

包名 `litgleaner`。本文档只描述要实现的功能和设计，是实现的依据；进度和实施顺序见 [ROADMAP.md](ROADMAP.md)，实测记录见 `docs/experiments/`。要改变这里的决策，先改本文档或新增 `docs/adr/` 记录，再改代码。

## 1. 目标与边界

**目标**：让科研新手也能做成三件事（[ADR 0009](adr/0009-survey-read-retain.md)）：

1. **全面调研一个课题**：研究者写下研究背景、研究内容和研究目标，系统起草检索式，做历史检索和引文扩展，给出阅读路线和课题地图，并说明覆盖到了什么程度（第 7.5 节）；之后每天从多个学术来源跟踪新文献，按研究画像筛选、评分、提炼，推送到领读器首页和可选的渠道（飞书等），接收者可以是研究者本人或 agent。
2. **快速读懂一篇文献**：任何论文（系统推荐的，或研究者自己添加的）都能在自带的领读器里打开，有导读、释义、全文翻译、提问和读后卡片（第 12 节）。
3. **沉淀自己的长期知识库**：研究者读完用自己的话回答引导问题，系统评价后沉淀进个人知识库；下一篇论文的导读按他已经掌握的知识来定制（第 12.7 节）。读过的论文、笔记和概念集中存放、可以检索、可以整体导出（第 12.8 节）。

本机 Zotero 作为可选同步。

**目标用户**：所有研究者，首要是研一和研零；研二、博士读新方向的论文时同样需要概念释义和全文翻译。首发面向中文读者，界面语言和阅读语言是配置项，不写死（第 15.6 节）。学生大多用 Windows。用户在自己的电脑上运行，先提供网页版（本机服务 + 浏览器），之后提供桌面安装包和手机端（第 15.5 节）；进阶用户也可以部署到服务器。模型调用走 API 提供方（推荐免费或低价模型，也支持 OpenAI 兼容的本地网关）；边读边问可以改走用户本机已有的 agent，不额外付费（[ADR 0005](adr/0005-local-agent-first.md)、[ADR 0008](adr/0008-agent-for-ask-only.md)）。项目自包含：推送、按钮回调、阅读、写入 Zotero 等用户功能都由拾穗自己实现，不依赖使用者本机的其他自动化平台。需求和证据见 [REQUIREMENTS.md](REQUIREMENTS.md)。

**解决的问题**：

| 研究者的痛点 | 系统的回应 |
|---|---|
| 不知道一个方向有哪些工作、读到什么程度算够 | 课题调研：历史检索加引文扩展，阅读路线、课题地图，每轮报告新增多少、覆盖到哪里 |
| 文献太多、怕漏，检索式难写，没人教 | 用自己的语言写研究描述，系统起草检索式并解释每个词，多来源跟踪 |
| 手里已经有论文（导师给的、自己下载的），工具却读不了 | 贴 DOI、链接或拖入 PDF 就能读，不要求先建研究画像 |
| AI 摘要会夸大结论，编造文献 | 评分、理由、回答都带原文引用和页码，代码校验引用存在；元数据从不经过模型 |
| 读完留不下，说不出和课题的关系 | 组会视角的读后卡片，推荐理由逐条对照研究目标 |
| 读得慢，术语不懂，越追引用越散 | 领读器：读前背景卡、术语就地释义、全文翻译与双语对照、边读边问、前置阅读指引 |
| 笔记散、找不回 | 批注和卡片集中存放，一个搜索框查全部，每条能跳回原文；跨论文对比表；个人数据可以整体导出 |
| 每篇都从零读起，学过的用不上 | 个人知识库：记录用户掌握的概念和他自己的表述；导读按掌握程度定制，用已知概念做类比；按间隔重复安排复习 |
| 入库的论文以后就不管了 | 论文间记忆：读新论文时提起文库里与它相关的论文（扩展、用了谁的方法、比较、矛盾、思路相近），附双方原文和用户当时写的笔记（第 12.9 节） |
| 存了不读，跟不上 | 待读队列、积压时减少推送、主题周报 |
| 写综述怕 AI 率和假引用 | 综述骨架和对比表，不代写正文；引用导出只用数据源给出的标识符 |
| 工具配不起来、不想付费 | 不配置就能打开论文、做笔记；第一次用到模型时才引导配置；推荐免费或低价模型，边读边问可以走本机 agent，显示花费和额度；开源免费 |

**不做**：绕过授权下载（Sci-Hub、代下载）、代写正文、内置受授权限制的期刊分区数据、引文图谱可视化、出版商网站爬取、公开的网页服务。

**必须容易变的东西**：

| 变化点 | 改动方式 | 不应该发生的事 |
|---|---|---|
| 增减信号源 | 加一个适配器和一段配置，或把 `enabled` 改成 `false` | 改流程代码 |
| 改评价指标 | 改一个 JSON 文件 | 改代码；新旧分数混在一起比较 |
| 切换或修改研究画像 | 改一个主题文件并执行 `activate` | 重新下载、重新解析已有文献 |
| 增减推送渠道 | 加一个发布适配器和路由配置 | 评分或选文代码感知渠道 |
| 换解析器（云端↔本地） | 换适配器 | 切分和评估代码感知 MinerU 格式 |
| 换翻译模型 | 改 `llm.yaml` 中 `translate` 任务的模型 | 领读器代码感知模型厂商 |
| 换界面语言或阅读语言 | 改 `app.yaml` 的 `language`；加界面语言是加一份消息表 | 提示词、组件、表字段里写死某种语言 |
| 换本机 agent 或模型 | 改 `llm.yaml` 的提供方或任务路由 | 流程代码感知具体 agent |
| 换文献管理软件 | 加 `ReferenceLibrary` 适配器 | 流程代码出现 Zotero 字段 |
| 换存储位置（本地↔对象存储） | 改配置 | 业务代码出现文件路径 |

## 2. 三条核心原则

1. **事实与判断分离。** 论文的元数据、全文、提取内容、译文是事实，全局只存一份。相关性、分数、是否推送是判断，按“主题 + 评价标准”分别存放。这是切换主题和修改指标不用重来的根本原因。
2. **一切派生物都带来源指纹。** 每个派生结果都记录“输入哈希 + 生产者版本”。配置变了，系统能算出哪些结果失效（`litgleaner stale`），而不是全量重跑，也不静默重跑。
3. **变化点走接口，其余保持简单。** 只给已知会有多种实现的地方定义接口，其他地方不做抽象（见第 16 节）。

## 3. 总体流程

```text
 配置: topics(研究画像) / rubrics / sources / channels / llm / retention
   │
   └─ topic draft：画像 + 种子论文（含 Zotero 分组）→ 起草检索式 → 用户确认
                          │
 三个入口，进入同一条事实层流程：
   课题调研（一次，有边界）：历史检索 + 引文扩展，逐轮报告覆盖度（第 7.5 节）
   日常跟踪（每天）：各信号源的增量
   添加论文（随时）：DOI、链接、PDF → inbox，不要求有研究画像（第 12.8 节）
                          │
 ┌──────────── 全局：事实层（每篇只做一次）──────────────┐
 │ discover → resolve → acquire → parse → extract        │
 │  发现       去重合并   取全文   归一化    提取事实与对比字段 │
 └──────────────────────────────────────────────────┘
        │ 新论文（先过本地关键词过滤）   ▲ 初筛通过才取全文
        ▼                              │
 ┌──────────── 按主题：判断层 ──────────────────────────┐
 │ triage ───────────────┘   assess → score → select    │
 │ 初筛相关性                 分维度评估+对照目标 算分 选文   │
 └──────────────────────────────────────────────────┘
                          │
 ┌──────────── 输出层 ──────────────────────────────────┐
 │ 领读器首页和课题页：推荐、阅读路线、课题地图              │
 │ Digest → 可见性投影 → 渲染 → 发布 → 飞书等渠道（人和 agent） │
 │ 周报：待读提醒 + 主题进展                               │
 │ 导出：方法对比表、引用（BibTeX / CSL-JSON）、个人数据      │
 └──────────────────────────────────────────────────┘
                          │
 ┌──────────── 领读与沉淀 ───────────────────────────────┐
 │ 卡片“去读” → 领读器：个性化导读、释义、全文翻译、提问、读后卡片 │
 │ 3 个引导问题 → 回答卡片 → 评价 → 知识库（概念、掌握程度）  │
 │   └─ 知识库反过来决定下一篇的导读和引导问题；到期概念进入复习 │
 │ 批注、卡片编辑 → annotation；阅读进度 → reading_state     │
 │ 可选：“加入 Zotero” → library：条目、笔记、PDF           │
 │ 可选：litgleaner mcp 给外部 agent 查画像、证据、相关论文    │
 └──────────────────────────────────────────────────┘
 审计：覆盖率、漏检、误杀抽查、渠道健康（横切全流程）
```

初筛通过后才取全文和解析，这是控制成本和存储的主要手段。

## 4. 模块与依赖规则

```text
litgleaner/
├─ config/
│  ├─ app.yaml  sources.yaml  channels.yaml  llm.yaml  retention.yaml
│  ├─ journals/<set>.yaml        # 期刊清单，可被多个主题引用
│  ├─ topics/<topic-id>.yaml     # 一个研究画像一个文件
│  └─ rubrics/<rubric-id>.json   # 评价指标，唯一来源
├─ prompts/                      # 提示词是文件，不写在代码里
├─ src/litgleaner/
│  ├─ domain/       # 模型与纯逻辑：Paper、Rubric 算分、切分器、去重、关键词过滤
│  ├─ ports/        # 接口，见下表
│  ├─ application/  # 各阶段、任务调度、选文、周报、导出、给 MCP 用的查询
│  ├─ adapters/     # 外部实现，每个外部系统一个包
│  │  ├─ common/    # 适配器共享：HTTP 客户端、PDF 下载、游标窗口、选项解析
│  │  ├─ sources/ fulltext/ parsers/ llm/ renderers/ blobstore/
│  │  ├─ feishu/    # 卡片推送 + 按钮回调
│  │  ├─ zotero/    # 收件箱信号源 + 全文来源 + 文献库写入与读取
│  │  └─ fakes/     # 测试和演示用的假实现
│  ├─ infra/        # 数据库、迁移、配置加载、钥匙串、应用数据目录
│  ├─ bootstrap.py  # 组装程序，含适配器注册表（显式字典）
│  ├─ service.py    # 常驻服务：组合网页后端、调度器、渠道监听、任务执行
│  ├─ server/       # 领读器的本地 HTTP 接口（只做协议适配）
│  ├─ cli.py  cli_library.py  cli_shared.py
│  └─ mcp_server.py # 只读 MCP 入口
├─ web/              # 领读器前端（TypeScript），构建产物随安装包发布
├─ packaging/        # 各操作系统的打包脚本和安装包配置
├─ tests/  unit/ contracts/ integration/ e2e/ architecture/ fixtures/
├─ data/             # 开发时的数据库、文件、归档（不进 git）；安装版放在系统应用数据目录
└─ docs/  REQUIREMENTS.md  ARCHITECTURE.md  ROADMAP.md  adr/  experiments/
```

| 接口（`ports/`） | 职责 | 典型实现 |
|---|---|---|
| `Source` | 按查询返回论文记录 | Crossref、OpenAlex、arXiv、PubMed、Zotero 收件箱 |
| `FullTextProvider` | 按标识符找 PDF | Zotero、arXiv、Unpaywall、Crossref TDM |
| `Parser` | PDF → `NormalizedDocument` | MinerU 云端、`pdf_text` |
| `LLM` | 结构化输出和流式文本调用 | Anthropic Messages、OpenAI Chat / Responses、Gemini、本机 agent（ACP） |
| `Renderer` / `Publisher` | 渲染与发送 | 飞书卡片 |
| `CardClick`（`ports/inbound.py`） | 渠道按钮回调的统一格式 | 飞书 |
| `ReferenceLibrary` | 写入条目、附件，读取分组和标签 | Zotero 本地 API |
| `ImageGenerator` | 分镜 → 动图（可选） | GPT Image |
| `SecretStore` | 读写密钥 | 系统钥匙串、环境变量 |
| `BlobStore` | 按 `blob://` 地址存取文件 | 本地目录、对象存储 |
| `Embedder` | 文本 → 向量（本地计算） | fastembed（ONNX Runtime） |
| `Store` | 数据库访问（只用来维持依赖方向） | SQLite |

**依赖方向只能向内**，由 `import-linter` 强制：

```text
入口：service（组合 server、调度、监听）；cli → cli_library → cli_shared；mcp_server
  → bootstrap : bootstrap_args → adapters | infra → application → ports → domain
```

- 入口层之间不互相依赖业务逻辑。`server/` 和 `mcp_server.py` 只做协议适配，查询和操作都调用 `application` 中的函数，和命令行共用同一套实现。
- `web/` 是独立的前端工程，只通过 `server/` 的 HTTP 接口取数据，不读数据库和文件。

- `domain` 不做任何 IO，不知道 MinerU、飞书、Zotero、SQLite 的存在。
- 适配器之间不能互相导入，也不能访问 `application` 和 `infra`；共享代码只能放 `adapters/common/`。
- 只有 `adapters/`、`bootstrap.py` 和配置里可以出现具体厂商名。`application`、`ports` 中出现厂商名（包括大模型厂商、本机 agent、飞书）视为缺陷。

## 5. 数据模型

存储用 SQLite（WAL 模式）+ SQLAlchemy Core + Alembic，表结构只通过迁移改变。

| 层 | 表 | 主键或唯一键 | 说明 |
|---|---|---|---|
| 事实 | `paper` | 内部 ULID | 标题、摘要、作者、期刊、日期 |
| 事实 | `paper_alias` | `(scheme, value)` | DOI、arXiv ID 等都映射到同一篇；只由信号源写入 |
| 事实 | `merge_log` | 自增 | 合并记录，支持撤销 |
| 事实 | `merge_candidate` | `(paper_a, paper_b)` | 模糊匹配到、等待人工确认的疑似重复 |
| 事实 | `sighting` | `(paper, source, query_hash)` | 谁在何时发现了它，覆盖率统计的基础 |
| 事实 | `source_cursor` | `(source, query_hash)` | 增量抓取水位 |
| 事实 | `citation` | `(citing_paper, position)` | 参考文献条目：原始文字、来源（信号源或解析结果）、对上的 `cited_paper`（对不上时为空）；正文中引用它的句子（`contexts`）、信号源给出的意图（`intents`：背景、方法、结果比较）和 `influential`，按来源原样记录。只记关系，不做图谱可视化 |
| 事实 | `paper_mention` | `(source_kind, source_id, paper)` | 用户笔记或论文正文中按 FTS5 匹配到的库内论文名、方法名的位置（第 12.9 节） |
| 事实 | `artifact` | `(sha256, kind)` | PDF、归一化文档、解析器原始输出、双语 PDF 等文件的索引、许可依据和保留期 |
| 事实 | `fulltext` | `paper` | 全文状态：`available`、`parsed`、`unavailable`、`failed` |
| 事实 | `extraction` | `(paper, input_hash, extractor_version)` | 结论、不足、创新点、方法、数据、指标、结果，均带证据 |
| 事实 | `translation` | `(unit, source_hash, target_lang, glossary_hash, translator_version)` | `unit` 为 `block`（段落及其句对译文）；导出的译文 PDF 只是由这些译文生成的文件，存为 `artifact` |
| 事实 | `explanation` | `(paper, kind, input_hash, producer_version)` | 领读器生成的背景卡、章节要点、前置阅读指引，带证据 |
| 判断 | `topic_state` | `topic` | 是否启用、当前画像哈希、从何时开始初筛 |
| 判断 | `triage` | `(paper, topic, topic_hash)` | 初筛结果和理由，提示词版本和模型只作记录 |
| 判断 | `assessment` | `(paper, topic, topic_hash, semantic_hash, input_hash)` | 各维度等级、证据、目标对照，由 LLM 产生 |
| 判断 | `score` | `(assessment, policy_hash)` | 最终分、等级、是否临时、是否有无法判断的维度，由代码算出 |
| 判断 | `rubric_snapshot` | `hash` | 首次使用时保存指标全文，历史分数可追溯 |
| 判断 | `topic_map` | `(topic, topic_hash, input_hash, producer_version)` | 课题地图：子方向的名称、说明和所含论文，由 LLM 任务 `map` 显式生成（第 7.5 节） |
| 判断 | `topic_outline` | `(topic, topic_hash, input_hash, producer_version)` | 已读综述骨架：短分组、覆盖缺口候选与生成时的对比表、来源引用附件，由 `outline` 显式生成，只追加保存（第 14 节） |
| 输出 | `digest` / `digest_item` | ULID / `(digest, position)` | 一次推送的不可变内容 |
| 输出 | `delivery` | `(digest, channel)` | 发送状态，保证不重复推送 |
| 反馈 | `feedback` | ULID；渠道事件号 `external_id` 唯一 | 只追加：加入文献库、不感兴趣、有用、需要全文；关系反馈另带 `relation_id` 与动作数据 |
| 反馈 | `library_entry` | `(paper, library)` | 已写进文献库的条目，有这一行就不再写 |
| 反馈 | `reading_state` | `paper` | 待读、在读（含读到的位置）、已读、放弃；来自领读器、渠道反馈和 Zotero 标签 |
| 用户 | `annotation` | ULID | 高亮、批注、读后卡片的用户修改；记录页码、`bbox` 和原文片段，不依赖 `chunk_id` |
| 用户 | `qa_message` | ULID | 边读边问的问答记录，回答附引用和核验结果 |
| 知识 | `concept` | ULID | 全局概念：规范名用原文术语；课题只是标签（第 12.7 节） |
| 知识 | `concept_alias` | `(normalized_name)` | 别名和各语言译名（带语言标记）到概念的映射，用于按名称匹配；课题术语表条目也经它关联到概念 |
| 知识 | `concept_occurrence` | `(concept, paper)` | 概念在哪篇论文出现：作用（核心、前置、提到）、定义原文、页码、`bbox` |
| 知识 | `concept_merge_candidate` | `(concept_a, concept_b)` | 模型提议的疑似同一概念，等用户确认 |
| 事实 | `memory_admission` | 自增序号；`paper` 唯一 | 首次入库的冻结配置与旧库基线，退出再入不重开事件（第 12.9 节） |
| 判断 | `relate_batch` | `(paper, input_hash, producer_version)` | 关系核实的冻结消息、来源、范围、费用 scope、输出与警告；空结果也保存（第 12.9 节） |
| 判断 | `paper_relation` | `(paper_a, paper_b, kind, input_hash, producer_version)` | 经 `relate` 核实的论文关系，附双方原文引用；状态 `valid / superseded / rejected_by_user`，被推翻时记录 `superseded_by`，不删除（第 12.9 节） |
| 判断 | `paper_embedding` | `(paper, input_hash, embedder_version)` | 本地向量（float32 二进制），只用于产生候选和检索排序（第 12.9 节） |
| 用户 | `answer_card` | ULID；修订只追加 | 用户对引导问题的回答：论文、问题、针对的概念、回答原文 |
| 用户 | `mastery_event` | ULID | 只追加：回答评价、复习自评、用户修改掌握程度 |
| 判断 | `answer_evaluation` | `(answer_card, input_hash, evaluator_version)` | 系统对回答的评价：每个概念对、漏、偏，附原文引用和参考答案 |
| 判断 | `concept_link` | `(concept_a, concept_b, kind)` | 前置、相似、对比关系，附依据和生产者版本，用户可以确认或删除 |
| 判断 | `mastery_state` | `(concept, policy_hash)` | 由 `mastery_event` 经纯函数算出的掌握程度和下次复习时间，可以随时重算 |
| 反馈 | `inbox` | ULID | 用户添加的论文（DOI、链接、上传的 PDF）和邮件提醒，待处理 |
| 审计 | `miss_log` | ULID | 漏检记录及原因 |
| 运行 | `survey_round` | `(topic, round)` | 只追加：一轮调研的查询范围、候选数、新增数、通过初筛数、费用 |
| 运行 | `job` | 幂等键 | 任务队列、重试、推迟、死信 |
| 运行 | `llm_call` | 自增 | 任务、模型、token、费用，用于预算控制 |

**去重规则**：

- 标识符完全相同才自动合并，新标识符挂到已有论文上。两篇已有论文互相冲突时只记录、不自动合并。
- 标题加作者的模糊匹配：高置信时合并，否则写入 `merge_candidate`，由 `litgleaner merge list / accept / reject` 处理。所有合并都写 `merge_log`，可以撤销。
- **预印本和正式版是同一篇论文。** 信号源同时给出两个标识符（如 OpenAlex、Semantic Scholar 的外部编号，Crossref 的 `is-preprint-of` 关系）时自动关联，元数据以正式版为准。正式版出现不会自动重取全文、重新评估；`stale` 报告会列出这些论文，由用户显式 `reassess`。

## 6. 信号源与全文

### 6.1 接口

适配器声明自己支持哪些查询，由流程规划实际调用，适配器不认识“主题”这个概念：

```python
Query = JournalWatch | KeywordSearch | CitationWatch | ReferenceList | AuthorWatch | InboxDrain | IdentifierLookup

class Source(Protocol):
    name: str
    capabilities: frozenset[type]   # 支持的查询类型

    def fetch(self, query: Query, cursor: Cursor | None) -> FetchResult: ...
    # FetchResult = records、next_cursor、warnings
    # 错误类型统一为 RateLimited / AuthFailed / SchemaChanged / Transient
```

| 能力 | 典型适配器 |
|---|---|
| `JournalWatch` | Crossref |
| `KeywordSearch` | arXiv、OpenAlex、PubMed、Europe PMC、CORE |
| `CitationWatch`（谁引用了它）、`ReferenceList`（它引用了谁）、`AuthorWatch` | Semantic Scholar、OpenAlex |
| `InboxDrain` | Zotero 新加入的条目、邮件提醒 |
| `IdentifierLookup`（按 DOI 或 arXiv 编号查一篇） | Crossref、arXiv；用户添加论文时使用（第 12.8 节），一次性查询，不用游标 |

`ReferenceList` 返回的参考文献，以及解析全文得到的参考文献条目，都写入 `citation`；按第 5 节的去重规则对到已有论文上，对不上的保留原始文字。

`CitationWatch` 返回候选论文时，同时携带来源已核实的引用关系：引用端和被引端的精确标识符、来源内序号、原始证据及来源实际提供的引用句、意图和重要性。多种子查询只保存来源明确给出的双端关系，不把所有返回论文与所有种子交叉连边。关系只随本次已采纳的引用者记录摄取；引用端无法唯一精确关联时跳过关系，被引端尚未入库时保留标识符供后续精确关联。候选论文、发现记录、引用关系和游标在同一事务中保存，原始响应先归档。关系指纹包含来源、准确双端和证据内容，不包含抓取日期、查询顺序或分页位置；重叠窗口和重试不重复登记，来源证据变化时追加版本。该摄取不增加来源请求、模型调用或初筛范围。

### 6.2 配置

```yaml
sources:
  crossref:
    adapter: crossref
    enabled: true
    options: { rate_limit_per_sec: 1 }
  core:
    adapter: core
    enabled: false
    credentials_env: [CORE_API_KEY]
  semantic_scholar:
    adapter: semantic_scholar
    enabled: true
    optional_env: [SEMANTIC_SCHOLAR_API_KEY]
```

### 6.3 规则

- **加来源**：写一个适配器，在 `bootstrap.py` 的注册表里加一行，加配置，录制响应到 `tests/fixtures/<来源>/`，通过 `tests/contracts/` 的统一测试。
- **减来源**：`enabled: false`。历史 `sighting` 保留，审计时仍能看到它的贡献。
- **原始响应先落盘，再解析**。解析逻辑修好后用 `litgleaner replay <来源> --since` 从落盘数据重放，不必重新抓取。
- 限速、错误分类、密钥脱敏和原始留档由共享 HTTP 客户端（`adapters/common/http.py`）负责，适配器不各写一套；重试和退避由任务调度负责。
- 游标统一是 ISO 日期，每次与上次窗口重叠几天以接住晚入库的记录（`adapters/common/window.py`）。Zotero 例外：本地模式用加入时间，Web 模式用库版本号。
- 联系邮箱从 `LITGLEANER_CONTACT_EMAIL` 读取，所有来源共用；可选 key 在配置里用 `optional_env` 声明，缺失时 `doctor` 只警告。
- 同一个 API 的元数据发现和全文获取是两个独立适配器，分别实现 `Source` 和 `FullTextProvider`。
- 各来源的能力和已知限制见 [SOURCES.md](SOURCES.md)。

### 6.4 全文获取

`FullTextProvider` 按配置顺序依次尝试：用户自己的 Zotero → 预印本（arXiv、PMC 开放子集）→ 开放获取聚合（Unpaywall、OpenAlex、Semantic Scholar、CORE）→ 出版商在 Crossref 登记的文本挖掘链接（订阅文章需机构网络）→ 手动投喂 → 仅摘要。

- 单个来源出错时继续尝试下一个；全部没拿到且有错误时交给调度重试，不标记为“没有全文”。
- 第三方 PDF 链接统一由 `adapters/common/download.py` 下载：每一跳都检查不是内网地址，限制大小和总耗时，校验 PDF 文件头。
- 每个 `artifact` 记录 `license_basis`（`open` / `subscribed` / `user_supplied`），决定保留策略，并保证这些文件不会进入公开渠道。

## 7. 研究画像

### 7.1 文件

一个研究画像一个文件，允许多个画像同时运行。文件只存定义，是否启用记录在数据库（`topic_state`），由命令切换。

```yaml
id: example-topic
name: 示例课题
background: >
  研究背景：领域现状，要解决的问题为什么重要。
content: >
  研究内容：打算研究什么、用什么方法、关心什么、不关心什么。
goals:
  - id: g1
    text: 研究目标一
  - id: g2
    text: 研究目标二
query:                          # 由 topic draft 起草，用户确认后写入
  include: ["keyword a", "keyword b"]
  synonyms:
    keyword a: ["别名 1", "别名 2"]
  exclude: ["不相关的词"]
journal_sets: [core]
seeds:
  dois: ["10.1109/EXAMPLE.2026.0000001"]
  authors: []
  zotero_collection: "课题/核心文献"   # 本机 Zotero 分组，作为种子论文
rubric: default
public: false                   # 是否允许出现在公开渠道
```

- `topic_hash` 覆盖影响判断的字段：`background`、`content`、`goals`、`query`。改名称或公开设置不会让判断失效。
- 种子论文同时用于起草检索式、引文追踪和校准集。
- 背景、内容、目标用研究者自己的语言写；检索式由系统生成英文，术语表是原文术语与阅读语言的对照（第 15.6 节）。
- 安装版的研究画像存放在应用数据目录，通过领读器的设置页编辑；文件格式不变，命令行和网页编辑的是同一份文件。

**课题术语表**：每个研究画像配一个 `<topic-id>.glossary.yaml`，文件注明目标语言，每条包含原文术语、目标语言的译名、一句话释义和出处。

- 由 `topic draft` 根据画像和种子论文起草，用户在领读器里可以随时增删改。
- 翻译和就地释义必须使用术语表中的译名；术语表内容的哈希（`glossary_hash`）计入译文指纹。
- 术语表变化后旧译文不自动重译，打开论文时提示“术语表已更新”，由用户选择是否重译。

**期刊分级**：`journals/<set>.yaml` 的每本期刊可以带 `tier` 标签（如“中科院一区”“CCF-A”）。

- 分级数据由用户导入：导师或学校给的 CSV，在设置页导入。项目不内置受授权限制的分区数据。
- 卡片显示期刊分级，路由可以按分级过滤。

### 7.2 起草检索式

研究者通常不擅长写检索式，所以由系统起草、研究者确认：

```bash
litgleaner topic draft example-topic    # 显式调用 LLM，花少量费用
```

- 输入：背景、内容、目标，以及种子论文的标题和摘要（DOI 列表 + Zotero 分组，后者通过 `ReferenceLibrary` 读取）。
- 输出写到 `<id>.draft.yaml`，同时显示和当前文件的差异：
  - 建议的 `include`、`synonyms`、`exclude`，以及术语表草稿；
  - 每个检索词都附**选择理由**（对应哪段描述、为什么用这个学科表述），兼作检索方法的教学；
  - 每个检索词预估能搜到多少篇（向 OpenAlex 查询计数，不花模型费用），帮助判断太宽或太窄；
  - 根据种子论文的期刊统计（代码统计，不经 LLM）给出期刊集建议。
- 草稿不会自动生效。研究者在领读器设置页或文件里确认合并后，`topic activate` 才使用新定义。

新研究画像第一次启用时，领读器引导研究者发起一次课题调研（第 7.5 节）；原先的入门清单并入调研结果里的阅读路线。

### 7.3 切换与回填

- 画像变化后，**只有新发现的论文按新定义处理**，运行时提示执行 `backfill`。旧定义下的判断不再参与排序，但不会自动花钱重筛历史。
- 新启用的画像同样只处理之后发现的论文，历史论文必须显式回填：

```bash
litgleaner topic activate example-topic
litgleaner topic backfill example-topic --since 2024-01-01             # 预览数量和费用
litgleaner topic backfill example-topic --since 2024-01-01 --execute   # 确认执行
```

- `backfill` 先用库内已有元数据重新初筛（只花初筛费用），再向支持历史查询的信号源补查。已有的 PDF、解析结果和提取内容直接复用。暂停的画像不消耗资源，数据全部保留。

### 7.4 初筛前的本地过滤

`domain` 中的纯函数先按 `include`、`synonyms`、`exclude` 在标题和摘要上做关键词过滤，命中排除词或完全不相关的论文不进入 LLM 初筛，结果和原因照样写入 `triage`（模型记为 `rule`）。期刊监控类来源无法按关键词查询，这一步是控制初筛费用的主要手段。

### 7.5 课题调研

日常跟踪只处理新发现的论文。研究者刚进入一个方向时，先要知道这个方向已经有哪些工作、该从哪篇读起，所以研究画像启用后先做一次有边界的调研，再转入日常跟踪（[ADR 0009](adr/0009-survey-read-retain.md)）。

```bash
litgleaner topic survey example-topic             # 预览：每一步预计多少篇、多少费用
litgleaner topic survey example-topic --execute   # 确认执行
```

领读器的课题页提供同一个操作，命令行和网页调用 `application` 中的同一个函数。

**一轮调研的步骤**：

| 步骤 | 做什么 | 费用 |
|---|---|---|
| 历史检索 | 按检索式向支持历史查询的来源取综述、高被引论文和近两年的论文，每类有篇数上限 | 无模型费用 |
| 引文扩展 | 从种子论文和当前高分论文出发，取它们的参考文献（`ReferenceList`）和引用它们的论文（`CitationWatch`）；被多篇论文同时引用的排在前面 | 无模型费用 |
| 过滤与初筛 | 先过本地关键词过滤（第 7.4 节），再初筛 | 初筛费用，执行前预览 |
| 取全文与评估 | 只对初筛通过的论文，走正常流程 | 同日常流程，受预算限制 |

- 默认两轮：第一轮是历史检索加种子论文的引文扩展，第二轮从第一轮的高分论文再扩展一次。每轮的候选数上限写在配置里。
- 每轮结束写一条 `survey_round`。**覆盖度**按“本轮候选中以前没见过、且通过初筛的论文所占比例”计算：低于阈值（默认 5%）时提示“再扩展一轮找不到多少新论文”，否则建议再做一轮，由研究者决定。
- 覆盖度只说明在已启用的来源里，顺着检索式和引文还能找到多少。课题页同时列出检索了哪些来源、各自贡献多少、哪些范围没有覆盖（没有接口的数据库、检索式之外的语言），不把结果说成“全了”。
- `topic backfill`（第 7.3 节）保留为底层命令：调研在它之上增加引文扩展、分轮和覆盖度。画像改动后重新调研，同样先预览。

**调研结果**在课题页呈现（第 12.8 节）：

- **阅读路线**：按“综述 → 奠基论文 → 代表作 → 最新进展”分组排序。综述按来源元数据标明的类型识别；奠基论文是被本课题通过初筛的论文引用最多的那些（由 `citation` 统计）；代表作按阅读价值分；最新进展取近两年。排序由 `domain` 的纯函数完成，不经模型；每篇附推荐理由（`goal_links`）和在本课题内被引用的次数。
- **课题地图**：LLM 任务 `map` 把通过初筛的论文分成 5–8 个子方向，每个有名称、一句说明和所含论文。输入是标题、摘要和已有的提取结果；输出里的论文编号由代码校验存在于输入，不存在的丢弃；没有归入任何子方向的论文列为“未分组”。结果写入 `topic_map`。库里新增论文后不自动重新生成，课题页提示“有 N 篇新论文未归入”。
- **对比表和综述骨架**（第 14 节）。

## 8. 评价指标

### 8.1 唯一指标

全系统只有一个排序和选文依据：`reading_value`（阅读价值分，0～100）。各维度只是它的组成部分，不单独用于选文。`config/rubrics/<id>.json` 是唯一来源，代码和提示词里都不写死维度或权重。

```json
{
  "schema_version": 1,
  "id": "default",
  "metric": { "key": "reading_value", "label": "阅读价值分", "range": [0, 100] },
  "levels": { "min": 0, "max": 5 },
  "dimensions": [
    {
      "key": "relevance",
      "label": "相关性",
      "weight": 35,
      "requires_fulltext": false,
      "question": "这篇论文和当前研究画像的目标有多接近？",
      "anchors": { "0": "完全无关", "3": "同领域，可借鉴", "5": "直接解决某个研究目标" }
    },
    {
      "key": "novelty",
      "label": "创新性",
      "weight": 25,
      "requires_fulltext": false,
      "question": "是否提出了新方法或新发现？",
      "anchors": { "0": "重复已有工作", "3": "对已有方法有实质改进", "5": "提出全新思路并显著突破" }
    },
    {
      "key": "evidence",
      "label": "证据可信度",
      "weight": 20,
      "requires_fulltext": true,
      "question": "实验设计、基线对比和数据是否支撑其结论？",
      "anchors": { "0": "没有实证", "3": "有基线对比但存在明显局限", "5": "设计严谨且结果可复现" }
    },
    {
      "key": "reusability",
      "label": "可复用性",
      "weight": 20,
      "requires_fulltext": true,
      "question": "方法、代码或数据能否用到我的研究中？",
      "anchors": { "0": "无法复用", "3": "方法可借鉴但需较多适配", "5": "代码和数据公开，可以直接使用" }
    }
  ],
  "gates": [{ "dimension": "relevance", "min_level": 2 }],
  "tiers": [
    { "key": "must_read", "label": "必读", "min_score": 80 },
    { "key": "digest", "label": "周报", "min_score": 60 },
    { "key": "drop", "label": "不推送", "min_score": 0 }
  ],
  "provisional": { "tier": "need_fulltext", "min_score": 60 }
}
```

### 8.2 计算规则

由 `domain/rubric.py` 的纯函数完成，**LLM 只给等级和证据，不给总分**：

```text
reading_value = round( Σ(weight × level / levels.max) / Σ(weight) × 100 )   # 只累加有等级的维度
```

维度等级为空有两种原因，处理方式不同：

| 情况 | 判定 | 处理 |
|---|---|---|
| **缺全文**：只有摘要，`requires_fulltext` 的维度 | 代码按全文状态置空，不看模型回答 | 结果标记为临时分 `provisional`，不能进入 `must_read`；达到 `provisional.min_score` 时归入 `need_fulltext`，推送时附“需要全文”操作 |
| **无法判断**：有输入但模型给不出等级 | 模型返回空 | 只按可判断维度计算，不限制等级，结果标记 `undetermined` 并在卡片上注明哪些维度无法判断 |

- **门槛**：门槛维度低于 `min_level` 时直接归入兜底等级（`drop`）。门槛维度为空时同样不放行，并进入误杀抽查。
- 启动时校验：权重总和为 100、等级和门槛合法、`tiers` 完整、`provisional.tier` 不与普通等级重名。校验失败直接退出。
- 门槛维度不能是 `requires_fulltext` 维度：只读摘要时它必然为空，所有摘要论文都会被门槛挡掉，进不了 `need_fulltext`。
- 算分规则本身（上面的公式和处理方式）有版本号，计入 `policy_hash`。规则变化后已有分数按新规则零费用重算。

### 8.3 修改指标的两种情况

直接改 JSON，git 记录历史，系统保存快照。系统用两个哈希判断影响范围：

| 修改内容 | 变化的哈希 | 处理方式 | 费用 |
|---|---|---|---|
| 权重、门槛、等级线 | `policy_hash` | `litgleaner rubric rescore`，用已有维度等级重算 | 零 LLM 费用 |
| 增删维度、问题、锚点 | `semantic_hash` | `litgleaner rubric reassess <主题>` 先预览，加 `--execute` 按范围重评 | 有 LLM 费用 |

只有 `semantic_hash` 和 `policy_hash` 都相同的分数才能直接比较。选文只使用当前画像和当前指标下的分数，没有重算的旧分数不参与排序。

**任何配置修改都不会静默产生费用**：改维度定义、研究画像、提示词或模型后，系统不会自动重评已有论文，新论文才用新配置。`litgleaner stale` 列出哪些派生结果的指纹与当前配置不一致（零费用），由用户决定是否重做。已归档的论文不会因此被删除，归档文件保留旧结果并标记 `stale: true`。

`litgleaner rubric eval` 用校准集（种子论文）和反馈数据比较修改前后的效果（前 K 篇命中率、必读漏选率）。改指标先看这个结果，不凭感觉。

### 8.4 对照研究目标

评估时模型同时输出 `goal_links`：这篇论文对应哪个研究目标（`goals[].id`）、可以借鉴什么、依据的原文引用和页码。

- `goal_links` 只用于推荐理由和周报，**不参与算分**；分数仍只由维度等级决定。
- 引用不在原文中的条目标记 `unverified`，推送时不显示为“作者原话”。
- 引用了不存在的目标 id 的条目丢弃。

## 9. 文献处理：解析与切分

### 9.1 防腐层：统一文档格式

不同解析器、不同版本的输出结构不同，所以每个解析适配器都必须转换成 `NormalizedDocument`。下游只认这个格式：

```python
class Block:            # 不可变
    kind: Literal["heading", "text", "table", "equation", "figure", "code", "reference"]
    text: str
    page: int
    bbox: tuple[int, int, int, int] | None   # 页面归一化坐标 0–1000，原点在左上，(x0, y0, x1, y1)；用于从 PDF 恢复高清图、定位证据和叠加高亮
    caption: str | None

class NormalizedDocument:
    schema_version: int
    source_pdf_sha256: str
    parser_id: str            # 如 mineru_cloud@vlm
    blocks: tuple[Block, ...]
    front_matter: tuple[str, ...]   # 页脚中的作者机构、基金信息，不进入正文块
    quality: Literal["ok", "degraded"]
```

默认使用 MinerU 精准 API 的 `vlm` 模型（适配器 `mineru_cloud`）。不使用只返回 Markdown 的轻量接口，因为它没有页码、坐标和结构信息，生成不了上面的格式。不耗额度的备选是 `pdf_text`，英文论文效果接近，中文期刊明显较差（对比见 [parser-comparison](experiments/2026-11-05-parser-comparison.md)）。

**MinerU 字段映射**（`*_content_list.json`）：

| MinerU `type` | 关键字段 | 归一化处理 |
|---|---|---|
| `text` | `text`、`text_level`、`bbox`、`page_idx` | `text_level` 非空则为 heading，否则为 text |
| `equation` | `text`（LaTeX）、`text_format` | equation |
| `table` | `table_body`（HTML）、`table_caption`、`table_footnote` | table |
| `chart`、`image` | `img_path`、`*_caption`、`*_footnote`、`content` | figure |
| `code` | `code_body`、`code_caption`、`sub_type` | code |
| `ref_text` | `text` | reference |
| `page_footnote` | `text` | 写入 `front_matter` |
| `page_number`、`aside_text`、`header`、`footer` | `text` | 丢弃 |

未知类型不能静默丢弃：保留文字并把文档标记为 `degraded`。

### 9.2 切分规则

切分器是 `domain/chunker.py` 的纯函数，相同输入和版本得到完全相同的结果。

```text
NormalizedDocument
  → 按标题划分章节，并归入标准类型：
    abstract / introduction / method / results / discussion /
    conclusion / limitation / references / acknowledgment / other
  → 每个章节内按“段落 → 句子”逐级切分
```

| 规则 | 取值 | 原因 |
|---|---|---|
| 目标大小 | 约 800 token，上限 1200 | 足够容纳一个完整论点 |
| 切分边界 | 优先章节和段落，迫不得已才按句子 | 保持语义完整 |
| 重叠 | 默认不重叠；长段落被迫切开时重叠 1 句 | 减少冗余存储和 token |
| 表格、图、代码 | 独立成块，不拆开 | 拆开后失去意义 |
| 公式 | 不拆开，但留在上下文的块中 | 公式离开前后文就看不懂 |
| 参考文献 | 单独解析成结构化列表，不进入正文块 | 用于引文追踪，不浪费 token |
| 致谢、页眉页脚 | 丢弃 | 对评估无用 |

每个 chunk 的字段：`chunk_id`、`section_type`、`section_path`、`page_start`、`page_end`、`token_count`、`text`。参数放在配置里，修改后 `chunker_version` 随之变化，并计入提取和评估的输入指纹。

**标题识别不到时不能静默出错**：先用规则匹配，缺少结论章节时取参考文献前的最后两节并标记 `degraded`。低质量解析结果会反映在推送内容里。

切分器必须处理以下情况，并有对应测试：

- 标题可能带空格：小型大写拆成 `I NTRODUCTION`，中文标题写成 `5 总 结`、`参　考　文　献`，分类时也检查去掉空格的写法。
- 中文期刊的双语前置部分：页首英文标题不算正文开始；`Abstract In ...`（没有破折号）、`Key words`、`摘　要`、`结束语` 都要识别。
- 参考文献后可能有作者简介和照片：解析器标出了参考文献条目时只用这些条目。
- `text_level` 不能表示层级：章节嵌套靠编号（`I.`、`A.`、`1.1`）推断。
- 摘要不是标题：IEEE 的 `Abstract—...`、`Index Terms—...` 是普通段落，要按段首模式识别。
- 论文标题以元数据为准，解析结果里的 1 级标题只作校验。
- 图注关联不可靠：评估不能依赖“图和图注一定对应”。
- 解析文本不等于原文：引用校验只能证明“引文存在于解析文本”，推送中的公式和关键数字提示以原文为准。

### 9.3 切分的用途

1. **节省 LLM 费用**：提取和评估只读摘要、引言、方法概述、结果、讨论、结论，并设总 token 上限。
2. **证据可追溯**：提取和评估结果记录原文引用和页码，代码校验引用确实存在于原文；校验失败标记为 `unverified`，不当作事实。证据保存引用原文和页码，不只存 `chunk_id`，切分规则升级后旧证据依然有效。
3. **文库检索**：归档论文的 chunk 写入 SQLite FTS5，供 MCP 和周报检索。

### 9.4 提取内容

`extraction` 与主题无关，每篇只做一次，切换主题时直接复用：

| 字段 | 内容 | 证据 |
|---|---|---|
| `summary` | 一句话概括（模型概括） | — |
| `problem` | 要解决的问题 | 原文引用 + 页码 |
| `prior_gap` | 已有方法的不足（作者的说法） | 原文引用 + 页码 |
| `approach` | 本文做法 | 原文引用 + 页码 |
| `claims` | 作者的主要结论 | 原文引用 + 页码，必填 |
| `innovation` | 创新点（模型概括） | 可选引用 |
| `limitations` | 不足，区分作者自述和模型推断 | 作者自述必须有引用 |
| `method` | 方法类别和要点 | 引用 + 页码 |
| `datasets` | 使用的数据集 | 引用 + 页码 |
| `metrics` / `results` | 指标、取值、实验设置 | 引用 + 页码 |
| `code_data` | 代码和数据是否公开、链接 | 链接来自原文时才保留 |
| `questions` | 组会上可能被问到的 3 个问题及回答要点 | 回答要点引用原文 |
| `highlights` | 原文中代表目标、创新、方法、结果的句子 | 原文片段 + 页码 + `bbox`，供领读器分色高亮 |
| `key_concepts` | 读懂本文需要的关键概念：名称、在本文中的作用（核心、前置、提到）、论文自己的定义 | 定义原文 + 页码；论文没有定义时标明，供知识库登记概念（第 12.7 节） |

提取字段变化会改变 `extractor_version`，旧提取结果不会自动重做，由 `stale` 报告列出。

**读后卡片**是 `extraction`（与主题无关）、`assessment.goal_links`（和我课题的关系）以及用户在 `annotation` 中的修改合成的视图，不单独存一份。用户修改不覆盖模型结果，两者都保留，并标明哪部分是用户写的。

## 10. 存储

### 10.1 放在哪里

| 内容 | 位置 | 能否重建 |
|---|---|---|
| 配置、提示词、代码 | 仓库 | — |
| 数据库 | `<数据目录>/db/litgleaner.db` | 否，**最重要的数据**，包括批注、问答、反馈、阅读状态等无法重建的记录 |
| JSON 归档 | `<数据目录>/archive/papers/YYYY/MM/<paper_id>.json` | 能，由数据库导出 |

`<数据目录>`：开发时是仓库下的 `data/`；安装版是系统的应用数据目录（macOS 为 `~/Library/Application Support/litgleaner`，Windows 为 `%APPDATA%\litgleaner`，Linux 为 `$XDG_DATA_HOME/litgleaner`），可在设置中更改。下文 `blob://` 地址都相对于它。
| 原始 API 响应 | `blob://raw/<source>/YYYY/MM/DD.jsonl.zst` | 大多能，但会过期 |
| PDF | `blob://pdf/ab/cd/<sha256>.pdf` | 开放文献能，付费文献不一定 |
| 双语 PDF（可选导出） | `blob://translated/ab/cd/<sha256>.<lang>.pdf` | 能，但消耗翻译费用 |
| 段落译文、背景卡等讲解 | 数据库 `translation`、`explanation` | 能，但消耗模型费用 |
| 归一化文档 | `blob://doc/ab/cd/<sha256>.<parser>.json.zst` | 能，但消耗解析额度 |
| 解析器原始输出 | `blob://parser_raw/<sha256>.content_list.json.zst`（只留这一个文件） | 能 |
| chunk | 不单独存，需要时计算；归档论文写入 FTS | 能，纯函数 |

**真相只有一处**：SQLite 是运行时的唯一真相。JSON 归档由 `archive` 阶段导出，不手改、不反向写入、不进 git。业务代码只使用 `blob://` 地址和 `BlobStore` 接口，因此可以把文件从本地迁到对象存储而不改业务代码。

### 10.2 如何减少存储

1. **漏斗**：初筛没通过的论文不下载 PDF，只存元数据和摘要。这是效果最大的一项。
2. **内容寻址**：文件以 SHA-256 命名，相同 PDF 只存一份。
3. **压缩**：文本和 JSON 用 zstd 压缩。
4. **解析后瘦身**：解析器结果包解压后立即丢弃 `layout.json`、`model.json`、`full.html`、`full.tex`、`full.docx`、`origin.pdf` 和缩略图，`content_list.json` 只留 30 天；需要配图时按 `bbox` 从 PDF 恢复高清原图。
5. **按价值分级保留**（`retention.yaml`）：

| 论文状态 | 元数据和摘要 | 提取结果 | 归一化文档 | PDF 与双语 PDF |
|---|---|---|---|---|
| 初筛淘汰 | 永久 | 无 | 无 | 从未下载 |
| 深评 `drop` | 永久 | 永久 | 90 天 | 30 天 |
| 深评 `digest` | 永久 | 永久 | 永久 | 180 天 |
| `must_read` 或已加入文献库 | 永久 | 永久 | 永久 | 永久 |
| 用户上传或付费获取且未归档 | 永久 | 永久 | 90 天 | 90 天 |

元数据和摘要永久保留，切换主题时才有东西可以重新初筛；提取结果体积很小，也永久保留。清理由 `litgleaner gc --dry-run` 预览后执行，只有相关 `job` 全部完成后才能删除对应文件。`litgleaner stats` 报告条数和文件占用。

### 10.3 备份

`litgleaner backup` 用 `VACUUM INTO` 生成数据库快照，按配置保留若干份，可上传对象存储；`litgleaner restore --check <快照>` 在临时目录还原并校验迁移版本和行数，用于定期恢复演练。

- 安装版默认每天自动备份到数据目录下的 `backups/`，保留 14 份。
- 每次升级执行数据库迁移前，必须先自动备份一次。

## 11. 推送

### 11.1 分层

```text
Selector（按路由选文）
  → Digest（不可变内容，存库）
  → 可见性投影（private / public）
  → Renderer（飞书卡片 / 纯文本 / …）
  → Publisher（只负责发送）
  → delivery（记录状态，失败重试，不重复发送）
```

选文和内容与渠道完全无关，一份 Digest 可以发到多个渠道。研究者本人和 agent 通过同一套渠道接收：卡片带论文编号和 DOI，agent 可以凭编号通过 MCP（第 12.6 节）取完整内容。

```python
class Publisher(Protocol):
    name: str
    visibility: Literal["private", "public"]

    def publish(self, rendered: Rendered) -> Receipt: ...
```

### 11.2 配置：渠道和路由分开

```yaml
channels:
  feishu_me:
    adapter: feishu
    renderer: feishu_card
    visibility: private
    credentials_env: [FEISHU_APP_ID, FEISHU_APP_SECRET]
    options: { receive_id: ou_xxx, receive_id_type: open_id }

routes:
  - { id: daily-me, topic: "*", channel: feishu_me, schedule: "daily 08:30", tiers: [must_read, need_fulltext], limit: 5 }
  - { id: weekly-me, topic: "*", channel: feishu_me, schedule: "weekly mon 09:00", tiers: [digest], limit: 15 }
  - { id: review-me, kind: review, topic: "*", channel: feishu_me, schedule: "weekly fri 17:00" }
```

`kind: review` 的路由生成周报（第 13 节），其余路由生成推荐。

### 11.3 推荐卡片的内容

每篇论文显示：

- 标题、作者、期刊和期刊分级、日期、DOI 链接；阅读价值分和等级；命中的所有主题。
- **为什么推给你**：按 `goal_links` 逐条列出“对应目标 g1：可以借鉴什么”。
- **作者原话**：一到两条核实过的引用，带页码；与模型概括在视觉上分开，模型概括标明“模型概括”。
- **全文获取途径**：开放获取、需要校园网（出版商链接）或暂无全文。
- 临时分注明“只读了摘要”；`undetermined` 注明哪些维度无法判断。
- 私有渠道带操作：「去读」（打开领读器中的这篇论文）、「稍后读」「不感兴趣」；开启 Zotero 同步时另有「加入 Zotero」；`need_fulltext` 的论文另有「上传全文」。

私有卡片的命中课题按当前研究画像指纹对应的相关初筛结果确定，稳定排序并随 Digest 冻结课题编号与名称；过期画像或已移除课题不进入新卡片。重绘历史卡片沿用冻结名称，不重新初筛。公开投影不包含这组课题关联，沿用第 11.4 节的白名单。

「去读」是链接，指向运行拾穗的那台电脑上的领读器，只在那台电脑上能打开；在手机上看到推送时用「稍后读」按钮，它通过回调记为待读。

### 11.4 公开和私有的边界

公开内容使用**字段白名单**（`PublicPaperView`），新增字段默认不公开：

| 字段 | 私有渠道 | 公开渠道 |
|---|---|---|
| 标题、作者、期刊、日期、DOI 链接 | ✅ | ✅ |
| 分数、等级、一句话总结 | ✅ | ✅ |
| 结论、不足、创新点（自己的概括） | ✅ | ✅ |
| 研究目标对照、反馈按钮 | ✅ | ❌ |
| 原文长引用、出版商摘要 | ✅ | ❌ 只放链接 |
| PDF、双语 PDF、归一化全文 | 不经渠道发送 | ❌ **永不公开** |
| 未设 `public: true` 的主题、反馈、费用 | ✅ | ❌ |

公开渠道收到的主题在选文时再过滤一次：即使路由写了 `*`，也只有 `public: true` 的主题能进入公开渠道。

LLM 输出来自不可信的论文内容：所有输出都限制长度；发给任何渠道前去掉其中的链接（裸域名不处理）；渲染时按纯文本处理，链接、@ 人和格式符号都不生效。公开渠道上线前要决定是否加人工审核。

### 11.5 不重复推送

- 同一路由、主题、周期只生成一份 Digest。
- **同一篇论文在同一渠道只推一次**，不分主题；卡片上列出它命中的所有主题。
- **例外：等级升级补推一次。** 以临时等级（`need_fulltext`）推过的论文，全文评估后进入更高的正式等级（如 `must_read`）时，再推一次并注明“读完全文后升级”。
- 发送前把状态记为 `sending`。适配器确定发送失败时抛 `TransientError` 或 `PermanentError`，可以重试。
- 其他异常（如超时、进程崩溃）无法确定对方是否收到：状态保持 `sending`，下次进入死信，**不自动重发**。确认后用 `litgleaner delivery resolve` 标记已收到或重发。
- 渠道支持幂等键时（如飞书消息的 uuid）一律带上。

**推送量受控**：路由的 `limit` 是上限。未读积压（`reading_state=queued` 超过阈值）时，每次推送按比例减少篇数，只保留 `must_read`，并在卡片上注明“你还有 N 篇待读”。推送频率默认每天一次，用户可以改为每周或暂停。

### 11.6 反馈回流

渠道按钮和转发的文件只写入 `feedback` 或 `inbox`，再由流水线读取。机器人不直接执行业务，所以它崩溃也不影响每日任务。

- 入站适配器放在各渠道自己的包里，例如飞书在 `adapters/feishu/listener.py`。适配器只负责核验身份（`answerers` 白名单）和格式，产出 `ports/inbound.CardClick`。
- 点击「加入 Zotero」写一条 `save_to_library` 反馈，由 `library` 阶段（`application/stages/library_save.py`）调用 `ReferenceLibrary` 写进文献库。
- 文献库没开时按 `Deferred` 推迟，不计失败次数。写成功后记 `library_entry`，重复点击不会重复写入。
- 飞书回调必须 3 秒内答复，所以监听只把点击放进队列，由服务进程的任务执行器处理，然后更新卡片。
- 飞书长连接由常驻服务维持。电脑休眠或关机时按钮点击收不到；需要随时可点的用户把服务部署到服务器（第 15.5 节）。
- 未启用对应渠道时不加载监听 SDK 或读取渠道凭据。共用同一应用凭据的渠道共用一条长连接；回调按订阅人的并集快速初筛，任务执行时按原 Digest 的渠道及其订阅人再次核验，论文必须属于该 Digest。没有 Digest 编号的旧卡片仅在单渠道时接受，多渠道歧义不写反馈。
- 点击队列由服务任务执行器持共享运行锁处理，锁竞争时保留待办；只执行反馈、文献库任务和卡片重绘，不由点击触发发现或付费模型阶段。消息更新在业务写入完成后执行，更新失败不撤销已记录的动作。渠道连接故障隔离于领读器和定时流程；服务停止时关闭连接、后台任务与事件循环，网络等待必须有界。SDK 的生命周期差异封装在渠道适配器内部。
- 渠道配置步骤和验证层级见 [CHANNELS.md](CHANNELS.md)。

## 12. 领读器与 Zotero

领读器是拾穗自带的本地网页界面，由常驻服务提供（第 15.5 节）。它是用户每天打开的地方，页面按调研、阅读、知识库三件事组织（第 12.8 节）；点进一篇论文就进入阅读页。

### 12.1 “好”的标准

设计参照 Semantic Reader 项目经过用户研究验证的做法：就地释义（ScholarPhi）、面向非专家的章节要点（Paper Plain）、分面高亮帮助略读（Scim）、结合读者文库标注引用（CiteSee）。下面是领读器必须满足的原则，每条都要能验收：

| 原则 | 含义 | 验收方式 |
|---|---|---|
| 原文为中心 | 增强内容出现在原文旁边或悬停处，不替代原文；随时能一键回到纯原文 | 每个增强都可关闭；第一次打开显示原文，之后沿用读者上次选的翻译模式 |
| 每句都可核验 | 模型写的每条内容都能跳到原文位置；没有依据的标明“无原文依据” | 自动检查：展示的引用 100% 通过 `verify_quote`，未通过的不显示为原话 |
| 模型和作者分得清 | 作者原话、模型概括、用户笔记三种内容在视觉上明显不同 | 界面走查 |
| 术语一致 | 同一术语在译文、释义、卡片中用同一个译名 | 自动检查：译文中术语表译名的命中率 100% |
| 不打断阅读 | 侧栏不遮挡正文；增强按需加载，不阻塞翻页；常用操作有快捷键 | 缓存过的论文 2 秒内打开；段落翻译流式返回，首字 2 秒内出现 |
| 花费和额度看得见 | 会产生模型费用的操作事先说明，并显示本月累计；边读边问走本机 agent 时显示调用次数和额度上限（[ADR 0008](adr/0008-agent-for-ask-only.md)） | 界面走查 |
| 沉淀可回顾 | 批注、卡片、问答都存下来，可以检索，并能跳回原文 | 端到端测试 |

用户体验指标（任务完成时间、理解测试、可用性量表、信任问题次数）在真实用户测试中测量，流程和门槛见 [ROADMAP.md](ROADMAP.md)。

**交互准则**（依据见 [设计研究](experiments/2026-11-07-reader-design-research.md)）：

- 增强默认收起、按需展开；悬停卡只放一条释义加出处，不遮挡原文。
- 背景卡、章节导读、问题索引只做导航入口，每条都能跳到原文，不提供“读完卡片就够了”的路径。
- 分面高亮固定四色（目标、创新、方法、结果），约每段最多一句，只标高置信度的句子，每类可以单独关闭。
- 术语释义优先显示论文自己的定义和位置；术语有多种用法或没找到定义时明确说明。
- 参考文献标注只用“建议先读”“已在库”“已读”三种，读过或入库后自动降级。
- 不确定的内容用第一人称说出来（“我无法从文中判断”），并标为“模型推断”。
- 读后卡片默认“先写后看”：用户先写自己的判断，再展开模型的版本；可以关闭。
- 每条模型内容都能被用户标为有误；标记写入反馈，用于校准。
- 选中文字的菜单提供“连续高亮”模式，避免每次都弹菜单。
- 上线后监测来源锚点的点开率、“标为有误”的比例和“先写后看”的关闭率。

### 12.2 阅读页

| 区域 | 内容 |
|---|---|
| 正文 | **原版视图**（默认）：在浏览器里渲染原始 PDF（引擎选择见 [ADR 0006](adr/0006-platform-and-reader-reuse.md)），增强内容和全文译文按页码和 `bbox` 叠加。**段落视图**：由 `NormalizedDocument` 重排，适合双语对照和小屏。两个视图之间按页码和块位置同步 |
| 读前 | **原理动画**（默认关闭）：用一个小例子分步演示论文的核心机制，每一步配原文引用<br>**背景卡**：这篇要解决什么、需要先懂的 3–5 个概念（每个都有释义和出处）、章节导读；概念部分按用户知识库定制，已掌握的少讲，没见过的用已知概念类比（第 12.7 节）<br>**3 个引导问题**：理解、对比、迁移，作为阅读重点 |
| 读中 | **就地释义**：术语表中的词和论文自己定义的符号悬停显示释义<br>**分面高亮**：按 `extraction.highlights` 把目标、创新、方法、结果句分色标出，可以逐类开关<br>**按需翻译**：选中段落或点段落旁的按钮显示中文，可以切换为整篇双语对照<br>**边读边问**：针对选中内容或整篇提问<br>**引用标注**：参考文献标出“已在你的库里”“已读”“建议先读”及理由 |
| 读后 | **回答卡片**：逐题写下自己的理解，提交后看评价和参考答案，沉淀进知识库（第 12.7 节）<br>**读后卡片**（第 9.4 节）：可编辑，包含用户的回答卡片；可以导出为组会汇报提纲 |
| 侧栏 | 按阅读顺序排四个标签页：导读、问答、笔记、读后；笔记支持高亮和文字笔记。侧栏和目录都可以折叠（第 12.8 节） |

- **原理动画默认关闭**：生成分镜要消耗较多 token，不同模型效果差距大。用户在设置中开启后，每篇论文仍需手动点“生成”，生成前显示预估费用。
  - **分镜**：模型只负责写分镜，以结构化数据存入 `explanation`（`kind = principle`），内容包括选哪个机制、几个步骤、每步说明、引用的原文、玩具例子的输入。引用按第 12.1 节核验。机制无法用小例子说明时（如纯定性的论文），不生成分镜。
  - **两种渲染方式**，在设置中选择：
    - `code`（推荐）：数值由代码按论文公式计算，前端用 HTML 或 SVG 逐步播放，可以暂停、单步、放大。
    - `image_gif`：把分镜交给 `ImageGenerator`（默认 GPT Image 系列）生成 GIF 动图，结果作为 `artifact` 缓存。图像模型可能画错文字、公式和数字，所以动图旁边固定标注“AI 生成动图，图中文字和数值未经核验，以原文为准”，并附上分镜的原文引用。动图不作为证据，不进入读后卡片和导出。
- 背景卡、章节导读和前置阅读指引在第一次打开时生成并缓存到 `explanation`。`must_read` 论文可以在推送前预生成，由配置决定。
- 解析质量为 `degraded` 时，段落视图顶部提示“结构识别不完整，以原版视图为准”。
- 论文语言和阅读语言相同时（如中文读者读中文论文）：翻译自动跳过，其余功能照常。

### 12.3 翻译

全文翻译是常规功能（REQUIREMENTS R2），目标语言是配置的阅读语言（第 15.6 节），任何时候都能一键切回原文：

| 模式 | 说明 |
|---|---|
| 原文 | 显示论文原版 |
| 全文覆盖 | 原版视图中，译文按版面块覆盖在原文位置上，保留版式 |
| 双栏对照 | 左边原文、右边译文，滚动同步 |
| 按页、按段翻译 | 只翻当前页或点中的段落；译文显示在原段下方或悬浮层 |
| 译文 PDF 导出 | 译文版、原文译文交替页两种。在前端用 PDF 引擎做字符级重排后写出，复用 Agentero 的实现（[ADR 0006](adr/0006-platform-and-reader-reuse.md)）；字体用 OFL 许可的 Noto Serif 和思源宋体，首次使用时下载并校验 |

- 版面来自解析得到的块（页码、bbox、类型），块内文字从 PDF 文字层按 bbox 读取，使每句译文都能对准原文位置。
- 公式、LaTeX 命令、URL、DOI、引用编号、作者-年份引用、图表和公式的交叉引用先换成占位符再翻译，回填时检查缺失和重复；校验失败的段落保留原文，不用部分译文覆盖。
- 全文翻译按阅读顺序分批，每批约一页正文，每句一个编号；每个段落完成就立即显示，不等整页。
- 翻译的单位是段落：被分页、分栏或图表切开的段落先拼回一段（前一块末尾没有句末标点、后一块以小写开头），一句跨块仍是一个编号，译文按各块原文长度切回各块。用户点某一块时翻译它所在的整段。

- 段落翻译是 LLM 任务 `translate`，走统一网关，计入预算。输出是流式纯文本，每行一句，结束后由代码校验句数和术语表译名，通过才缓存（[ADR 0004](adr/0004-streaming-translation.md)）。
- 提示词中注入课题术语表；公式、符号、引用编号、表格按原样保留。
- 译文按 `(block, source_hash, target_lang, glossary_hash, translator_version)` 缓存，同一段只翻一次；术语表变化后不自动重译（第 7.1 节）。
- 翻译只走 API 提供方（[ADR 0008](adr/0008-agent-for-ask-only.md)）。整篇翻译先估算费用，用户确认后才执行。推送论文的后台预翻译同样走 API；没有配置 API 时不预翻译，用户打开时再翻。

### 12.4 边读边问

- 内置问答使用 `llm.yaml` 中的 `ask` 任务。`ask` 是唯一可以走用户本机 agent 的任务（第 15.2 节、[ADR 0008](adr/0008-agent-for-ask-only.md)）；没有本机 agent 时用 API 提供方。agent 的安全措施在接入时另行决定。
- 上下文：选中内容、所在章节、相关 chunk（按需检索，FTS5 与本地向量混合排序）、研究画像、读后卡片，以及论文间记忆中与本篇有关的已核实关系和用户笔记（第 12.9 节）。只发送必要片段，不整篇发送。
- 回答必须给出引用的原文和页码，代码核验；没有依据的部分标为“模型推断”。
- 问答记录写入 `qa_message`，可以检索，也可以把一问一答存为批注。
- 进阶用户可以让 Claude Code、Codex 等外部 agent 通过只读 MCP（第 12.6 节）获取同样的上下文。

问答记忆执行合同：

- 新问题排队时冻结实际系统提示、完整清洗消息、研究画像指纹、协议及完整请求生产者，以及实际发送的来源清单；问题与任务仍按请求 ID 同事务幂等保存。来源区分作者原文、用户批注正文和用户历史问题，模型回答与模型提取概括不能冒充用户笔记或作者原文。尚无规范源表的回答卡片、可编辑读后卡片由相应功能落库后接入。
- 检索先限定当前论文及文库来源、来源类型和作者身份，再按 FTS 命中及本地向量混合排序。关系只使用业务状态有效且当前证据完整可核验的记录，最多三条；FTS 取最多 64 个完整来源候选，保留版本和原始 BM25；已就绪本地模型可用问句向量检索有效论文缓存、重排最多 64 个原文候选，禁止下载或隐式重嵌入写库。向量缺席或失败时说明降级，其他信号继续；向量只决定召回和顺序，引用必须回到规范源。相关提取只使用当前输入和生产者有效的字段，明确标为模型背景并冻结其指纹。
- 总输入仍为 4000 token 的保守上限，系统提示、身份、标题、关系、笔记和清洗后的完整 JSON 包装均计入。选区及本篇原文优先；为可用记忆保留有界份额，外部来源按完整条目取舍。候选片段提取共扫描最多两百万字符及四千个来源，实际发送片段保持连续，损坏归档按论文隔离；同一文档一次准备或复核只读一次。关系按确定顺序核验最多六十四个候选，原页和已用核实批次冻结片段仍按原合同完整复核，不把截断内容误报为原文失配。
- 原文引用保留 `paper_id/page/quote`；用户笔记及历史问题另用 `note_citations` 保留论文、规范源 ID、来源类型和逐字引文，不为无页码笔记伪造页码。陈述通过 `mentioned_paper_ids` 及 `[[paper:<id>]]` 标记明确所提论文；每个外部身份必须由该论文有效原文或用户来源引用覆盖，未声明的已发送外部论文身份或标题同样拒绝。代码逐条核验真实论文、原页或用户源版本、单个实际发送片段及清洗后完整消息；跨论文证据不足的整条陈述丢弃，本篇无据判断仍标模型推断。全丢弃时保存服务端“证据不足”结果，避免再次收费。
- 调用前与保存回答前复核冻结输入、实际发送来源和所用关系，变化要求重新提问；新增未选记忆不扩张旧问题。完整请求生产者包含协议、schema、提示词、请求模型与提供方。新答案保留冻结清单和生产者，旧答案按缺失信息保留 `unknown`；统一过期快照批量加入当前有效批注，固定十八次读取后核验，不逐答案补查或做向量推理。历史答案的过期判断只比较实际冻结使用的来源与配置，不因新增无关记忆失效。保存问答为批注时，只以当前论文的作者原文作位置锚点，其他出处通过问答关联保留。

### 12.5 Zotero 同步（可选）

`ReferenceLibrary` 的 Zotero 实现走 Zotero 桌面端的本地 API（`127.0.0.1:23119`），不经过 zotero.org，**不需要安装任何 Zotero 插件**。

| 写入内容 | 说明 |
|---|---|
| 条目 | 有 arXiv 编号且没有期刊的建成预印本，其余建成期刊论文 |
| 分组和标签 | 默认分组「拾穗」；标签含主题名和推送等级 |
| 笔记 | 读后卡片和用户批注的导出（Markdown 转 HTML），末尾附拾穗编号 |
| PDF | 系统已经取到的全文；导出过双语 PDF 时一并挂上 |

- 查重：先按标题搜索，再核对 DOI 或 arXiv 编号；已有条目只补分组、标签和缺少的附件。
- 只写「我的文库」，不写群组文库。
- 授权：在领读器设置页点“连接 Zotero”，引导用户打开 Zotero 的本地 API 开关并在弹窗中点“始终允许”，本地 key 存入 `SecretStore`。
- 读取（种子分组、“已读”标签）优先用本地 API；不可用时读 `zotero.sqlite` 的只读副本，绝不直接打开或写入用户的数据库文件。
- 笔记同步是单向的（拾穗 → Zotero）。在 Zotero 里改的笔记不会回写，以免两边冲突。

### 12.6 给外部 agent 的只读接口

`litgleaner mcp` 以 stdio 方式提供只读 MCP 服务，Claude Code、Codex 等都可以挂载：

| 工具 | 返回 |
|---|---|
| `get_profile(topic)` | 研究背景、内容、目标、术语表 |
| `list_recommendations(topic, since)` | 推荐过的论文、分数和等级 |
| `get_paper(id 或 DOI)` | 元数据、各维度等级与证据、目标对照、读后卡片、用户批注 |
| `search_archive(query)` | 已归档论文的全文检索（FTS5），带页码 |
| `related_papers(paper)` | 同主题下方法、数据或引用相近的论文 |
| `comparison_table(topic)` | 第 14 节的方法对比表 |

- 只读：不提供任何写入或执行工具，不监听网络端口。
- 返回的论文内容用分隔标记包裹，并注明是不可信数据。
- 查询逻辑在 `application`，`mcp_server.py` 只做协议适配。

### 12.7 知识库与个性化引导

研究者读完一篇论文，用自己的话回答引导问题；系统评价回答，把他掌握的概念和他自己的表述沉淀进个人知识库。下一篇的导读和引导问题按知识库定制：已经懂的少讲，不懂的用他懂的东西类比（[ADR 0007](adr/0007-knowledge-base-and-personal-guidance.md)）。

**知识库**

- 全局一份，以概念为单位，跨课题共享；课题只是标签，由概念出现过的论文所属课题推出，用户也可以手动加。
- 概念来自提取结果的 `key_concepts`（第 9.4 节）：按别名精确匹配到已有概念，匹配不上就新建；模型提议的疑似重复写入 `concept_merge_candidate`，由用户在知识库页确认。
- 课题术语表（第 7.1 节）继续负责译名，条目按英文术语经 `concept_alias` 关联到概念。

**掌握程度**：系统评价，用户可以改。

| 等级 | 怎么达到 |
|---|---|
| 没见过 | 默认 |
| 见过 | 读过含该概念的论文，或打开过它的讲解 |
| 能解释 | 用户写的回答经评价，对该概念的解释正确 |
| 能应用 | 对比题或迁移题回答正确，或复习中多次记得 |

- 等级由 `domain` 中的纯函数从 `mastery_event` 算出，写入 `mastery_state`（键含 `policy_hash`，规则变了可以零费用重算，同 `rubric rescore`）。用户修改优先，修改本身也是一条事件。
- 打开讲解、读过论文本身只能把概念记为“见过”。只有用户自己写出来、经过评价的内容才能提高到“能解释”及以上。

**个性化导读**（LLM 任务 `guide`）：打开论文时，对这篇的关键概念按掌握程度分别处理。

| 掌握程度 | 导读怎么写 |
|---|---|
| 没见过 | 完整讲解，优先用论文自己的定义；用用户已掌握的最相近概念做类比，并说明类比在哪里失效 |
| 见过 | 一句提醒，加上和相近概念的对比 |
| 能解释、能应用 | 一句带过，引用用户自己写过的话作锚点；或者直接跳过 |

- 输入：这篇的提取结果和背景卡；关键概念各自的掌握程度；用户对这些概念写过的回答（原话片段）；论文间记忆给出的已核实关系和用户在那些论文上写过的笔记（第 12.9 节）。只发送这篇论文涉及的概念，不发整个知识库。
- 导读和引导问题第一次打开时生成并缓存在 `explanation`（`kind = guide`）。指纹包含“相关概念的掌握状态”。知识库变化后不自动重新生成，再次打开时提示“你的知识库已更新，要不要重新生成”。
- 知识库为空（新用户）时退化为通用导读。首次向导可以让用户勾选熟悉的概念，作为初始的修改事件。

**3 个引导问题和回答卡片**

| 问题 | 考什么 | 知识库为空时 |
|---|---|---|
| 理解 | 用自己的话说出本文的核心机制 | 不变 |
| 对比 | 和用户已掌握的概念或读过的论文相比，异同在哪里 | 改为和论文里的已有方法比较 |
| 迁移 | 能不能用到自己课题的某个研究目标上，怎么用 | 没有研究画像时，改为“换一个场景还成立吗” |

- 问题在读前展示，作为阅读重点；同时挂在对应章节的开头。
- 每个问题一张回答卡片，**先写后看**：用户写一到三句话，提交后才显示评价（LLM 任务 `evaluate`）和参考答案。评价按问题针对的每个概念给出：对、漏、理解偏了，每条附原文引用，引用必须通过 `verify_quote`，没通过的不显示为原话。
- 用户可以跳过任何一题，可以修改回答（修订只追加），可以把评价标为“有误”（写入 `feedback`），可以直接改掌握程度。
- 回答卡片同时出现在读后卡片（第 9.4 节）里，标明是用户写的。

**复习**

- 下次复习时间由纯函数根据复习记录算出（间隔逐步拉长，例如 1、3、7、14、30 天）。
- 领读器首页有“今日复习”。复习题从用户自己写过的回答出发；用户回答后自评“记得 / 模糊 / 忘了”，不调用模型。用户点“帮我看看”时才调用 `evaluate`。
- 主题周报的“回顾”从到期概念中抽取（第 13.2 节）。

**知识库页**：按课题标签浏览，用 FTS5 检索概念；每个概念显示掌握程度、出现过的论文和页码、用户的回答卡片、相关概念（前置、相似、对比）；可以修改等级、确认或拒绝合并、导出 Markdown。

**边界**

- 模型从不写入用户的回答；作者原文、模型生成、用户写的三种内容在知识库页同样分开显示（第 12.1 节）。
- 概念关系（`concept_link`）由模型在生成导读时提议，附依据；用户可以确认或删除，不作为评价掌握程度的依据。
- 不引入向量数据库（第 16 节）：概念匹配靠别名和模型提议，检索靠 FTS5 与存在 SQLite 里的本地向量（第 12.9 节）。

### 12.8 页面结构与入口

领读器的页面按用户要做的三件事组织，不按流水线的阶段组织（[ADR 0009](adr/0009-survey-read-retain.md)）。

**常驻导航**：

| 入口 | 回答的问题 | 内容 |
|---|---|---|
| 今天（首页） | 现在该做什么 | 继续读（在读的论文和读到的位置）、今日复习、新推荐；待读超期的必读论文置顶（第 13.1 节） |
| 课题 | 这个方向有什么，我覆盖到哪里了 | 每个研究画像一页：调研进度和覆盖度、阅读路线、课题地图、对比表、综述骨架（第 7.5、14 节）；检索式、术语表、推送频率在这里编辑 |
| 文库 | 我读过什么、存了什么 | 所有有阅读状态或笔记的论文，按在读、待读、已读、放弃和课题筛选 |
| 知识库 | 我懂了什么 | 概念、回答卡片、复习（第 12.7 节）；全部笔记和高亮的汇总 |
| 设置 | — | 模型和花费、语言、渠道、Zotero、本机 agent、数据目录和导出 |

导航上另有两个常驻操作：添加论文、全局检索。

**添加论文**：任何页面都能用，也可以把 PDF 拖进窗口。

- 接受 DOI、arXiv 编号、论文链接和 PDF 文件。写入 `inbox`，由事实层流程处理（去重合并、取全文、解析、提取），按用户主动操作排在后台任务之前（第 15.2 节）。
- 元数据仍然不经过模型：有标识符时向信号源查；只有 PDF 时，由代码从首页文字里找 DOI 或 arXiv 编号再查；查不到时用文件名建条目并标明“元数据待补”，用户可以手填。
- 上传的 PDF 做与下载相同的大小和文件头校验，`license_basis` 记为 `user_supplied`。
- PDF 存好就能在原版视图打开；解析、讲解、译文完成后陆续出现，界面显示各自的进度。
- 不要求有研究画像。有启用的画像时照常初筛和评估；没有时只走事实层，读后卡片里“和我课题的关系”留空。

**全局检索**：一个搜索框，用 FTS5 查论文（标题、摘要、已归档全文）、笔记和高亮、回答卡片、问答、概念。结果按类型分组，每条跳到原文位置。

搜索文字执行合同：`memory_fts` 保留原有八列及原文 `title/text`，原文列不参与分词，另用 `search_title/search_text` 保存按 `NFKC → casefold → 空白压缩` 生成的搜索副本，沿用 trigram。全局检索、概念、候选和问答对查询使用同一规范化；短词字面匹配也查搜索副本。BM25 仅对搜索标题和正文赋权四和一，其余列权重为零。返回内容、页码、作者身份、规范来源核验及冻结输入仍使用原文和既有来源版本，不把规范化偏移直接用于切原文；摘句保留真实连续原文，兼容字形展开及组合字符。

所有后续索引写入同事务维护搜索副本。确定性规范化函数由业务与迁移连接显式注册；普通 SQLite 工具仍可只读和备份，直接改写带索引触发器的规范表须注册该函数，否则写入失败，不允许静默生成不一致索引。旧库通过既有 `db upgrade` 重建索引，从旧八列逐值回填，保留全文块、空文档标记、行身份和来源版本；不读取归档，不访问模型或来源，不新增重建命令。降级恢复旧索引布局与触发器。备份升级演练比较业务表和 FTS 逻辑记录数，FTS 已知内部影子表不按物理行数判断丢失，另外核验索引完整性。

**个人数据导出**：`litgleaner export mine --out <目录>`，设置页有同一个操作。

- 每篇论文一个 Markdown 文件（元数据、读后卡片、回答卡片、笔记和高亮，带页码），每个概念一个 Markdown 文件，全部论文的 BibTeX 和 CSL-JSON。PDF 默认不导出，可以选择一并导出。
- 只导出，不读回，SQLite 仍是唯一真相（第 10.1 节）。作者原文、模型生成、用户写的三种内容在导出文件里同样分开标明。

**阅读页布局**：

- 正文优先。目录和侧栏可以分别折叠，状态按读者保存；窗口变窄时先收目录，再把侧栏收成抽屉；打开双栏对照时自动收起两者。
- 顶栏只放：返回、标题、原文与译文的切换、“显示”面板入口、帮助。视图切换、分面高亮、术语释义等开关放在“显示”面板里。
- 还没有提供的功能不放禁用的占位控件。
- 快捷键提示按操作系统显示修饰键。
- 界面文案不出现命令行；需要命令行才能完成的事，界面上要有等价操作。
- 空页面给出下一步：没有任何论文时，首页显示“读一篇论文”和“调研一个课题”两个入口（第 15.5 节）。

验收：在 1280×720 的窗口里（对应常见的 1366×768 屏幕，以及 1920×1080 屏幕放大到 150%）走查，顶栏不换行，阅读页全部功能可用。

### 12.9 论文间记忆

一篇论文进入文库后不是就不管了：以后读到与它相关的论文时，导读和问答会提起它，附双方原文和用户当时写的笔记（[ADR 0010](adr/0010-paper-memory.md)，调研见 [开源实现调研](experiments/2026-11-11-memory-open-source-survey.md)）。

**范围**：只在文库内建立关系，即有阅读状态、笔记或由用户添加的论文（第 12.8 节）。流水线发现的候选论文不参与。

**三部分记忆**：概念记忆（第 12.7 节）、论文关系（本节）、个人记忆（笔记、高亮、回答卡片、问答、读后卡片中用户写的部分）。都在 SQLite 里。

**事实关系**（零模型费用，论文进入文库时生成）：

| 信号 | 来源 |
|---|---|
| 直接引用：A 的参考文献对上了库内的 B，附引用句和意图 | `citation` |
| 文献耦合：A、B 引用了至少 k 篇相同文献；被至少 ⌈n/3⌉ 篇库内论文共同引用的文献视为重要前作 | `citation` |
| 共享核心概念 | `concept_occurrence` |
| 共享数据集、方法类别（归一化名称） | `extraction.datasets`、`extraction.method` |
| 提到了但没有关联：笔记或正文里出现库内论文的短标题、方法名 | `paper_mention`（FTS5 匹配） |
| 内容相近 | `paper_embedding` 的余弦相似度 |
| 文本相近 | `memory_fts` 的 BM25 |

事实关系提供只读查询 `/api/papers/{paper_id}/memory-facts`：仅接受文库内论文，返回其与其他文库论文之间的双向引用、共同参考文献、共享核心概念和按归一化名称精确匹配的数据集及方法，保留各侧来源与原文位置。引用按唯一精确别名动态关联；共同参考文献按同一目标去重，多来源证据不增加共同目标数，歧义标识符不参与连边。共同目标可以尚未进入文库；关系两端始终属于文库。结果稳定分页，返回完整总数；共同目标数是原始信号，是否达到文献耦合阈值由下述策略决定。

引用身份核验先完成全库别名的最终归并，再生成直接边、共同目标和重要前作。跨记录别名链最终连接多个已知论文 ID 时，该组未保存目标 ID 的条目均不参与连边或计票；唯一目标的传递关联保留。已保存的显式目标 ID 独立作为事实，不借其原始别名桥接其他目标，也不因动态别名组歧义而被擦除，仍按各自 ID 参与直接边和共同目标。各投影使用同一最终接受结果，逐来源保留全部原始证据及其输入顺序，不改写数据库引文。

查询复用最新提取，不回退旧版本。提取输入必须对应当前文档、切分、语言和预算，已配置的生产者指纹也须匹配；未配置模型时保留可核对输入的已有事实并注明生产者未完整核验。共享核心概念还须与该提取的输入、生产者指纹及当前核心名称、位置对应，名称沿用已登记的概念别名；定义未核验不补造定义。数据集和方法只使用已核验字段，名称仅统一 Unicode、大小写与空白，不猜缩写或同义词。缺少或过期证据单独说明，不阻断原始引文关系。查询读取一致批量快照，不写库、不加载模型、不联网、不重新提取。

重要前作提供全文库只读查询 `/api/memory/important-works`：`n` 为同一快照中全部当前文库论文数，包含尚无引文的论文；门槛为 `⌈n/3⌉`，空文库门槛为零且结果为空。每个唯一精确目标按不同引用论文计票，多来源、多位置与重复别名不加票；同一论文引用自身不计票，不同论文即使作者相同仍各计一票。目标可以尚未入库，沿用事实查询的全库别名归并和歧义排除规则，不按标题猜测。返回文库规模、门槛、每个目标的不同引用论文数，以及逐篇的阅读状态和全部来源证据。结果按引用论文数降序、精确目标身份升序稳定分页，并返回分页前总数。复用事实查询的八次一致读取，在事务外计算，不产生持久化结果、模型费用或外部请求；文库与引文变化在下次读取时生效。

**候选打分**：`domain` 中的纯函数对上表信号加权求和，权重、每篇核实的对数 N（默认 5）、阈值写在 `config/memory.yaml`，计入 `policy_hash`。改权重只重排候选，零费用。

候选策略放在 `memory.yaml` 的 `candidates`：默认权重为直接引用 6、带方法/扩展意图及非空引用句 5、共同参考文献 4、共享核心概念 4、共享方法 4、余弦 3、共享数据集 2、文本检索 1；共同参考文献至少 2 篇，余弦至少 0.5，总分至少 0.5，每篇最多 5 个候选。这些是可调整的初始策略，真实案例校准另记实验。除余弦和文本检索外，各项只计是否命中；双向引用、多个概念、多来源和多位置不重复抬高同一项。共同参考文献沿唯一目标去重后判断门槛。余弦使用原始非负分数，文本分数使用每篇最强有效 BM25 的相反数，除以本次全部有效命中中的最大值；缺席、无效或未过单项门槛时该项为零。策略参数及算法协议版本共同决定 `policy_hash`，分项值、权重和贡献都保留。

只读 `/api/papers/{paper_id}/memory-candidates` 合并全部文库事实、当前有效向量和已有 FTS 的命中并集，按总分降序、论文 ID 升序返回；只保留正分且达到总分门槛的候选。默认返回策略规定的 N，接口的 `limit` 只能进一步缩小数量，另返回截断前总数。候选保留双方事实、实际向量输入指纹及 FTS 来源、位置、版本和原始 BM25，不能据此宣称语义关系。缺少模型或有效提取时，其他信号仍独立可用。

候选读取使用独立一致快照：原事实八次查询，再读取文库向量及 FTS 命中，共十次 SELECT；原事实和向量接口的窄快照合同保持不变。FTS 查询仅取本篇标题与摘要的前 8192 字符，统一 Unicode、大小写与空白，按顺序提取最多 32 个不同检索词（可配置为 1–64）：三字以上的普通词按整词，连续中日韩文字按三字窗口，常见英文虚词及不足三字的词不参与；各词按字面值做 OR 召回。匹配只使用 `paper/fulltext/extraction`，不把用户笔记、问答或概念条目当作论文正文；全文须对应当前文档指针，提取须对应当前最大 ID 且通过事实查询同一输入和生产者护栏。每篇每种来源只保留最强命中，归一化在失效项排除后执行。查询与索引搜索副本按第 12.8 节同一协议规范化，原文字形及来源版本保持。没有索引时文本信号缺席；GET 不补索引、不读归档、不加载 SDK、不排队、不执行 `relate`。首次入库的自动处理、提及和语义核实由相应流程组合。

**判断关系**：LLM 任务 `relate` 只核实打分最高的 N 对，不负责发现。

- 输入：双方提取结果的 `problem`、`approach`、`method`、`claims` 片段和引用句，论文内容按不可信数据包裹。
- 输出（JSON Schema）：每对一种关系或“无关”：`extends`、`uses_method_of`、`compares_with`、`contradicts`、`similar_approach`、`same_problem`。每条必须有双方原文引用，经 `verify_quote` 逐字核对，对不上的整条丢弃。
- 写入 `paper_relation`。新证据推翻旧判断时旧记录标 `superseded_by`，不删除。用户可以确认、删除、改类型，写入 `feedback`。
- 只比较新进入文库的论文和已有的文库论文，不反向重算旧论文之间的关系；受 `relate` 预算限制，用完时推迟。历史回填用 `litgleaner memory backfill`，先给出对数和预计费用。
- 没有配置模型时只显示事实关系。

执行采用耐久的首次入库记录 `memory_admission`、只追加的核实批次 `relate_batch` 和 `paper_relation`。入库记录与添加、首次阅读状态或首条批注同一事务登记，并入按需队列；记录的递增序号确定此前已入库的对端范围，不靠同秒时间猜顺序。迁移为既有文库登记基线，不产生任务；退出后再入不自动重算。打开论文使用明确的写操作，GET 保持只读；渠道“加入外部文献库”和领读器“稍后读”是独立操作。首次入库时缺少 `relate` 路由会冻结这一事实，本次只处理本地事实，之后配模型不补算这些旧事件。

入库处理只为本次新论文准备事实、参考文献及已就绪的本地向量，不重算旧对端、不自动下载嵌入模型。等待本地获取、解析和提取使用 `WaitingForWork`；前置已终止或没有可核实原文则明确结束并保留理由。事件冻结策略、语言、提取和核实生产者及输入预算的配置身份；执行前改变则停止旧工作。候选在前置就绪后从仍在文库且序号更早的论文中排序，随后冻结实际发送内容；新入库论文不扩张已有批次。仅有笔记的论文也可触发首次入库，但用户笔记不发送给 `relate`。

`memory.yaml` 的 `relate.token_budget` 默认 8000（含完整系统提示、清洗后的 JSON 与隔离包装），每对及每侧均有连续原文片段上限；整对放不下就省略，不发送半对。默认 `relate` 路由每日额外限额为 0.2 美元，可沿第 15.2 节修改或显式清除。一次调用核实最多策略规定的 N 对；估费按价目表与实际输入、每对预计输出计算，标明经验估计。无候选、无关、缺失返回或全部引用未通过也保存批次完成凭据，重试复用，不再次收费。

模型只可选择输入中的一对并给一种关系或“无关”。`extends`、`uses_method_of`、`compares_with` 的 `paper_a` 是动作发出方，`paper_b` 是被扩展、被使用或被比较方；`contradicts`、`similar_approach`、`same_problem` 按论文 ID 规范化双端顺序。双方分别验证真实论文身份、零基页码、当前文档原页、实际发送的连续片段及清洗后的完整消息；页标记、元数据、未发送尾部和另一篇的同页文本均不能充当引文。任一侧失败整条丢弃；无关或未核验输出不能推翻已有有效判断。

核实批次按完整输入与生产者精确缓存，保留实际来源指纹、模型、费用 scope、遗漏及校验警告。关系证据和判断内容冻结，只允许状态及替代指针变化；新核验通过的判断取代同一双端的旧模型判断时，旧记录改为 `superseded` 并指向新关系，整个批次与关系变更同事务保存。没有新有效判断则只保存批次。关系两端必须不同且均在文库，身份歧义不连边。只读列表区分当前、过期和无法完整核验，保留历史；变化只提示，不自动核实。

统一 `stale` 同时核验全部关系和批次历史：与问答来源核验共用含当前有效批注的十八组结果，同一短事务固定十八次 SELECT，离开事务后复用来源元数据指纹和按文档归档缓存的原文核验，不逐条查询。用户决定的类型不因模型配置变化失效；原文或提取变化仍明确提示。首次入库台账不属于模型派生物，不因配置变化回填。

用户确认、删除和改类型写入带 `relation_id` 及动作数据的追加式 `feedback`，与关系状态在同一事务完成，按请求 ID 幂等；改类型追加用户来源的新判断，保留原模型证据并替代旧记录。用户已决定的双端不会被后续自动模型覆盖，显式回填也说明并跳过；历史删除可由明确确认恢复。原推荐卡片只读取保存/忽略动作，关系反馈不影响待保存或卡片状态。

显式 `litgleaner memory backfill` 默认只预览整个文库的待核实对数、遗漏、精确缓存与预计费用；执行必须携带当前预览指纹并重新核对，按新入库的同一冻结和核验流程排队，不能把旧事件转成自动任务。API 提供等价的预览、确认、状态、历史及反馈操作，沿用会话、Host/Origin 和 CSRF 保护。`memory_admit` 与 `relate` 进入同一按需执行器，由常驻服务或持共享运行锁的 CLI 消费；请求中不调用模型。

**本地向量**：端口 `Embedder`，默认适配器 `fastembed`，默认模型 `paraphrase-multilingual-MiniLM-L12-v2`（多语言，384 维）。

- 输入是标题、摘要和提取结果的 `problem`、`approach`；结果存 `paper_embedding`。文库几千篇以内在内存里逐个计算相似度，不建索引，不引入向量数据库。
- 模型第一次用到时下载并校验；未下载或在配置中关闭时，向量信号缺席，其余照常。
- 换模型产生新的 `embedder_version`，旧向量保留，`stale` 列出，`litgleaner memory reembed` 显式重算。
- 向量只用来产生候选和检索排序，不作为关系的依据。

本地向量的配置放在可选的 `config/memory.yaml`，默认启用本地适配器；没有依赖或模型缓存时，其余功能照常运行。组装层的参数与凭据辅助代码可放在同层 `bootstrap_args.py`，显式 `EMBEDDERS` 注册表仍在 `bootstrap.py`，嵌入适配器独立放在 `adapters/embeddings/`。启动、只读接口、`stale` 和命令默认预览均不加载模型、不下载文件；`litgleaner memory reembed --execute` 首次实际计算时才允许下载模型。

重算默认预览整个文库的缓存命中、待算数量、模型、维度和本地就绪状态；显式执行持共享运行锁，仅计算缺少当前精确指纹的论文，分批推理，批内向量全部校验后在短事务中重新核对文库范围和输入，再按指纹追加，变化项跳过。已有向量不删除，失败后可重试并复用已保存批次。独立窄快照只读文库论文、最新提取、全文指针和历史向量；事实查询的批量合同保持不变。

输入按标题、摘要、`problem.text`、`approach.text` 顺序加固定字段标签，统一 Unicode 和空白，再按配置字符上限取连续前缀。提取须对应当前输入及可核验的生产者；缺少或过期的提取只退化为标题摘要，不补造字段。输入指纹包含实际传入嵌入器的文本和预处理协议版本；另保留提取 ID 作为出处，不因未使用的字段变化使向量失效。生产者指纹包含适配器协议、模型、维度、推理选项、运行库版本和模型资产清单的内容校验值。首次计算生成本地资产清单，后续计算核对文件内容；只读状态检查仅使用清单、文件状态和依赖元数据，不构造推理实例。

`paper_embedding` 同时保存配置指纹、实际输入文本、模型与维度、提取出处及创建时间，向量按小端 float32 保存。写入前、使用时分别核对维度、有限值及非零范数；损坏向量不参与相似度。统一 `stale` 保留全部历史向量，区分输入失配、配置或生产者变化与无法完整核验；本地模型未就绪不等同于历史输入过期。

只读 `/api/papers/{paper_id}/memory-similar` 返回当前文库内、同生产者和维度的有效向量余弦分数，按分数降序、论文 ID 升序稳定排序；未就绪或缺少当前向量时返回空信号及原因，不触发推理。候选加权、首次进入文库的自动计算和语义核实由候选及 `relate` 流程组合，不在 GET 中执行。

**个人记忆检索**：FTS5 虚表 `memory_fts` 收录笔记、高亮、回答卡片、问答、读后卡片中用户写的部分和每篇提取结果的摘要字段，每条保留出处（论文、页码、类型、作者原文 / 模型生成 / 用户写的）。全局检索（第 12.8 节）、导读和问答都用它；与向量相似度合并排序。

**什么时候提起**：

| 时机 | 内容 |
|---|---|
| 打开论文 | 导读顶部“和你读过的论文”：最多 3 条已核实的关系卡（类型、对方论文、双方原文、你在对方论文上写过的一句）；本文引用了你库里的哪几篇、哪几篇引用了本文 |
| 读到某段 | 引用指向库内论文时行内标出（第 12.2 节的引用标注），悬停显示对方标题、阅读状态、你的笔记摘句；概念出现处链到其他论文中的同一概念 |
| 边读边问 | 检索结果加入已核实关系、相关论文的提取结果、你的笔记（第 12.4 节） |
| 引导问题 | 对比题优先和已核实关系中的论文比较（第 12.7 节） |
| 回看旧论文 | 论文页和文库显示“后来读的 B 扩展了它” |

阅读记忆摘要执行合同：

- 只读 `/api/papers/{paper_id}/reading-memory` 为打开和回看提供同一来源投影；主论文须已进入文库。GET 不登记打开、不改阅读状态、不补事实、不调用生成模型、执行向量推理或访问来源；模型描述元数据只用于核对原关系配置。打开仍使用独立的明确写操作。
- 关系卡只使用业务状态为有效且当前证据完整可核验的记录，最多三条。用户决定优先，同优先级先展示反向 `extends`，再按关系创建时间和 ID 降序；按该确定顺序最多核验六十四个候选，过期、未知及省略均说明。未由用户决定的模型关系须能读取原批次全部已发送原文，缺失使该批次关系无法完整核验；用户决定沿原有豁免模型批次配置的合同，双侧来源仍须核验。保留关系方向、双侧指定页原文、原判断指纹与对方当前阅读状态；反向扩展沿原有方向展示，时间字段保留其真实含义，不以入库或更新时间补造首次阅读时间。
- 每个对方可带一条当前有效批注的用户正文摘句，优先最近更新的非空正文，再按 ID 降序。摘句取首个非空行内的连续前缀，最多二百四十字符，注明截断；保留规范批注 ID、版本和原有页码。作者高亮原文及模型回答不充作用户正文，用户未写正文时返回空来源。
- 双向引用按文库对端分组，保留全部原始引文证据、来源及对端阅读状态，按对端 ID 稳定分页并返回完整总数。身份与歧义处理复用事实查询的全库精确别名规则，排除自连及非文库对端；不把引用方向改写成语义判断。
- 独立一致快照复用事实查询的八组结果，并追加主论文相关关系、所需核实批次及当前有效用户批注，共十一组 SELECT。关系原核实批次使用到的文档指针同批读取；事务外转换和原页核验，同一归档至多读取一次，损坏只影响对应关系。原事实、候选及全历史过期快照合同保持独立；核验不逐记录补查。笔记编辑、删除、文库退出及关系反馈在下次查询反映，不缓存或重算派生结果。

- 提起的内容只来自事实和已核实的判断；模型不能凭空说“这和你读过的 X 类似”。
- 导读缓存的指纹包含相关关系和笔记的指纹；记忆变化后不自动重写导读，再次打开时提示可以重新生成。
- 研究画像作为常驻块进入导读和问答的提示词，其余记忆按需检索。模型不写入任何记忆表：写入只有事实层流程、`relate` 校验后的结果和用户操作三条路。

**验收与调参**：用真实论文案例集（每组 3–6 篇，已知关系，如 Transformer 与 BERT、LIME 与 SHAP）测已知关系的召回、错误关系数和每篇 `relate` 费用；权重、N、提示词按案例调整，记录在 `docs/experiments/`。

## 13. 待读队列与主题周报

### 13.1 待读队列

- 来源以领读器为主：点「稍后读」或在卡片上点「稍后读」记为 `queued`；打开论文记为 `reading` 并保存读到的位置；读后卡片确认完成或手动标记记为 `read`；点「不感兴趣」记为 `dropped`。
- 开启 Zotero 同步时，写入的条目打上待读标签（默认「待读」）；用户在 Zotero 里改成已读标签（默认「已读」）时，`zotero` 信号源下次运行读到后同步为 `read`。标签名在配置里设置，不写死。
- 领读器首页按“在读 → 今日复习 → 新推荐”排列，待读超过 N 天的必读论文置顶提醒；完整的待读列表在文库（第 12.8 节）。

### 13.2 主题周报

`kind: review` 的路由每周生成一份，按主题分节：

1. **待读提醒**：`queued` 超过 N 天的必读论文。
2. **本周进展**：只汇总本周已推送或已读的论文，按研究目标分组，说明新出现了什么方法、结论或数据集。
3. **回顾**：从知识库中到期复习的概念里抽几个，附上用户自己当时的回答和出处论文，提醒去领读器复习（第 12.7 节）；知识库为空时，从已读论文中抽 2–3 篇重现读后卡片的要点。

- 进展部分由 LLM 生成，输入只包含这些论文的提取结果和证据。每条陈述必须引用输入中的论文编号，代码校验编号存在于输入集合，不存在的陈述丢弃。
- 周报本身也是不可变的 Digest，走同样的渲染、发布和不重复推送规则。

## 14. 方法对比表与引用导出

```bash
litgleaner export table --topic example-topic --format md|csv [--tier must_read,digest]
litgleaner export refs  --topic example-topic --format bibtex|csl-json|gbt7714 [--read-only]
litgleaner export outline --topic example-topic   # 综述骨架
```

- **对比表**：每行一篇论文，列为方法、数据集、指标与结果、代码是否公开、阅读价值分、对应目标。每个单元格来自 `extraction`，可附页码；`unverified` 的内容标注出来。
- **引用导出**：只用信号源写入的元数据和标识符，LLM 不参与。只导出有 DOI 或 arXiv 编号的论文；缺少标识符的单独列出，标为“需要人工核对”。
- **综述骨架**：按研究目标或方法类别把已读论文分组成提纲，每组附对比表和可核验引用，并列出“研究空白候选”（对比表中没有被覆盖的方法与数据组合等），每条都指向具体论文。**不生成成段正文**。
- 对比表、引用、综述骨架都可以在领读器里查看和导出。
- 对比表和引用导出不花费 LLM 费用；综述骨架的分组说明由 LLM 生成，按需执行。
- **综述骨架执行合同**：使用独立 `outline` 任务，先只读预览，再由用户确认固定输入并排队。范围为当前画像下相关且已读的论文；只使用已有提取，不补抓全文。模型仅返回短组名、短说明、论文编号及有编号依据的覆盖缺口候选；代码检查实际发送的论文编号和研究目标编号，附上由原始元数据生成的引用与由提取生成的对比表。缺少提取内容不构成研究空白证据；候选只描述当前已读输入集合的覆盖缺口。
- 结果以 `topic_outline` 只追加保存，带画像、实际发送输入、来源与生产者指纹；同时保存实际输入、预算遗漏和未分组编号，以及生成时的表格与来源引用附件。模型、提示词、阅读语言、预算或已发送来源改变时标记过期，不自动重做；新增已读论文单独提示。历史结果不随来源后续更新而被改写，相同输入与生产者重复确认复用缓存。

## 15. 运行与 LLM

### 15.1 任务调度

- 用 SQLite 的 `job` 表做任务队列，每个阶段自己定义幂等键。重复运行不会重复处理，也不会重复收费。
- 阶段顺序：discover → triage → acquire → parse → extract → assess → score → archive → select → publish → library。所有阶段都能单独运行：`litgleaner run --stage <name>`。
- 领读器的讲解、翻译、问答和双语 PDF 导出是按需任务，由用户操作触发，走同一个任务队列和预算；`must_read` 论文的背景卡可按配置在 `archive` 之后预生成。例外：单段翻译在请求里即时执行并流式返回，照常检查预算、记录费用（[ADR 0004](adr/0004-streaming-translation.md)）。
- 课题调研（第 7.5 节）和用户添加的论文（第 12.8 节）同样是用户触发的任务，走同一个队列和预算；添加的论文排在后台任务之前。
- 同一时间只允许一个流程运行（文件锁），定时任务重叠时后者直接退出。
- 写入集中在常驻服务进程：流水线、渠道监听、领读器都在这个进程里，按任务排队执行，事务保持短小。命令行操作同样先取文件锁。
- `Deferred`（额度用完、外部任务仍在处理、Zotero 没开）推迟到指定时间再试，不计失败次数。
- 失败按指数退避重试，超过次数进入死信。`AuthFailed`、`SchemaChanged` 重试也不会成功，直接进入死信。有失败时 `litgleaner run` 退出码为 1。
- 解析或提取彻底失败时，论文退回按摘要评估并标记为临时分，不会从系统里消失。
- 安装版由常驻服务按配置的时间运行流水线；启动时发现错过了运行时间就补跑一次。服务器部署也可以由 cron 调用 `litgleaner run`。

### 15.2 LLM

- 按任务配置模型，`providers` 定义怎么连（协议、地址、密钥、价格），`tasks` 定义哪个任务用哪个模型：

```yaml
tasks:
  triage:      { provider: main, model: CHEAP_MODEL,  prompt: triage }
  extract:     { provider: main, model: STRONG_MODEL, prompt: extract }
  assess:      { provider: main, model: STRONG_MODEL, prompt: assess }
  topic_draft: { provider: main, model: STRONG_MODEL, prompt: topic_draft }
  map:         { provider: main, model: STRONG_MODEL, prompt: map }         # 课题地图（第 7.5 节）
  outline:     { provider: main, model: STRONG_MODEL, prompt: outline }     # 已读论文综述骨架（第 14 节）
  review:      { provider: main, model: STRONG_MODEL, prompt: review }
  explain:     { provider: main, model: STRONG_MODEL, prompt: explain }     # 背景卡、章节导读、前置阅读
  translate:   { provider: main, model: CHEAP_MODEL,  prompt: translate }
  principle:   { provider: main, model: STRONG_MODEL, prompt: principle, enabled: false }   # 原理动画分镜，默认关闭
  ask:         { provider: main, model: STRONG_MODEL, prompt: ask }
  guide:       { provider: main, model: STRONG_MODEL, prompt: guide }       # 个性化导读和 3 个引导问题（第 12.7 节）
  evaluate:    { provider: main, model: STRONG_MODEL, prompt: evaluate }    # 评价用户的回答卡片
  relate:      { provider: main, model: CHEAP_MODEL,  prompt: relate, daily_budget_usd: 0.2 }      # 核实论文间关系（第 12.9 节）
budget:
  daily_usd: 2.0
```

每个 `tasks.<task>` 可额外配置 `daily_budget_usd`，为非负有限数；省略或 `null` 表示仅受全局预算限制，`0` 暂停该任务的新调用。任务限额与全局限额同时生效，均沿 `llm_call` 按 UTC 自然日统计，包含已报告用量的失败响应；限额按任务名称聚合，不因更换模型或提供方而重置。调用开始前检查，单次响应可能使费用超过余额；不将未知费用当作已知费用，也不宣称预留了并发额度。

任务预算耗尽抛出 `Deferred`，推迟到下一个 UTC 日界，不增加 attempts，也不受外部任务最长等待期限限制；其他任务仍可继续。预算和本地前置等待会在同一事务中清除外部连续等待的起点，恢复后的首次外部 `Deferred` 重新开始计时，真正连续的外部等待仍按原期限结束。全局预算耗尽或缺模型仍停止当前阶段，同时清除本轮剩余、属于所选范围且未被调研占用的任务的外部等待起点；不改变排定时间、失败次数或完成状态。结构化调用和流式调用使用同一规则；流式对象构造时预检，真正开始每次提供方请求前再次检查，预建或重复迭代不能绕过额度。HTTP 与 SSE 沿用 `budget_exceeded` 状态，任务预算错误同时保留任务名称。模型连接测试属于独立的 `configuration_test` 用量，只受已保存的全局预算限制，不消耗任一业务任务的限额。

模型设置返回每个任务的 `daily_budget_usd`；保存草稿可通过 `task_budgets_usd` 按已选任务设置限额。未出现的键保留该任务原限额，显式 `null` 清除任务限额，未选择任务的限额不允许修改；校验拒绝布尔、字符串、非有限数及负数。只改限额不改变输入或生产者指纹，不触发任何历史重算或模型请求。

- **本机 agent 提供方**（[ADR 0005](adr/0005-local-agent-first.md)）：协议 `acp`，预设 `codex`、`claude_code`、`deepseek_harness`，也可以自定义启动命令。它实现同一个 `LLM` 接口，流程和网关不感知它是 agent：
  - agent 只当模型用：不声明文件和终端能力，权限请求一律拒绝，在应用数据目录下的空目录里开会话，有只读模式时切到只读模式，不挂 MCP。实测表明这些措施挡不住 agent 自带的读文件工具（[ADR 0008](adr/0008-agent-for-ask-only.md)），接入前要另定补充措施。
  - 常驻服务为每个提供方保持一个预热的进程；每次调用新开会话、用完关闭；同一提供方串行执行。
  - 不按 token 计价：价格记为 0，记录调用次数和估算 token，可以设每日调用上限。
  - 拾穗不安装 agent，只检测并提示安装和登录命令。
  - 只有 `ask`（边读边问）可以走 agent（[ADR 0008](adr/0008-agent-for-ask-only.md)）。其他任务（翻译、讲解、导读、评价回答和全部后台任务）由配置校验拒绝路由到 `acp`，用 API 提供方；没有配置 API 时，后台流水线的 LLM 阶段保持待处理，不报错。

```yaml
providers:
  my_codex:
    adapter: acp
    options: { preset: codex, max_calls_per_day: 200 }
tasks:
  ask: { provider: my_codex, model: default, prompt: ask }
```

- 预算用完后 LLM 任务保持待处理，第二天继续，不计失败次数；积压时**优先处理最新发现的论文**。
- 领读器中用户主动发起的操作（翻译、提问、讲解）优先于后台任务；预算用完时提示用户，可以临时追加当天额度。
- 支持国内低价模型（OpenAI 兼容接口）；领读器设置页显示每篇论文和本月的花费。
- 输出必须通过 JSON Schema 校验，失败只重试有限次。例外：`translate` 输出流式纯文本，结束后由代码校验（[ADR 0004](adr/0004-streaming-translation.md)）。
- 流式输出时，推理模型往往先思考很久才给出正文。适配器在收到思考内容时发出一次“思考中”事件（不带思考内容），界面据此显示状态，不让用户对着空白等待。
- `assess` 提示词根据当前 rubric 和研究画像动态生成，维度不写死。
- 输出语言是提示词的参数，取自配置的阅读语言，提示词文件里不写死（第 15.6 节）。
- **论文内容一律视为不可信数据**，用分隔标记包裹，提示词明确其中的指令无效。模型输出只允许填写固定字段，总分由代码计算，模型没有任何工具权限。

### 15.3 数据去向

拾穗不区分内容敏感程度，下表说明每类数据会发到哪里，供使用者自行判断：

| 数据 | 发往 | 何时 |
|---|---|---|
| 检索词、DOI、联系邮箱 | 已启用的信号源和全文来源 API | 发现、取全文 |
| PDF 文件 | MinerU 云端（使用 `mineru_cloud` 时） | 解析 |
| 标题、摘要、全文片段、研究画像、术语表 | `llm.yaml` 中配置的模型提供方 | 初筛、提取、评估、起草检索式、周报、领读器的讲解、翻译和问答 |
| 用户在领读器中的提问和选中内容 | 同上 | 边读边问 |
| 用户的回答卡片、知识库中相关概念的掌握程度和用户原话片段 | 同上 | 生成个性化导读、评价回答（第 12.7 节） |
| 两篇文库论文的提取片段和引用句；与本篇相关的用户笔记片段 | 同上 | 核实论文关系（`relate`）；导读和问答提起相关论文（第 12.9 节） |
| 无（向量在本机计算） | 只在首次使用时从模型仓库下载嵌入模型文件 | 本地向量（第 12.9 节） |
| 边读边问的内容（`ask` 走本机 agent 时） | 用户本机的 agent（Codex、Claude Code、DeepSeek Harness 等），以及该 agent 使用的模型提供方 | 边读边问 |
| 原理动画的分镜（步骤说明、原文短引用） | 配置的图像模型提供方 | 用户开启并选择 `image_gif` 渲染时 |
| 卡片内容（标题、分数、理由、短引用） | 飞书等推送渠道 | 推送 |
| 条目、笔记、PDF | 本机 Zotero，不经过 zotero.org | 加入文献库 |
| Zotero 文库条目 | api.zotero.org（仅 Web 模式） | 读取收件箱和全文 |
| MCP 查询结果 | 调用它的 agent，以及该 agent 使用的模型提供方 | agent 查询 |

### 15.4 密钥

密钥通过 `SecretStore` 读取，配置文件里只存密钥名（`credentials_env`、`optional_env`）。启动时检查已启用组件所需的密钥，日志、界面和命令输出不显示密钥。

- 安装版：在向导或设置页填写，存入系统钥匙串；领读器只显示“已设置”和末四位。
- 命令行和服务器：从环境变量读取；服务器上存入权限为 600 的环境文件，不进 git。环境变量优先于钥匙串。
- Token 会过期：适配器收到认证失败时抛 `AuthFailed` 并告警，不计入重试。

### 15.5 发布与运行形态

**先做网页版，所有形态共用同一个服务和同一套前端**：常驻服务提供本地 HTTP 接口，领读器是浏览器里的网页。桌面外壳和手机端只是换一种方式打开这个网页，不另写一套界面和业务逻辑。

| 形态 | 面向 | 内容 | 阶段 |
|---|---|---|---|
| 网页版 | 所有用户 | 常驻服务 + 系统浏览器；`litgleaner serve` 或安装包启动后自动打开浏览器 | 首先实现 |
| Windows 安装程序 | 普通用户（学生大多用 Windows） | 内含 Python 运行时、依赖和构建好的前端；双击启动常驻服务并打开浏览器 | 与网页版同期，一等支持 |
| macOS、Linux 安装包 | 普通用户 | 同上 | 随后 |
| `uv tool install litgleaner` | 会用命令行的用户 | `litgleaner serve` 启动同一个服务 | 已有 |
| 容器镜像 | 需要全天在线（飞书按钮随时可点）的用户 | 部署到服务器，通过 SSH 隧道或反向代理访问领读器 | 随后 |
| 桌面外壳（可选） | 想要独立窗口的用户 | 用系统 WebView 包住同一个网页（Tauri 等），不嵌业务逻辑 | 有需要再做 |
| 手机端 | 想在手机上读的用户 | 访问电脑或服务器上的服务（见第 16 节的触发条件），界面响应式适配 | 以后 |

- **Windows 一等支持**：路径一律用 `pathlib`，不手拼分隔符；文件名和日志按 UTF-8 读写，不依赖系统代码页；子进程（本机 agent、解析器）按 Windows 方式启动 `.cmd` 包装，退出时结束整个进程树；CI 在 Windows 上跑测试。
- **前端不依赖桌面外壳的能力**：文件选择、打开外部链接、通知都走浏览器标准能力或本地接口，这样同一套前端在浏览器、桌面外壳和手机上都能用。

- **常驻服务**（`service.py`）在一个进程里组合：领读器 HTTP 接口、定时调度、飞书长连接、任务执行器。可以在设置中开启登录时自动启动（macOS LaunchAgent、Windows 开机启动项、Linux systemd 用户服务）。
- **本地安全**：只监听 `127.0.0.1` 的随机端口；每次启动生成访问令牌，浏览器通过启动链接获得会话；检查 `Host` 和 `Origin` 头，防止 DNS 重绑定和跨站请求；改变状态的请求带 CSRF 令牌；设置严格的 CSP（为 PDF 引擎的 wasm 只放行 `wasm-unsafe-eval`，不放行 eval 和内联脚本）；模型输出一律按纯文本或经过清洗的 Markdown 渲染。
- **上手是渐进式的，没有必须走完的向导**（[ADR 0009](adr/0009-survey-read-retain.md)）：
  - 第一屏只有两个入口：“读一篇论文”（贴 DOI、链接或拖入 PDF）和“调研一个课题”（写研究背景、内容、目标）。界面语言跟随系统，可以在这一屏切换。
  - 不需要模型的功能不配置任何东西就能用：打开 PDF、选字、高亮、笔记、检索。没有配置解析服务时用不耗额度的 `pdf_text`。
  - 第一次用到模型的操作（翻译、导读、提问、调研里的初筛）在原地引导配置：选模型提供方（推荐免费或低价模型，也可以填 OpenAI 兼容的本地网关地址）、填 key、测试连接并估算花费，配好后继续刚才的操作。
  - 本机 agent、飞书、Zotero 不在上手流程里，放在设置页，并在相关场景提示一次：第一次提问后提示可以改用本机 agent（先 API、后 agent 的顺序不变，[ADR 0008](adr/0008-agent-for-ask-only.md)）；第一次收到推荐后提示可以同时推到飞书；检测到本机 Zotero 时提示可以同步。每条提示都可以关掉不再出现。
- **密钥**：安装版通过 `SecretStore` 存入系统钥匙串（macOS 钥匙串、Windows 凭据管理器）；命令行和服务器部署继续用环境变量。配置文件里只存密钥名。
- **升级**：启动时检查新版本并提示，不自动安装；升级后先自动备份，再执行数据库迁移。
- **代码签名**：macOS 发布包需要 Developer ID 签名和公证，Windows 发布包需要代码签名证书，否则系统会拦截或警告。

### 15.6 语言

论文语言、读者的语言都不写死（[ADR 0009](adr/0009-survey-read-retain.md)）。配置里有两个语言：

```yaml
language:
  ui: zh-CN        # 界面语言；默认跟随系统
  reading: zh-CN   # 阅读语言：译文、讲解、卡片、导读、评价、推送卡片的输出语言；默认同界面语言
```

- **模型输出**：阅读语言作为参数传给提示词。输出语言计入提取、评估、讲解、导读等派生物的输入指纹；改阅读语言不自动重做，由 `stale` 列出（第 2 节的原则）。作者原话始终保留原文，不翻译后冒充原话。
- **翻译**：目标语言是阅读语言（`translation.target_lang`）；论文语言与阅读语言相同时跳过翻译。
- **术语和概念**：术语表按“原文术语 + 目标语言译名”存储，概念的规范名用原文术语，各语言的译名存为带语言标记的别名（第 5、7.1 节）。
- **界面文案**：`web/` 的文案集中在按语言分的消息表里，组件里不写字面文案；类型检查保证每种语言的键一致。不引入多语言库。提供简体中文和英文两种界面，中文先做。
- **服务端的消息**：返回给界面的错误带稳定的错误码，文案由前端消息表给出；日志保持一种语言。
- **与地区有关的功能**（飞书、GB/T 7714、期刊分区导入）都是可选的适配器或用户导入的数据，核心流程不依赖它们。
- 章节识别的规则（第 9.2 节）目前覆盖英文和中文论文。其他语言的论文识别不出标准章节时按 `degraded` 处理，仍然可以阅读和翻译。

## 16. 防止代码腐化的机制

规则要靠工具执行，不靠自觉：

| 风险 | 机制 |
|---|---|
| 依赖方向被破坏 | `import-linter` 契约 |
| 流程代码出现具体厂商名 | `tests/architecture/`：`application`、`ports` 中出现信号源、解析器、大模型厂商、飞书、Zotero、BabelDOC 等名字就失败 |
| 适配器行为不一致 | `tests/contracts/` 统一契约测试，新适配器必须通过 |
| 外部 API 变化不被发现 | 录制响应做回放测试；线上 `SchemaChanged` 告警 |
| 配置拼写错误或默默失效 | Pydantic `extra="forbid"`，`litgleaner doctor` 启动自检 |
| 数据库结构漂移 | Alembic 迁移，禁止手动改表 |
| 数据被意外修改 | 领域模型不可变（frozen），`feedback` 等记录只追加 |
| 文件和函数膨胀 | 文件不超过 400 行，函数不超过 50 行（`tests/architecture/` 检查） |
| 语言被写死 | 前端各语言消息表的键由类型检查保证一致；`tests/architecture/` 检查提示词文件不含写死的输出语言（第 15.6 节） |
| 决策失传 | 本文档 + `docs/adr/` |
| 回归 | 单元、契约、集成、E2E 四层测试，覆盖率不低于 80%；第 17 节的变更场景写成 E2E 测试 |

**故意不做**（以及什么时候才做）：

| 不做 | 原因 | 触发条件 |
|---|---|---|
| 微服务、消息队列 | 单人单机，SQLite 队列足够 | 需要多机并发处理 |
| PostgreSQL | 写入集中在一个服务进程，SQLite 足够 | 需要多用户共享或多机写入 |
| 向量数据库 | 个人文库几千篇以内，向量存在 SQLite 里、在内存中逐个计算就够（本地向量见第 12.9 节，ADR 0010） | 文库规模让逐个计算明显变慢 |
| 动态插件加载 | 显式注册表更容易调试 | 需要第三方安装插件 |
| 公开的网页服务 | 领读器只在本机 `127.0.0.1` 提供，数据不出本机 | 要做登录、评论或多人协作；或者开始做手机端（手机要访问电脑或服务器上的服务，需要先设计配对和鉴权） |
| 支持多种数据库 | `ports/store.py` 的接口只用来维持依赖方向 | 出现第二种实现 |
| 给切分器抽象接口 | 只有一种实现 | 出现第二种实现 |
| MCP 写入工具 | 写入要经过反馈和调度，保证幂等和可追溯 | 有明确的 agent 写入需求，并先设计权限 |
| 多语言库、简体中文和英文之外的界面语言 | 带类型检查的消息表足够；其他语言没有用户 | 有人提供并愿意维护某种语言的消息表；或文案需要复数、性别等语法处理 |
| 知识库与外部笔记软件双向同步 | 会出现两个真相；单向导出已经能把数据带走 | 有明确需求，并先设计冲突处理 |

## 17. 用变更场景检验架构

| 场景 | 需要改动的地方 | 不用动的部分 |
|---|---|---|
| 新增 Scopus 信号源 | 1 个适配器、`bootstrap.py` 注册表、`sources.yaml`、录制数据 | 流程、评分、推送 |
| 下线某信号源 | `sources.yaml` 一行 | 其他全部 |
| 调权重 | rubric JSON，执行 `rescore` | 代码；不产生 LLM 费用 |
| 新增评价维度 | rubric JSON，执行 `reassess` | 代码 |
| 新增研究目标 | 主题 YAML 的 `goals`，执行 `activate`，按需 `backfill` | 已有 PDF、解析结果、提取内容 |
| 新建研究画像 | 主题 YAML，`topic draft` 起草检索式，`activate`，`topic survey` 做一次调研 | 代码 |
| 调整调研的轮数、每轮上限或覆盖度阈值 | 配置；覆盖度和阅读路线的纯函数 | 信号源适配器、初筛和评估 |
| 用户添加一篇没有研究画像对应的论文 | 不用改：走 `inbox` 和事实层 | 判断层；之后建了画像再显式 `backfill` |
| 增加一种界面语言 | `web/` 加一份消息表 | 组件、后端 |
