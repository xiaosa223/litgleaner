# 知识库事实后端

概念全局共用一份，保留原文术语；课题筛选来自出现过该概念的论文关联。登记在正常提取流程中完成，复用这一次 `extract` 调用，不再单独调用模型。

提取结果新增 `key_concepts` 数组，每项包含 `name`、`role`（`core` / `prerequisite` / `mentioned`）、`definition` 和零基 `page`。没有原文定义时 `definition=null`。概念名必须确实出现在指定原页以及实际发送的正文中；定义还须通过原页与清洗后发送内容的原话核验。没有通过核验的定义只保留在提取记录中，知识事实与检索不把它作为作者原文。

发送正文的保守预算包含标题、摘要、页标记和实际片段；长串无空格文本不能绕过限制，超长元数据也会截取。记录的来源片段与实际发送的连续原文一致，未发送的术语和定义不能登记为已核验事实。原文核验确认引用存在于解析文字；概念作用和定义选择来自模型，关键数字及公式以 PDF 为准。

原文术语经 Unicode NFKC、大小写和空白归一后精确匹配别名。匹配到已有概念则复用；没有匹配才创建概念。不会凭语义相近自动合并缩写、同义词或不同概念。别名语言未知时保留空值，不把阅读语言当作论文术语的语言。

`concept_occurrence` 保存概念、论文、作用、原文定义、零基页码、真实解析块的 `bbox`、核验状态和提取指纹，同篇同概念只登记一个位置。登记与提取在同一事务中，重复执行保留已有事实。新提示词使旧提取标记过期，旧论文不自动重提取，也不为补齐概念发生额外费用。

| 接口 | 返回内容 |
|---|---|
| `GET /api/knowledge/concepts` | `items`、完整 `total`、`limit`、`offset`；每项含 `concept`、`aliases`、出现论文数 `papers` 和一个已核验 `definition`（可为空） |
| `GET /api/knowledge/concepts/{concept_id}` | `concept`、`aliases`、所有 `occurrences`，含论文标题、页码、原文坐标、来源与 `stale` |
| `GET /api/papers/{paper_id}/concepts` | 本篇论文的概念及其出现位置 |

列表支持 `q`、`topic_id`、`limit=1..200`（默认 50）和非负 `offset`。名称、别名与已核验定义通过本地 FTS5 检索，兼容短中文；按名称和 ID 稳定分页。查询不调用模型，预算耗尽或没有配置提取模型时仍可读取已有事实。

定义的 `authorship` 为 `author`，保留作者原文；出现位置中的 `definition_authorship` 在没有已核验定义时为空。读取时会根据当前文档、切分规则、阅读语言与提取提示词计算 `stale`，只提示来源版本有变化，不重算。全局 `/api/search` 返回 `kind=concept`，保留对应论文与真实页码，前端搜索可以跳到该页。

接口沿用本地会话、Host/Origin 保护。知识库界面仍为预览，尚未接这些事实接口；此段不返回掌握程度、复习日期或用户回答。后续导读、回答卡片、掌握程度、复习和用户确认合并随独立模块接入。

2026-11-11 本地验收：后端全量 1671 项通过，覆盖率 94.41%；Ruff、格式、Mypy 195 个源文件和三项依赖契约通过。前端 29 项测试、类型检查及构建通过；独立审查的 198 项定向回归和 7 项预算补验通过，无剩余阻断。测试使用模拟模型与临时数据库，未做真实模型或浏览器验收。
