# API 边读边问

问答使用 `ask` 任务，可通过模型设置接口配置，也可在 `llm.yaml` 中显式加入：

```yaml
tasks:
  ask: {provider: main, model: YOUR_MODEL, prompt: ask}
```

目前使用结构化 API 输出。提问后保存用户原文并排队，由常驻服务优先执行按需任务；只查历史、状态或重复提交相同请求不会调用模型。命令行可用 `litgleaner run --stage ask` 处理待答问题。

| 接口 | 用途 |
|---|---|
| `POST /api/papers/{paper_id}/qa` | 提交问题，返回 202 和问题记录、状态；接收 `text`、`request_id`，可带 `selection` 和零基 `page` |
| `GET /api/papers/{paper_id}/qa` | 返回最近 50 个问题及答案，按时间、ID 正序；`limit` 可设 1–200 |
| `GET /api/papers/{paper_id}/qa/{question_id}` | 查询单题状态和答案 |
| `POST /api/papers/{paper_id}/qa/{question_id}/annotation` | 答案完成后保存关联批注：`body` 只存用户提问，`quote` 保留核验过的作者原文，`qa_question_id` 关联完整模型答案 |

接口沿用启动会话、Host/Origin 和 CSRF 保护。调用方为每次新提问生成唯一 `request_id`，网络重试时沿用。相同论文、相同请求 ID 和内容返回原问题；同一请求 ID 用于不同内容时拒绝。问题和答案只追加，已保存答案不会因任务重复执行而重新计费。

## 来源与回答证据

新问题的上下文可包含本篇原文、文库内相关论文、当前有效的已核实关系，以及用户批注和历史问题。来源在完整消息中明确区分：

| 来源 | 内容与版本 | 回答引用 |
|---|---|---|
| `author` | 指定论文、文档和零基页码的连续原文 | `citations`：`paper_id`、`page`、`quote` |
| `note` | 有效批注的用户正文，以完整规范记录的哈希冻结版本 | `note_citations`：`paper_id`、`source_id`、`kind: "note"`、`quote` |
| `question` | 用户历史问题原文，以完整规范记录的哈希冻结版本 | `note_citations`：`paper_id`、`source_id`、`kind: "question"`、`quote` |
| `model_backgrounds` | 当前有效提取的 `summary`、`problem`、`approach` 片段，冻结提取 ID、输入、生产者及内容指纹 | 仅作模型背景，不接受为作者原文或用户引文 |

批注中的作者原文 `quote` 不作为用户笔记正文；模型回答也不参与用户来源召回。没有页码的笔记保留无页码状态，不伪造 PDF 位置。

回答由 `statements` 组成，每项包含 `text`、`citations`、服务端算出的 `inference`、`note_citations` 和 `mentioned_paper_ids`。每条引文必须同时存在于当前规范源、单个实际发送的连续片段，以及清洗后完整 JSON 的对应来源中。作者引文还须匹配同一论文的原页；相同页码不能借用另一篇的文字，多个独立片段不能拼成一条引文。

提及外部论文时，模型通过 `mentioned_paper_ids` 和 `[[paper:<id>]]` 明确身份；该陈述的每篇外部论文都必须由该论文的有效作者原文或用户引文覆盖，缺少任何一篇时整条丢弃。实际发送的外部论文 ID 或完整标题出现在陈述中但未声明，也会拒绝；这项检查针对明确身份，不能保证识别所有未写身份的自然语言暗示。本篇无有效依据的陈述保留为 `inference=true`。全部陈述被丢弃时，保存对应阅读语言的服务端“证据不足”结果，任务正常完成，重试不再次收费。

引用核验只能证明引文存在于解析文字或规范用户记录，仍需以 PDF 原文核对关键数字和公式。

关联批注保留问答的结构化来源：通过 `qa_question_id` 查询本篇单题接口即可读完整回答。模型回答继续只按模型来源进入检索，不复制进“用户笔记”的索引。用户编辑批注正文不会改写原问题或模型答案。

状态包括 `queued`、`retrying`、`done`、`failed`、`configuration_required` 和 `budget_exceeded`。新问题缺模型时返回稳定的 `model_configuration_required`，不写入问题或任务。预算耗尽时保留 pending，恢复预算后继续。模型费用按论文记录，提供方已报告用量的失败响应也计费。

## 有界混合召回

选区及本篇原文优先，所在章节和页码参与词法排序。FTS 先限定当前论文或仍在文库的论文、来源类型和作者身份，再读取最多 64 个完整来源候选并核对当前版本；模型回答及提取摘要不作为作者原文或用户笔记命中。最多取三条业务状态有效且当前证据完整可核验的关系，携带双方原文；已过期或无法完整核验的关系跳过并说明。

FTS 的查询与搜索副本共用[统一字形协议](SEARCH.md)，支持全角、`ß` 及组合字符。召回后仍使用真实原文核对规范笔记、问题和原页，保留既有来源版本与冻结消息；规范化后相等的伪造索引不能通过逐字核验。

已就绪的[本地向量](LOCAL-EMBEDDINGS.md)可计算临时问句向量，从有效论文缓存召回最多五篇正相似度论文，并重排最多 64 个原文候选；词法、有效 FTS 分数及非负余弦共同影响顺序。没有资产、关闭向量、模型身份变化或推理失败时给出降级说明，词法、FTS 和有效关系继续工作。提问准备不下载模型、不隐式重算或写入论文向量，也不调用收费模型。

全部来源共用两百万字符、四千个来源的扫描上限。完整系统提示、问题、选区、画像、论文身份和标题、关系、笔记、模型背景及清洗后 JSON 与隔离包装合计按保守估算限制为 **4000 token**。为可用记忆保留有界份额，外部来源按完整条目取舍。选区必须存在于指定页且完整放入预算，否则拒绝提交并要求缩小范围。同一文档在一次准备或复核中只读一次；坏归档按论文隔离。

## 冻结、复核与历史

新问题排队时冻结实际系统提示、清洗后的完整消息、研究画像、阅读语言、切分版本、主论文全文内容指纹及实际发送来源。请求生产者指纹包含记忆协议、输出 schema、提示词、请求模型和提供方；问题与任务按 `request_id` 同事务幂等保存。实际发送的来源、论文标题、关系摘要和模型背景必须与冻结清单对应。

执行分三轮复核：

1. 调用模型前读取一致快照，检查配置、完整消息及规范来源；发现变化或无法完整核验时要求重新提问。
2. 模型返回后读取新快照，重新读取已发原文并核对笔记、问题、关系和提取版本，再逐条校验回答引文。
3. 保存前在短事务中重读所用规范行与配置指纹，阻止复核后发生的记录变化；文档读取位于写锁之外。

新增未选中的笔记、问题或关系不会扩张旧问题。已使用来源被编辑、软删除、退出文库，或所用关系被拒绝、替代及证据过期时，需要重新提问。已有历史答案继续可读，不自动重做。

新答案保存完整 `context` 和 `request_producer_version`，任务清理后仍可独立核验。统一 [`stale`](STALE.md) 使用固定 **18 次 SELECT** 的批量快照，包括当前有效批注；事务外核验，不逐答案补查或进行向量推理。新答案指纹与证据完整且匹配时可为 `current`；旧答案缺少完整请求生产者时保留 `unknown`，已知失配仍优先标为 `stale`。

问答继续分别按用户和模型身份进入全局 FTS 检索。阅读页问答组件、自动多轮上下文、本机 agent 通道，以及尚无规范源表的回答卡片和可编辑读后卡片仍待接入；全局搜索的向量混合排序也属于独立范围。

本功能使用隔离数据库及离线适配器验证；当前验收记录见 [ROADMAP.md](ROADMAP.md)。真实模型的记忆回答质量、真实嵌入模型效果、真实钥匙串、浏览器交互及 Windows 真机仍待实测。
