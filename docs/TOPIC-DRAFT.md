# 新建课题与起草检索式

研究者在领读器里写下课题名称、研究背景、研究内容和研究目标，系统据此新建研究画像；再由 `draft` 模型任务起草英文检索词、排除词和术语表，每个词附选择理由。草稿不会自动生效，研究者逐条修改后确认，才写入主题文件并启用课题（ARCHITECTURE 第 7.1、7.2 节）。

## 流程

1. **新建课题**：`POST /api/topics` 只写主题文件，不启用、不调用模型。此时课题没有检索词，状态为 `new`，课题页默认打开“检索词”标签。
2. **起草**：预览（只读、不联网、不调用模型）→ 携 `plan_hash` 确认 → 按需队列调用一次模型 → 草稿写到 `<id>.draft.yaml`。
3. **确认**：研究者在“检索词”标签修改后保存。`PUT /api/topics/{id}/query` 写入主题文件的 `query` 和 `<id>.glossary.yaml`。从未启用过的课题随之启用；已暂停的课题保持暂停，保存不会让它重新开始花钱。启用只影响之后发现的论文，历史论文仍需显式 `topic backfill` 或课题调研（第 7.3 节）。

已有检索词的课题也能重新起草；编辑表保留当前检索词，“用草稿替换”需要研究者显式点击。起草完成时如果研究者已经改过编辑表，也不覆盖，只提示可以替换。

## 接口

所有接口需要本机会话，改变状态的请求还需要 `X-CSRF-Token`，请求体拒绝额外字段。

| 方法与路径 | 用途 |
|---|---|
| `GET /api/topics` | 全部课题（含未启用）：`id`、`name`、`goals`、`status`（`active`、`paused`、`new`）、`terms`（检索词与同义词个数） |
| `POST /api/topics`，`{name, background, content, goals: [文本]}` | 新建，返回 `{id}` |
| `POST /api/topics/{id}/draft/preview` | 费用估计、是否命中已有草稿、可用和缺失的种子论文、当前检索式 |
| `POST /api/topics/{id}/draft`，`{"plan_hash":"..."}` | 核对指纹后幂等排队 |
| `GET /api/topics/{id}/draft/jobs/{job_key}` | 任务状态、草稿、费用、错误 |
| `GET /api/topics/{id}/draft` | 最近的草稿、是否过期、当前检索式和术语表 |
| `PUT /api/topics/{id}/query`，`{include: [{term, synonyms}], exclude, glossary: [{forms, translation, definition}]}` | 写入，返回 `{id, terms, status}` |

## 新建课题的规则

- 名称、背景、内容和至少一个目标都必填；名称不超过 100 字，目标不超过 20 个，空白目标丢弃。目标按顺序编号 `g1`、`g2`……
- 课题编号就是文件名：纯英文名转成小写连字符形式（最长 40 字符）；含其他文字时用 `topic`。重名时加 `-2`、`-3`；Windows 保留名（`con`、`nul` 等）前加 `topic-`。
- 评价指标用 `default`，没有时用按名称排序的第一个。期刊集、种子论文为空，公开设置为否。
- 文件先写临时文件再以硬链接落位，已有同名文件时失败，不覆盖、不留下写了一半的文件；不支持硬链接的盘（exFAT、部分网络盘）退回独占创建。写出的文件权限与手写的相同（0644）。写入失败返回 500 `topic_save_failed`。

## 起草的输入、费用与缓存

- 发给模型的是研究画像（背景、内容、目标）、当前检索式，以及最多 10 篇种子论文的标题和摘要前 1500 字。种子论文只取**已在文库里**的 DOI，不联网；不在文库里的列在预览的 `seeds_missing`。
- 种子论文的标题截到 300 字。种子论文内容可能含有诱导性文字，提示词把它当数据处理，输出过 JSON Schema 校验；最终由研究者逐条确认。
- `plan_hash` 覆盖课题编号、画像、当前检索式、全部输入、模型和提示词版本、阅读语言。任一变化后旧预览不能确认；队列执行前按当前状态重新计算，不一致时任务失败、不调用模型，所以同一课题先后确认两份计划时只有最新的那份会花钱。
- 失败的任务、或草稿文件被删掉的已完成任务，用同一计划再次确认会重新排队。
- `estimated_usd` 是 `draft` 任务单次历史费用均值；没有历史时为 `null`，命中已有草稿时为零。命中时确认直接完成，不调用模型。
- 没有配置 `draft` 路由时，确认返回 409 `model_configuration_required`，界面原地弹出模型配置。

## 草稿的校验与过期

- 模型输出须满足 JSON Schema：检索词 1–20 个，每个附理由和至多 8 个同义词；排除词至多 20 个；术语至多 60 条。
- 代码再清理：检索词和同义词不分大小写去重，与检索词重复的排除词去掉并记警告。
- 草稿依据的背景、内容、目标或阅读语言变化后标记过期（`stale`），界面提示可以重新起草；只改检索式不会让草稿过期。
- 草稿文件读不出来时当作没有草稿，记日志，不报错。

## 确认写入

- 检索词去重后至少一个；排除词与检索词或同义词重叠时拒绝（`query_invalid`）。术语表译名留空的行由界面丢掉。
- 主题文件的内容必须和服务运行中的定义一致，被手改过时拒绝（`topic_changed_on_disk`），刷新后再改。写入前主题文件和已有术语表各保存一份 `.bak`；先写术语表、最后写主题文件，主题文件写失败时术语表还原。写入后的文件格式与手写的相同，原有注释不保留。
- 术语的多个原文写法（`forms`）原样保存；界面里用逗号分隔。只填了原文或只填了译名的行，界面要求补全或删除，不静默丢弃。
- 术语表以当前阅读语言为目标语言整份替换。术语表变化不会自动重译已有译文（第 7.1 节）。

## 检索词命中篇数

“检索词”标签的“查每个词能搜到多少篇”按编辑表里**还没保存**的词查，不调用模型、不写文件。

- `POST /api/topics/{id}/term-counts`，`{include: [{term, synonyms}], exclude}`，返回 `{source, since, until, counts: [{term, hits, error}]}`。
- 每行（检索词连同同义词，加上全部排除词）向支持 `TermCount` 的来源发一次检索，窗口是到今天为止的 365 天；这正是日常跟踪每天要初筛的量。某一行查失败时只这一行 `hits` 为 `null`、`error` 为 `source_unavailable`，其余照常；被限流时剩下的行不再请求，总时长超过 60 秒后剩下的行也不再请求，都标为 `source_unavailable`。任何一行不合法时整个请求返回 422 `query_invalid`，一次检索也不发。
- 没有支持计数的来源时返回 422 `term_count_unavailable`；目前只有 OpenAlex 支持（[SOURCES](SOURCES.md)）。
- 界面按大致经验线解读：0 篇提示检查拼写；少于 50 篇提示偏窄；超过 20000 篇提示很宽（日常跟踪会送来大量论文去初筛，费用和无关论文都会多）。篇数已去掉含排除词的论文，不同检索词搜到的论文会有重叠，不能相加；其余显示篇数和每天约几篇。改了这一行或排除词后旧篇数隐藏。
- 起草草稿时不自动查篇数，由研究者点按钮查，避免每次起草都发一串检索请求。

## 课题设置：修改描述、启用与暂停、重新筛选

课题页的“课题设置”标签，与命令行 `topic activate`、`topic pause`、`topic backfill` 等价（第 7.3、12.8 节），都不调用模型。

| 方法与路径 | 用途 |
|---|---|
| `GET /api/topics/{id}` | 名称、背景、内容、目标、状态、检索词个数 |
| `PUT /api/topics/{id}/profile`，`{name, background, content, goals: [{id, text}]}` | 修改研究描述，返回保存后的定义和 `changed`：`{topic, changed}` |
| `POST /api/topics/{id}/activate`、`/pause` | 启用、暂停，返回 `{id, status}` |
| `POST /api/topics/{id}/backfill/preview` | 还没按当前定义初筛的文库论文篇数、初筛费用估计、`plan` |
| `POST /api/topics/{id}/backfill`，`{"plan":"..."}` | 核对后排队初筛，返回 `{queued}`；没有配置 `triage` 路由时返回 409 `model_configuration_required`，界面原地弹出模型配置 |

- **修改描述**：已有目标带原编号提交，编号保留（评估里的目标关联靠它）；新目标 `id` 为 `null`，接着现有最大的编号往后排；编号对不上时拒绝（`topic_goals_invalid`）。以前删掉的最大编号可能再次被用到，但评估、阅读路线和综述提纲都按 `topic_hash` 区分，改目标后旧结果不再显示，不会挂到新目标上。界面在请求返回前不会再发第二次保存。检索式、术语表、评价指标不变，术语表文件不动。与起草检索式相同：文件被手改过时拒绝，写前留 `.bak`。
- `changed` 表示背景、内容或目标变了（`topic_hash` 变化）；只改名称时为否，判断不失效。启用中的课题立即换成新定义，之后发现的论文按它初筛，`triage_from` 从此刻算起；暂停的课题保持暂停。确认检索式时同样如此。描述变化会让已有的检索式草稿标记过期。
- **启用**：没有检索词时拒绝（`topic_query_missing`）。启用、暂停和修改定义在服务里互斥，状态里记的总是当前定义的指纹。启用和恢复只处理之后发现的论文；暂停期间不检索这个课题，补上这段时间要再做一轮课题调研。
- **重新筛选**（回填）：只对启用中、状态与当前定义一致的课题（否则 `topic_not_active`）。范围是整个文库里还没按当前定义初筛的论文，不限日期（命令行可用 `--since`）。费用只估初筛；通过初筛的论文之后照常取全文、提取和评估，另算费用，界面写明这一点。`plan` 覆盖当前定义和待筛论文列表，之间有变化时拒绝（`plan_changed`），重新预览。
- 还不能在界面里向支持历史查询的信号源补查（第 7.3 节），也没有 `rubric reassess` 的界面入口。
