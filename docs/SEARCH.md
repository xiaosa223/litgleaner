# 本地混合检索

全局检索使用 SQLite FTS5，覆盖论文元数据、已归档全文、用户笔记和高亮、模型提取、问答及概念。结果保留论文、零基页码和作者／用户／模型身份，显示真实原文摘句。

```http
GET /api/search?q=Straße&limit=30
```

`q` 最多 500 个字符，空查询返回空结果；`limit` 默认为 30，可设为 1–100。接口沿用本地会话及 Host／Origin 保护。返回 `hits`，每条包含 `kind`、`id`、`paper_id`、`title`、摘句 `text`、`page` 和 `authorship`。

响应还提供 `mode`（`lexical` 或 `hybrid`）、`protocol`、`model`、`query_hash`、逐结果 `signals` 及有界 `warnings`。已有调用方可以继续只使用 `hits`。

## 向量补充相关论文

FTS 继续检索全库，包括尚未进入文库的元数据。模型已就绪且文库存在当前有效的[本地论文向量](LOCAL-EMBEDDINGS.md)时，搜索额外计算一次临时查询向量，与文库缓存比较。查询从原始文字执行 NFKC 和空白压缩，再按嵌入字符上限取前缀；禁止下载模型，不保存查询向量，不重算论文，也不排队。没有可用缓存时连临时推理也不执行。

向量可以补充没有词法命中的相关论文。这些结果使用真实论文标题、摘要和作者元数据身份，`kind="paper"`、`id=paper_id`、`page=null`。论文级余弦只给论文元数据加分；正文、笔记、问答及其他来源保留自己的词法信号和原页。相似度用于找论文，不能据此宣称论文之间存在已核实关系。

初始协议为 `global-search-hybrid-v1`，每次读取最多 512 条词法候选：

- 词法贡献为原始 BM25 相反数除以候选池中的最大值；全部为零的短词命中取 1。
- 向量贡献为论文余弦的非负部分，两项权重均为 1，总分为两项之和。
- 同一 `(kind,paper_id,id)` 合并最强信号，不同来源独立保留。按总分降序、原 BM25 升序（缺席按 0），再按种类、论文 ID、来源 ID 升序排列，最后取 `limit` 条。

`signals` 保留原始 `bm25/cosine`、两项贡献、总分及实际向量输入指纹。分数是本次候选池内的初始排序值，效果与权重仍需真实论文案例校准。

推理前后及融合返回前核对模型身份和 float32 输出。关闭、资产未就绪、无当前缓存或推理失败时，词法结果的内容与顺序保持，诊断说明降级；坏向量逐论文排除。快照中嵌入数据无法转换时，也保留词法候选。诊断最多展示 32 条，再附省略说明，不返回异常里的私有路径。

词法和向量的独立快照在同一短事务中固定读取 **5 次 SELECT**；转换、有效性投影和推理均在事务外完成。结果对应本次一致快照，不逐论文补查。全局入口仍先检查旧归档是否缺索引；全部就绪时，该检查另有 1 次读取，因此整个请求通常为 6 次读取。缺索引时沿原路径补齐。已有相似度、事实、候选、阅读摘要和 `stale` 的窄查询合同保持。

## 字形匹配与原文

查询和搜索副本使用同一协议：**NFKC → casefold → 压缩空白**，每份原始文字只执行一次。例如：

| 原文或查询 | 搜索字形 |
|---|---|
| `ＴＲＡＮＳＦＯＲＭＥＲ` | `transformer` |
| `Straße` | `strasse` |
| `Cafe` 加组合重音 | `café` |
| 分离的 Hangul 字母 `가` | `가` |

规范化后先拆词，再区分长短词：三字及以上用 trigram，短词通过搜索副本做字面匹配。全局词法查询要求所有词命中；[问答](QA.md#有界混合召回)与[论文候选](MEMORY-CANDIDATES.md)保留各自的 OR 召回及来源限制。概念检索也使用同一搜索副本。用户输入按字面词处理，不能充当 FTS 运算符；无检索词时不执行向量推理。

`memory_fts` 的 `title/text` 保存原文，`search_title/search_text` 保存搜索副本；BM25 只给搜索标题和正文赋权 4 和 1。返回的标题、摘句、页码和来源版本都使用原值。摘句最多取 320 个连续原文字符，按真实原位置定位命中，兼容 `ß`、连字展开、重音重排和 Hangul 组合。

问答仍逐字核对规范笔记、问题和文档原文；搜索副本相同不能代替原文相等。已有问答的冻结消息和来源指纹也沿用原文，新增召回不会扩张已经排队的问题。

## 索引维护与升级

元数据、笔记、高亮、提取、问答和概念由数据库触发器同事务维护搜索副本；解析时写入全文块及文档完成标记。全局检索保留旧归档补索引行为：首次遇到缺标记的归档会读取本地文档并写入索引，损坏归档按论文隔离。论文候选及问答的 FTS 查询只读已有索引。索引维护不调用模型、来源 API 或嵌入器；全局混排的临时本地推理沿上节条件执行。

已有数据库通过原命令升级：

```bash
uv run litgleaner db upgrade
```

迁移 `0020` 从旧索引回填搜索副本，逐值保留原八列、行 ID、全文块、空文档标记及来源版本，不读归档。升级前沿用自动备份；重建失败会回滚，降级恢复旧八列布局及触发器。

业务与迁移连接注册确定性 SQLite 函数 `litgleaner_search_normalize_v1`。普通 SQLite 工具可以读取和备份数据库；直接修改带索引触发器的业务表时也必须注册该函数，缺失时写入会失败，防止留下不一致索引。应用写入应使用现有仓储。
