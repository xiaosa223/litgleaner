# 阅读记忆摘要

论文页在打开和回看时，可通过同一个只读接口取得最多三条当前可核验的关系、库内双向引用，以及对方论文上的用户笔记摘句。接口沿用领读器本地会话、Host 和 Origin 检查。

```http
GET /api/papers/{paper_id}/reading-memory?limit=50&offset=0
```

主论文须在当前文库内，范围沿用 [`memory-facts`](PAPER-MEMORY.md)：存在阅读状态、有效批注，或用户添加流程已完成。`queued`、`reading`、`read`、`abandoned` 均可出现；已添加但没有阅读状态的论文显示 `new`。未知或未进入文库的主论文返回 404。

`limit` 为 1–200，默认 50；`offset` 为非负整数，默认 0。参数越界返回 422。这两个参数只分页双向引用的对端，关系卡独立选取，最多三条。超过总数时 `citations` 为空，关系卡及完整总数仍返回。

## 响应字段

| 字段 | 含义 |
| --- | --- |
| `paper` | 主论文的 `paper_id`、标题与当前 `reading_status` |
| `relations` | 最多三张关系卡，每项包含原 `relation`、对方 `paper`、`direction` 和可空的用户笔记 `note` |
| `citations` | 当前页的引用对端；每项包含对方 `paper`、`cites`、`cited_by` 和可空的 `note` |
| `total`、`limit`、`offset` | 分页前完整引用对端数，以及当前引用分页参数；`total` 不计关系卡 |
| `relation_candidates` | 与主论文有关、业务状态为 `valid` 的关系候选总数，包含随后因证据或文库范围被排除的记录 |
| `relations_checked` | 本次实际核验的关系候选数，上限 64；已选满三张卡时提前停止 |
| `relations_truncated` | 候选多于已核验数量时为 `true`，表示有记录因三卡展示上限或六十四候选核验上限未检查 |
| `warnings` | 本次关系选择的诊断；每项含 `paper_id`、`code` 与 `detail`，空结果也保留原因 |

所有 `paper` 结构都来自同一快照，保留对端当前阅读状态。`relation` 仍保存原关系 ID、类型、业务状态、来源、解释、批次、双端身份、`source_hashes`、`input_hash`、`producer_version` 及真实创建时间；两侧证据分别保存在 `evidence_a`、`evidence_b` 中，含论文 ID、原文档指针、零基页码和原文。

## 三张关系卡如何选择

先排除已被替代或用户拒绝的关系，仅对业务状态为 `valid` 的记录排序：

1. 该条关系上的精确用户决定优先。
2. 同优先级先展示反向 `extends`，即对方论文扩展当前论文。
3. 再按关系创建时间降序、关系 ID 降序稳定排列。

按此顺序最多核验 64 个候选，选满三张当前完整可核验的卡即停止。这里的创建时间是关系判断的创建时间；入库顺序与更新时间也分别保留其原有含义。系统没有足够证据记录首次阅读时间，因此不会把反向扩展包装成“后来第一次读到的论文”。

卡片的 `direction` 相对主论文：`outgoing` 表示原 `paper_a` 为主论文，`incoming` 表示原 `paper_b` 为主论文；`contradicts`、`similar_approach`、`same_problem` 返回 `symmetric`。无论从哪一端查看，原 `paper_a`、`paper_b`、双侧原文和判断指纹都不翻转；引用方向也不改写成语义关系。

用户决定精确落到关系 ID：用户来源的关系，或该记录上已登记的确认、拒绝决定，按该条记录处理；改类型生成的用户关系沿其新 ID 生效。相同双端的其他模型历史和同批次其他关系不会因此获得豁免。已拒绝的记录仍受 `valid` 筛选排除。反馈接口见 [论文关系核实](PAPER-RELATIONS.md#结果缓存与反馈)。

未由用户决定的模型关系须核对原批次、冻结配置、当前输入及作者原文，原批次实际使用的全部文档都必须可读。即使卡片两端文档正常，同批次第三篇文档损坏也会使该模型关系无法完整核验；不依赖该损坏文档的独立批次继续核验。用户确认或用户来源关系可豁免模型批次及其配置检查，两端是否仍在文库、当前来源指纹与指定页原文依旧核对。

## 用户正文摘句

每个对端最多附带一条 `note`，关系卡与引用对端使用同一选择规则：只看当前有效批注的非空用户 `body`，按 `updated_at`、批注 ID 降序取最新一条；最新批注正文为空时继续找较旧的非空正文。高亮可以有用户正文，但作者 `quote` 和模型回答不会被拿来补成用户笔记。

| `note` 字段 | 含义 |
| --- | --- |
| `source_id`、`paper_id` | 规范批注 ID 与所属论文 ID |
| `text` | 首个非空行内的连续前缀，最多 240 字符；保留原文，不拼接多行、不改写或插入省略号 |
| `page` | 批注原有的零基页码，缺失时为 `null`，不从作者引用或其他记录补造 |
| `source_version` | 对完整规范批注记录计算的稳定内容哈希；正文尾部或其他出处字段变化也改变版本 |
| `truncated` | 该行超过长度上限，或其后仍有其他行时为 `true` |
| `authorship` | 固定为 `user`，明确这是用户正文 |

没有有效非空用户正文时 `note` 为 `null`。批注编辑或删除在下一次查询反映，不沿用缓存摘句。

## 双向引用与分页

每个当前文库对端只占一个 `citations` 项，按对端论文 ID 升序稳定分页：

| 字段 | 方向 |
| --- | --- |
| `cites` | 本篇引用对方，保留该方向的全部原始 `Citation` |
| `cited_by` | 对方引用本篇，保留该方向的全部原始 `Citation` |

自连与非文库对端被排除；与主论文没有直接引用关系的论文不出现。多个来源、位置和重复证据不合并或互相覆盖，原始 `source`、`source_position`、`raw_text`、`contexts`、`intents`、`influential`、创建时间、页码及坐标均保留。

已保存的 `cited_paper_id` 沿用既有事实。动态别名关联按全库唯一精确身份及最终全局接受的目标分组计算，库外冲突同样阻止误连；跨记录别名链最终指向多篇论文时，该动态边不进入摘要。无歧义的传递关联仍可连接到当前文库对端，不按同名标题猜测目标。

## 无法完整核验与警告

业务状态 `valid` 与证据状态分开。卡片只展示证据状态为 `current` 的记录；已知失配为 `stale`，没有已知失配但缺少核验条件为 `unknown`，后两种记录均通过警告说明并排除。响应没有单独的顶层 `status` 字段。

| `warnings[].code` | 含义 |
| --- | --- |
| `relation_outside_library` | 关系对端已退出文库，不展示该卡 |
| `relation_stale` | 当前来源、原页、策略或生产者配置与原判断存在已知失配 |
| `relation_unknown` | 缺少原批次、完整冻结信息、可读文档或当前生产者核验条件，无法确认完整有效 |
| `relations_omitted` | 达到三张卡或六十四候选核验上限，尚有候选未检查 |

`detail` 保留具体原因。缺少当前 `relate` 或提取模型路由时，已有未确认模型判断可能无法完整核验；系统不会为 GET 临时配置模型或执行任务。用户精确确认的关系仍按上述豁免规则检查其当前两端证据。没有有效关系或没有引文时可返回空数组，不补造关系或来源。

## 一致读取与执行边界

一次请求固定 **11 组 SELECT**：复用事实查询的八组结果，追加主论文相关关系、所需原核实批次和当前有效用户批注。批次使用到的文档指针同批读取；短事务结束后转换领域对象、投影引用并核对归档原页，不逐关系补查数据库。同一归档在一次请求中至多读取一次，读取失败也缓存，失败范围限于依赖该文档或原批次的关系。事实、候选和统一历史过期报告保持各自独立快照合同。

GET 不写数据库、队列或归档，不补抓来源，不生成回答或关系，不执行向量推理、不下载模型，费用为零。可以读取已配置模型的 `describe` 描述元数据来核对生产者配置；这不会执行生成请求。笔记编辑、文库退出和关系反馈在下次查询直接反映，不缓存派生摘要。

读取摘要不登记打开、不改变阅读状态。首次打开仍通过独立的 [`POST /api/papers/{paper_id}/open`](PAPER-RELATIONS.md#自动处理与历史保护) 完成。阅读页界面接线与验收进度见 [ROADMAP](ROADMAP.md)；问答实际发送的冻结记忆与证据规则见 [QA](QA.md)。
