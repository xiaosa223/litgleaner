## 实施顺序

每一步都要能运行和验证，不做只有框架的空壳。

1. ~~**备份**：`backup`、`restore --check`、升级前自动备份。在启用真实飞书反馈之前完成。~~ 已完成。
2. ~~**修正已知差异**：上表各项。~~ 已完成，剩余部分留在上表，随对应步骤处理。
3. **领读器设计研究**：
   - 拆解 Semantic Reader 的几个原型（ScholarPhi、Paper Plain、Scim、CiteSee）和常用产品（Zotero 阅读器、小绿鲸、沉浸式翻译、alphaXiv）。
   - 输出 `docs/experiments/` 下的设计参考：每个功能借鉴什么、避开什么。
4. **低保真原型**：可点击的网页原型，用解析器对比的 4 篇样本论文做内容，找 3–5 名研一做出声思考测试，修改信息结构。
5. **领读器可用版本**（5a 服务和阅读骨架、5b 按需翻译已完成，余下按 5c 背景卡和章节导读、5d 分面高亮、5e 边读边问、5f 读后卡片、5g 自动检查的顺序）。ADR 0005、0006、0008 已接受，0007 待审阅细节。据此调整：先用 API 跑通全部 LLM 功能，全文翻译前移；本机 agent 只接边读边问，推迟到 API 跑通之后（ADR 0008）；阅读页换到 EmbedPDF + Tailwind + shadcn 重做；5c 改为个性化导读和 3 个引导问题，5f 加入回答卡片和知识库。具体顺序在动手前另行列出：
   - 常驻服务、本地 HTTP 接口、阅读页、背景卡、就地释义、分面高亮、按需翻译、边读边问、读后卡片、批注。
   - 具体顺序（2026-11-08 定）：① 后端全文翻译：段落合并、按句编号分批、占位符保护、“思考中”状态（已完成）；② 阅读页换到 EmbedPDF + Tailwind + shadcn，再做全文覆盖和双栏对照；③ 边读边问，先走 API，之后接本机 agent；④ 个性化导读、引导问题和回答卡片（等 ADR 0007 定稿）。
   - 第 12.1 节的自动检查项（引用核验率、术语命中率、打开时间）写进测试。
6. **真实用户测试**：5–10 名研一、研二，每人读一篇自己方向的论文并完成读后卡片，与他们现有的工具对比。通过门槛：
   - 完成时间比现有方式短；
   - 理解测试正确率不低于现有方式；
   - 可用性量表（SUS）不低于 70；
   - 信任问题（术语错误、无依据的回答）每篇不超过 1 次，且都能被用户识别出来。
   - 不达标时回到第 4 或第 5 步，不进入发布。
7. **研究画像**：新的主题文件字段、`topic draft`（检索词理由和命中数预估）、术语表、期刊分级导入、入门清单、本地关键词过滤。
8. **推荐理由与飞书卡片改版**：`goal_links`、作者原话与模型概括分开、去读和稍后读、全文获取途径、积压时少推。
9. **发布形态**：打包工具选型（PyInstaller 与 Briefcase 对比）、首次向导、`SecretStore`、自动启动、升级检查、代码签名。
10. **待读队列与主题周报**、**对比表、引用导出与综述骨架**。
11. **可选能力**：Zotero 同步改版（笔记导出）、双语 PDF 导出、只读 MCP。
12. **校准与运维**：校准集和 `rubric eval`、`stale`、`gc`、`replay`、`merge` 命令、告警。
13. **防漏检**：邮件提醒、手动投喂、引文追踪、覆盖率审计。
