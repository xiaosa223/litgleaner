# 提取事实与原文证据

`extract` 仍是与课题无关的一次提取，复用已有流水线和同一次模型调用。输出先经过闭合 JSON Schema，再由代码核验原文；提取、关键概念和出现位置在同一事务中保存。没有新增模型任务、数据表或自动历史重提取。

## 数据契约

`application/extraction_schema.py` 定义 `v2` 契约。所有列出的字段必填，缺少依据时使用规定的 `null` 或空数组，不从模型常识补事实。

| 字段 | 输出 |
|---|---|
| `summary`、`innovation`、兼容字段 `conclusion` | 模型概括，字符串或 `null` |
| `problem`、`prior_gap`、`approach`、`method` | `{text, quote, page}` 或 `null`；方法文本包含类别和要点 |
| `claims`、`datasets`、`metrics`、`results` | `{text, quote, page}` 数组；结果保留指标、取值、单位和实验条件 |
| `limitations` | `{text, source, quote, page}` 数组；`author` 必须有原文与页码，`inferred` 单独标明模型推断 |
| `code_data` | `{kind, availability, text, url, quote, page}` 数组；区分代码/数据和公开/不公开/未知 |
| `questions` | 恰好三个 `{question, answer}`；回答是证据对象，节选无法支持时为 `null` |
| `highlights` | `{kind, quote, page}` 数组；目标、创新、方法、结果四类原句 |
| `key_concepts` | 沿用名称、角色、原文定义及页码，见 [KNOWLEDGE](KNOWLEDGE.md) |

`claims` 字段必须返回；当前节选没有可引用结论时允许空数组，表示缺少证据。空数组不能解释为论文没有主要结论。同样，未提到代码或数据公开情况不能写成“不公开”。

页码为 PDF 零基索引。`text`、问题与回答概括使用配置的阅读语言，`quote` 保留作者原文。模型不得输出 `verified` 或高亮坐标。

## 核验规则

`application/extraction_facts.py` 同时检查：

1. 引文至少十个规范化字符，存在于指定页的解析文本。
2. 引文也存在于本次真正发送的同页连续正文及完整消息，且已清除不可信隔离标签；不同片段间的页码标记不能被去掉后拼成新引文。
3. 元数据标题、摘要头和预算外正文不能充当页证据。

核验结果由代码添加 `verified`。失败仍保留模型原记录供核对，不能作为已证实的作者事实；模型推断的局限始终保留 `source=inferred`。这种核验能证明引文在解析文本和发送范围内出现，公式、数字和模型对原句的概括仍需结合原版论文判断。

代码/数据链接另外记录 `url_verified`。只保留已核验引文、真实原页和实际发送正文中的完整 HTTP(S) 地址；猜测地址、路径大小写不符、前缀截断、凭据或控制字符等失败地址置为 `null`。此步骤不联网访问链接，不承诺远端可用性。

高亮 `bbox` 从真正包含整段引文、且已发送的原始文档块取得。缺坐标或跨块时保留 `null`，不拼出覆盖无关内容的方框。前端高亮展示尚未接线。

## 版本、费用与导出

- `input_hash` 包含文档、切分版本、阅读语言、发送预算和提取契约；缺模型配置时也能识别契约变更。
- `extractor_version` 包含契约、Schema、提示词、模型和提供方配置指纹。关键概念的生产者指纹与提取一致。
- 排队任务保存输入和生产者指纹，执行前发现变化即跳过。已有提取始终只标记 `stale`，不会被普通运行、重复任务或改配置自动重做。
- 首次提取进入死信后，`jobs retry` 会明确标记本次恢复。仅在仍无提取结果且全文状态为 `failed` 时，允许按当前配置恢复；普通自动重试不获得这项许可，已有历史不受影响。
- 归档、阅读接口和个人导出均保留新字段、原文、页码及核验状态。Markdown 按字段展示模型内容，并单独列出核验引文。
- 本模块用假模型及本地真实数据库验证；未调用真实来源、模型或系统钥匙串。统一 `stale` 命令、历史显式重提取入口、课题对比表和综述骨架另行实施。
