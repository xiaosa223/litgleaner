# 数据库备份

运行 `litgleaner serve` 时，常驻服务按配置时区每天自动生成一次数据库快照。启动后及每轮定时调度开始时检查；当天尚无已完成的自动快照，就在取得运行锁后补一份。默认调度间隔为 5 分钟，失败或运行锁被占用时留到后续调度重试。

## 目录和保留份数

```yaml
timezone: Asia/Shanghai
backup:
  # 省略 dir 时使用数据库同级的 backups/ 目录
  dir: data/backups
  keep: 14
```

路径按配置根目录解析。`keep` 默认为 14，至少为 1；自动、手动和迁移前快照共用保留份数。每次成功生成快照后清理超额旧快照，并保留刚完成的快照；时钟回拨时也保留本次生成或选中的当天快照。

活动数据库始终从快照识别和清理范围中排除，不占保留份数；即使它与快照在同一目录、使用了快照格式的文件名，也不会被当作已完成备份或被清理。

“一天”按 `app.yaml` 的 `timezone` 判断。文件名使用 UTC，例如 `litgleaner-20261111T010203Z-daily.db`；跨 UTC 日期仍可能属于同一个本地日。夏令时重复的一小时也只生成当天一份。

## 启动、重启和失败

- 同一天重启服务，会复用当天已经完成的自动快照。
- 服务关机或休眠后恢复，会在下一次可用调度补当天快照；不会补造离线期间每天的历史状态。
- 手动和迁移前快照各有用途，当天生成过它们仍会执行每日自动备份。
- 自动备份与流水线、迁移共用运行锁；多个服务实例不会同时生成自动快照。
- 备份失败会写入日志，后续调度重试；领读器和流水线继续工作。未配置模型也可备份，备份本身零模型费用。
- 如果当天缓存的快照被删除，服务会在下一轮检查时重新生成。

快照使用 SQLite `VACUUM INTO` 生成一致副本，先写 `.partial` 临时文件，完成后才原子发布最终名称。临时文件、零字节文件、同名目录及无效自动快照名称均不算当天备份完成。生成或发布失败会清理本次临时文件，已有成功快照保留；保留清理失败后，后续调度会复用已完成快照并重试清理。

## 手动备份和恢复演练

```bash
uv run litgleaner backup
uv run litgleaner backup --config /path/to/config
uv run litgleaner restore --check /path/to/litgleaner-20261111T010203Z-daily.db
```

手动备份支持在流程写入时生成一致副本。`db upgrade` 对已有旧版本数据库执行迁移前，先生成升级前快照；备份失败就停止迁移。

全部快照入口还共用备份目录里的 `.backup.lock`：目录扫描、目标命名、快照发布和保留清理串行执行，确保并发清理仍至少留有一份成功快照。该锁独立于流水线运行锁，手动备份仍可与正常流程并行；锁文件固定保留，进程结束时操作系统释放锁。

`restore --check` 在临时副本中检查 SQLite 完整性、迁移版本和表行数，必要时在临时副本上升级旧快照。演练保留原快照和正在使用的数据库。当前真正还原仍需停服务后手动处理，见 [ROADMAP.md](ROADMAP.md)。

快照包含 SQLite 中的论文元数据、判断、笔记、问答等记录。PDF、文档归档和配置存放在数据库之外，迁移或恢复整套资料时需要同时保管相应目录。目前快照写入本地目录，对象存储上传待独立实现。
